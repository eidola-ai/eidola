# AGENTS.md

Guidance for AI coding agents working in this repository.

Eidola is a privacy-preserving AI chat system: an OpenAI-compatible proxy server running in confidential enclaves, plus a native GUI app and CLI sharing one Rust core. ## Architecture at a glance

**Server** (`crates/eidola-server`): Axum-based OpenAI-compatible proxy to Tinfoil (`inference.tinfoil.sh`); PostgreSQL 17+; anonymous-credential billing (Stripe via a thin `reqwest` wrapper); deployed as a StageX `FROM scratch` image inside Tinfoil Containers (AMD SEV-SNP), plain HTTP behind the attestation-bearing TLS shim. Tool calling is wire-level pass-through — the server never executes a tool. The client and server both compute the pricing contract from `eidola-common` (`prompt_charge`), so the client's hold covers the server's charge by construction.

**App core** (`crates/eidola-app-core`): the GUI and CLI share this crate as a normal library — no FFI. All business logic lives here: config, the embedded Turso (libSQL) database, attested HTTP clients, accounts/wallet, chat inference (a bounded agentic tool loop), participants/templates, agent memory, local llama.cpp models. `AppCore::new` is fallible (exclusive advisory `flock` on the local DB — one writer, loudly; second opener gets `AppError::DatabaseInUse`). A `Change` bus broadcasts domain invalidations after every durable commit, each carrying whether a caller is waiting on the write (`ChangeOrigin`) so a busy consumer can tell its own writes from a background one's. A sub-space turn driver gives windowless delegated rooms their turns. **Any change to the chat path must extend the chat harness** (`tests/chat_path.rs` + the `tests/bus.rs` exit-point table).

**Local database:** fresh-start, no migrations — `crates/eidola-app-core/schema/schema.sql` is the whole baseline. Schema changes edit `schema.sql` and bump `LATEST_VERSION` in `db.rs`; other versions are refused ("delete your dev database"), never migrated. turso defaults `foreign_keys` OFF; `db::connect()` enables it per connection.

**Trust chain:** deterministic OCI build → server digest → `tinfoil-config.yml` → enclave measurement (`measure-enclave`) → `releases/trust/server-enclave.json` → embedded in the cli/GUI as their trust root → `artifact-manifest.json` (the signed deployment record). Clients re-verify enclave attestation on every TLS handshake (`tinfoil-verifier`). The server resolves the upstream router measurement at runtime from Tinfoil's Sigstore-signed releases (`src/upstream_trust` — temporary until we self-host inference).

**Website** (`crates/eidola-www` + `www/`): in-workspace static-site generator; docs render directly from `docs/`; adding a doc requires a `www/docs-nav.toml` entry (the build fails otherwise).

## Branch flow

`next` is the integration trunk; `main` is verified and promotion-only. **Never commit to `main` directly** — feature/dependency PRs target `next`; a maintainer promotes via `/promote` on the `next` → `main` PR, which fast-forwards `main` to the validated head. Cheap gates (`rust-checks`, lint, CLA, …) run on `next` PRs; the expensive `Build & Verify Artifacts` chain runs only for `main` (push + the promotion PR) and its `Guard` job is the merge gate. Full doctrine: `.github/AGENTS.md`.

## Build commands

**Prerequisites:** `rustup`, `direnv`, `docker`. The `justfile` is the primary development interface — run `just` to see all recipes. `just` itself is one of the Rust dev tools pinned via the `crates/devtools/` anchor crate, built by `.envrc`, and put on `PATH` by direnv.

- `just build {server,cli,gui,www}` — local-toolchain builds. `gui` on macOS also assembles `crates/eidola-gui/build/Eidola.app` (required for AppKit to treat the binary as a real app).
- `just run {server,cli,gui,www}` — build and run; accepts trailing args (e.g. `just run cli chat "hello"`). `www` serves locally with drafts + rebuild-on-change.
- `just test` — `cargo test`.
- `just check` — clippy, rustfmt, `rumdl check` over committed markdown (`.rumdl.toml`), and `cargo-deny check licenses bans sources` against `deny.toml`; `just lint-md-fix` applies auto-fixes.
- `just dev` / `just services` / `just down` — container-based dev workflows (full stack vs. host-mode services; see `crates/eidola-server/AGENTS.md` → Compose files).
- `just client-local` / `just client-reset` — point this machine's client (the GUI and CLI share one profile) at the local dev stack, and revert. Dev-only convenience over the sanctioned override surface: `scripts/local-client.sh` shells out to `eidola configure`, which writes base URL + ARK/ASK + trusted measurement as per-column overrides on the `eidola` backend row; `client-reset` clears each back to NULL, which *is* the compiled-in trust-root pin. Attestation is never weakened — the client runs the same per-handshake verification against the mock shim's chain. Quit any running Eidola first (single-writer local DB). Trusting the shim's mock TLS root in the OS trust store needs `sudo` and stays a human step: the script prints the command, never runs it; macOS reset guidance removes every same-name dev root so rotated roots cannot remain trusted. **Only the trust bundle moves** — the account (config.toml) and the wallet (local DB) stay with the profile, and neither is per-column overridable, so `client-local` pre-flights the profile and warns specifically when either is present (`eidola account create` refuses while an account exists; a production credential can be picked for a local turn and parked until `eidola wallet credentials recover` after `client-reset`).
- `just update-openapi` — regenerate the committed `openapi.json` after changing server endpoints.
- `just update-brand` — regenerate every identity asset (macOS `.icns` + `Assets.car`, website favicon + touch icon, Linux themed icons including the symbolic mark) from the geometry in `brand/generate.py`. macOS-only; the outputs are committed, so nothing builds them. See `brand/AGENTS.md`.
- `just update-manifest` — regenerate `artifact-manifest.json` + `releases/trust/server-enclave.json`. **Release-time only; do not run as part of a feature change** (desktop `narHash` / `archiveSha256` move with any sidecar/toolchain/packer change).
- `just engine` — materialize the bundled llama.cpp sidecar via Nix for the dev `.app` (optional; `just build gui` does not depend on Nix).
- `just apple-roundtrip [path/to/Eidola.app]` — re-run the Apple detached-signature round-trip checks on a built universal `.app` (macOS-only; with no path it builds `.#eidola-gui-macos-universal` first, which is slow). Measurement and verdict: `scripts/fixtures/apple-roundtrip/round-trip.md`.
- `just verify-apple <unsigned.tar.gz> <sigbundle.zip>` — reconstruct a signed macOS app in a temporary directory from the reproducible unsigned archive plus detached signatures, validate the placement record byte-for-byte, and print structurally parsed embedded claims. The unsigned input is the flake's gzip'd POSIX tar (`.#eidola-gui-macos-universal-archive`), the bytes `archiveSha256` covers; the detached material has no manifest-bound container, so either argument may be a tar or a zip and the container is read from the file's magic bytes, never its name. Those claims are not independent Apple authentication; the signed release attestation binds the input, detached material, output, and expected identity. Runs on macOS or Linux with POSIX `awk` and `od`, plus Info-ZIP `unzip` for a zip input and a `-z`-capable `tar` (GNU tar or bsdtar) for a tar one. A tar input also needs directory modes deferred to the end of extraction, or a read-only directory refuses the members packed after it: bsdtar defers by default and GNU tar is passed `--delay-directory-restore`, which the script probes for rather than assuming an implementation. `just test-verify-apple` gates all of that, and runs its body under two userlands — the host's own tools and then GNU tar + mawk (via `nix shell` when the host is not already GNU) — so a Mac exercises the userland most verifiers actually run; see `crates/eidola-apple/AGENTS.md`.

**Dev profile:** dependencies build at `opt-level = 2` in dev (`[profile.dev.package."*"]`) while our crates stay unoptimized — 8-17× faster GUI frames for ~90 s one-time cost. The cost is debugging *inside* a dependency (locals read "optimized out"); backtraces are unaffected. Measurements in the comment above the profile in the root `Cargo.toml`.

## Crate layout

Pure Rust crates under `crates/` (do not add a top-level `tools/` tree): `eidola-server`, `eidola-app-core`, `eidola-cli`, `eidola-gui`, `eidola-www`, `gpui-markdown-editor`, `tinfoil-verifier`, `measure-enclave`, and `eidola-common` — shared contract logic that must be bit-identical across boundaries: the pricing contract both client and server compute (`prompt_charge`, `chargeable_prompt_tokens`, `PromptCharge`), the outer chat-request construction and compatibility contract (`chat_completion_request_body`), and the `embed` marker-recognition rule shared with the markdown editor. Its dependency rule: admissible only if already in every consumer's graph and required for contract fidelity (today just `serde_json`). `eidola-attestation` is the shared attestation-template rendering both `release-tool` (signing side) and app-core's updater (verifier side) must agree on character-for-character; `eidola-apple` is the pure-Rust detached Apple-signature contract shared by release tooling and downstream consumers. Operational utilities: `generate-openapi`, `tinfoil-shim-mock`, `hash-secret`, `release-tool`. `crates/devtools/` is a lib-only anchor crate pinning Rust dev tools (`rumdl`, `just`, `cargo-deny`) in `Cargo.lock`; adding a tool is one `=X.Y.Z` dep there plus a `-p <tool>` in `.envrc`.

## Conventions

- Pure Rust dependencies preferred (cross-compilation); OpenAI API format is the canonical interface.
- Server endpoints are documented via utoipa `#[utoipa::path]` annotations + `ToSchema` derives, collected by `OpenApiRouter` in `lib.rs::build_router()` (SSE-only types listed manually in `api_doc.rs`). New/changed endpoints: annotate, register via `routes!()`, run `just update-openapi`.
- Nix is used for CI quality gates and reproducible desktop release builds (macOS universal cli + GUI `.app`, Linux GUI), not daily development. The bundled llama.cpp `llama-server` sidecar (`packages.llama-server` in `flake.nix`, pinned to release b9960 for `gemma4` support, trimmed to one binary) ships in every desktop **payload**; app-core resolves it by **one rule on every platform — a `llama-server` sibling of the running executable** — and never scans `$PATH`. That is why the macOS `.app` ships it at `Contents/MacOS/llama-server`, beside the main binary (where Apple expects a bundle's executables, and what keeps signing/notarization straightforward), and why the Linux Nix GUI **copies** it to `$out/bin/llama-server` next to the *copied* GUI binary (`$out/bin/.eidola-gui-wrapped`): the bundle layout lives in `flake.nix` + `scripts/package-gui-app.sh`, never in app-core. Every shipped executable is copied, never referenced by store path — Nix store paths are input-addressed, so a reference binds the build recipe but not the output bytes (`docs/verification.md` → Copied, not referenced). The macOS sidecar is deliberately arm64-only (Intel Macs get the honest missing-engine state); Linux ships CPU-only for now, and with BLAS off: nixpkgs' default BLAS backend is a shared library a static binary cannot carry, and it measured an order of magnitude slower at prompt processing anyway. The sidecar derivation remaps `$NIX_BUILD_TOP` out of C `__FILE__` (and zeros Darwin `LC_UUID`) so copied sidecar bytes are a function of source. Nixpkgs Mesa on the current Linux GUI is a *reference* (`VK_ADD_DRIVER_FILES`), not a copy — those driver bytes are outside `archiveSha256`. Vocabulary (payload / archive / envelope / installable) and the hash table: `docs/verification.md`.
- **The sidecar's linkage is per-platform, and enforced in the derivation rather than asserted in prose.** On Linux it is fully static against musl (`pkgsStatic`) — no `PT_INTERP`, no `DT_NEEDED` — which `postFixup` checks with `readelf` so a nixpkgs bump cannot quietly reintroduce a dependency. On Darwin llama.cpp's own libraries are folded into the one binary and only the system frameworks (Metal/Accelerate/libc++/libSystem) remain, which is as static as an Apple platform gets: libSystem is never linked statically.
- **Linux has two payloads, from the same build.** The Nix one (`packages.eidola-gui-linux`) carries a whole userland out of the store and references nixpkgs Mesa. The host-generic one (`packages.eidola-gui-linux-fdo`) is the same release binary with the two pieces of post-link metadata that bind it to the store removed by `patchelf` — `RUNPATH`, and the interpreter, reset to the filesystem-hierarchy path — so the host's own Wayland, Vulkan loader, and Mesa or proprietary NVIDIA drivers load into the glibc they were built for. `packages.eidola-linux-deb` wraps that binary and the sidecar into a byte-reproducible `.deb`: both executables at `/usr/libexec/eidola/`, with a `/usr/bin/eidola-gui` symlink, which keeps the sibling-of-exe engine rule intact because `/proc/self/exe` reports the symlink's target. The oldest glibc a shipped executable may demand lives in `flake.nix` as `glibcSymbolFloor` and is checked against the built binary's symbol versions, so raising it fails the build and never a user's launch. Debian dependencies are declared there too, and every `DT_NEEDED` soname must have a package or the build fails.
- Artifact/trust files: `artifact-manifest.json` (`schema_version: 2` — integer, see `docs/trust-root.md` and `docs/verification.md`) records OCI `digest`s, Nix desktop `narHash` plus `archiveSha256` of the flake-built `.tar.gz`, and enclave measurements; `releases/trust/server-enclave.json` isolates the enclave block as the cli's build input. Regeneration and verification doctrine: `.github/AGENTS.md` and `crates/measure-enclave/AGENTS.md`.
- CLA state lives in `CLA-INDIVIDUAL.md`, `CLA-CORPORATE.md`, `CLA-SIGNERS.txt`; changing either CLA text requires new signer entries (the hash changes).
- **Every square logo surface is generated from `brand/`** — one hexagon-grid mark, one generator, committed outputs (macOS `.icns` + `Assets.car` for light / dark / tinted, website favicon + touch icon, Linux themed icons including the symbolic mark). Never hand-edit a derived asset, and never build a brand asset out of an SF Symbol: Apple licenses those for use inside an app, not as icons, logos, or trademarks. The GUI's status-item glyph remains the real `circle.hexagongrid` symbol at runtime, which that licence does allow. Doctrine: `brand/AGENTS.md`.
- **User-facing GUI strings are localized, and every translation is a build input.** They live in Fluent files under `crates/eidola-gui/locales/`, embedded at compile time and reached through build-generated typed accessors; nothing loads a translation at runtime, because an unmeasured string file could rewrite security-critical UI text without breaking a signature. `eidola-app-core` stays locale-free (typed errors out; the presentation layer localizes), and the CLI and website are English. Doctrine: `crates/eidola-gui/AGENTS.md` → Localization.
- **Licensing is per-component**: `eidola-server` is AGPL-3.0-only; `eidola-app-core`/`eidola-cli`/`eidola-gui` are GPL-3.0-only; every other crate and the repo default is MIT OR Apache-2.0; `docs/` and `www/` content is CC-BY-4.0 (terms/privacy/CLA texts carved out). `LICENSE.md` is the human map and `REUSE.toml` the machine-readable declaration — a new crate needs a `license` field in its `Cargo.toml`, and a crate changing license buckets must update both files. Third-party dependency licenses are vetted by `cargo-deny` (`deny.toml`, whole-graph, gated in `rust-checks` and `just check`; advisories run on a daily schedule instead — see `.github/AGENTS.md`) and by `dependency-review.yml` (lockfile diffs, all ecosystems); the two allow-lists are kept aligned per the note in `deny.toml`. Workspace crates are exempt via `licenses.private.ignore` since nothing is published.
