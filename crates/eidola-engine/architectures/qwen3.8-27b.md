# Qwen3.8-27B

`Qwen/Qwen3.8-27B-FP8`, text only, on one Blackwell GPU. The architecture is `eidola_common::architecture::Architecture::Qwen38Dense27B`.

**Status: in progress.** The reference forward and the chat format are implemented and verified; the serving core carries the recurrent state (below); the CPU executor reproduces the forward bit for bit through the real scheduler, drafting included; the CUDA executor and its kernels are built (decode graphs per rung, FA2 at head dimension 256 in the fast profile, the FP8 GEMM swapped at decode sizes, the FP8 projections of one input stacked into one GEMM, the 5,120-output GEMMs split over K at every row count, sampling and chain acceptance on the device by a sampler of its own, one target forward a drafting step, and in the fast profile the DeltaNet in blocks on tensor cores), equal to the CPU executor on host-compiled kernel bodies eagerly and on the padded rung path, and run on a B200 (its device suites, and the serving bench under a profiler); and the inference node serves the architecture (below). The variant is implemented: its `Shape` is known, so a catalog row and a deployment may name it. None is committed.

## The model

- **A dense hybrid of 64 layers.** Three Gated DeltaNet layers then one gated full-attention layer, sixteen times over; every layer has a SwiGLU feed-forward.
- **Gated DeltaNet.** Linear attention with a fixed-size recurrent state per sequence: 16 query/key heads and 48 value heads of 128 dimensions, a causal depthwise convolution of width 4 over the projected queries, keys and values, a per-head decay and write strength, and an output RMS norm gated by SiLU. Its state is an FP32 128 × 128 matrix per value head, about 151 MB a sequence over the 48 layers, whatever the context length.
- **Gated full attention.** 24 query heads and 4 KV heads of 256 dimensions, per-head RMS norms on queries and keys, rotary position on the first 64 dimensions of each head, and a sigmoid gate on the attention output. KV is 64 KiB a position.
- **One MTP drafting layer** of the full-attention kind, sharing the embedding and the output head.
- **Precision.** FP8 E4M3 weights with a BF16 scale per 128 × 128 block for the large projections; the embedding, the head, the norms, the DeltaNet's small projections, its convolution and the drafter's input projection are BF16. Activations are quantised to FP8 per token and 128 columns at runtime.
- **Not served: vision.** The checkpoint carries a vision encoder, which the text path never reads.

## How it will be verified

Each level is held to the one before it, as for the other architectures:

1. **The reference forward** (`eidola-engine-model`), an f32 forward with the released model's rounding points, against the released modelling code (Transformers' `qwen3_5`) with its unspecified operations pinned, and a health check on the real checkpoint: a next-token accuracy floor over the checkpoint's own licence text and a known one-word answer. **Done on the CPU:** exact on a synthetic fixture, on the first four real layers and on the whole released model; healthy (accuracy 0.998 on the licence text, as vLLM measured, and "Paris"). Still to run on a GPU: the reference as released there, against which ours must be no further than the reference is from itself, and the drafter against vLLM's own (`eidola-engine-model/AGENTS.md` → Qwen3.8).
2. **The CPU executor** (`eidola-engine-cpu`) equal to that forward bit for bit through the real scheduler: chunk sizes, interleavings, prefix hits at recurrent-state snapshots, preemption, the host tier, and drafts accepted and rejected. **Done on the committed fixture**: every row's logits, every drafter and chain row, every draw and every stored state exact (`eidola-engine-cpu/AGENTS.md` → Qwen3.8).
3. **The CUDA executor** (`eidola-engine-cuda`) held to the CPU executor, in two profiles. The **exact** profile (the verification mode) equals the CPU executor bit for bit; the **fast** profile (the serving mode: the FP8 and BF16 linears on tensor cores, the DeltaNet's `a` and `b` projections as one small-N GEMM over their stacked weight, the gates in f32, and the Gated DeltaNet in blocks, below) is held to reproducibility between calls (greedy tokens and logits the same whatever the batch, the chunking, decode or prefill, a cache hit or not, and the draft width), asserted, and its distance from the exact profile measured. **Done without a GPU**: every kernel body equal to the model crate, and the exact profile equal to the CPU executor through the real scheduler (logits, tokens, state images byte for byte, encryption, the host tier) on those bodies compiled for the host, eagerly and on a decode rung's padded launch sequence, and invariant on both; the fast profile's plans packed on every path; the blocked DeltaNet's host form equal to its definition, near the token recurrence, and reproducible through the real scheduler across block boundaries (`eidola-engine-cuda/AGENTS.md` → Qwen3.8). Prepared for a GPU: the same tests on the device with graphs replaying, the fast profile's invariance across paths on a fixture with the released 256-wide heads, the released model's comparison, health, generation, and serving speed at the reference stack's workloads (`scripts/qwen_*_session.sh`).

The Gated DeltaNet can be computed token by token or in chunks of tokens, and the two orders round differently. The exact profile's contract is the token recurrence: every token, in a prefill, a decode step or a draft check, runs one step from the state the token before it left, so a layer's state and output depend only on the token prefix, and a state saved after any token resumes exactly. The reference forward exposes the step as public kernels the executors call. The fast profile computes it in blocks at absolute positions (16 positions at the serving block size): each block in its chunked form from the state at its start, a position's output from its block's positions up to it alone, and a state only at a block's end. Its outputs and states are functions of the token prefix too, however the scheduler cuts and batches the rows, and the serving core keeps states at block boundaries anyway, so its contract is the same (`eidola-engine-cuda/AGENTS.md` → Qwen3.8, *The DeltaNet in blocks*).

## The recurrent state in the serving core

The DeltaNet layers' state is a pool of state buffers beside the KV groups (`eidola-engine/AGENTS.md` → Recurrent state): a sequence keeps a base buffer at its last block boundary and its executor slot the inputs after it; drafts never reach a stored state; and the prefix cache keeps snapshots only at a sequence's branch, regeneration and continuation points, with every guarantee its KV blocks get. `mock::qwen_like_spec` is the shape the serving core's tests run (`tests/recurrent_state.rs`).
