# eidola-www — Agent Development Guide

A small in-workspace static-site generator (pure Rust: `pulldown-cmark` + `toml`, and `merman` for diagram parsing and layout; pinned in `Cargo.lock`, no external SSG binary) that builds the public site ([www.eidola.ai](https://www.eidola.ai)).

## Content model

- Content lives in the top-level `www/` — `pages/` for standalone pages, `blog/` for `YYYY-MM-DD-<slug>.md` posts with TOML `+++` front matter, `static/` for assets.
- The docs section renders **directly from `docs/`** — single source of truth, with relative `.md` links rewritten to site routes and out-of-docs repo links rewritten to GitHub blob URLs.
- Output: pretty URLs (`/docs/client/`, `/blog/<slug>/`), a blog index + Atom feed only when the build has posts to put in them (no empty index, no header link, no feed otherwise), `sitemap.xml`, GitHub-convention heading anchors (authored `#fragment` links keep working). Deterministic (sorted input order, no timestamps).
- **Docs navigation:** the sidebar structure lives in `www/docs-nav.toml` (`[path, label]` entries in titled sections). **Adding a doc requires adding a nav entry** — the build fails on a missing or stale entry. Rendered as a sticky left rail on wide screens, a `<details>` disclosure on narrow ones. Docs and posts with ≥3 h2/h3 headings get an "On this page" right-gutter rail (scroll-spy in `www/static/toc.js`); every docs page ends with an edit-on-GitHub link.
- **Three pages are Stripe's landing targets**, not ordinary content: `payment-complete.md`, `payment-canceled.md`, and `billing.md` (the billing-portal return). Their routes are pinned by constants in `crates/eidola-server-gateway/src/account.rs`; renaming or removing one breaks a redirect a live checkout depends on, so the two move together. Each says plainly that the reader may close the window and go back to the app, and claims nothing about timing the webhook actually owns.
- Legal documents publish their exact source bytes at `/terms/source.md` and `/privacy/source.md` for the server's terms-feed poller (see `crates/eidola-server-gateway/AGENTS.md`); rendered pages carry `eidola:version` / `eidola:source-sha256` meta tags.
- **Hash-versioned docs** (`HASH_PUBLISHED_DOCS` in `lib.rs`, today just `privacy-guarantees.md`) get the same source-bytes + `eidola:source-sha256` treatment but no version number — the content hash *is* the version, and it's the same whole-file hash `release-tool attest` signs into each release attestation. Never add `version` front matter to these files: front matter would change the attested bytes, and a monotonic number implies ongoing-conduct (legal-doc) semantics. The byline links `source.md` and the file's GitHub history; release-pinned copies are reachable via the `git_commit` in any attestation.
- **Diagrams are fenced `mermaid` blocks, drawn as inline SVG at build time** (`src/diagram.rs`). GitHub renders the same block itself, so the source is the one diagram both places show. `merman`, a Rust implementation of Mermaid 12, parses it into Mermaid's semantic model and lays it out with ELK's layered algorithm (Mermaid 12's default for flowcharts, so the arrangement matches GitHub's); the SVG is drawn here from that model and geometry, never taken from `merman`'s own SVG, so that every colour comes from `site.css` theme slots and the diagram follows day and night (the source decides structure, line kind and stroke widths; colours it names are ignored). A line whose width is not its kind's (thin, or thick for `==>`) gets it from an id and a class (`a chat@-. chat .-> b`, `class chat wide`), never from `linkStyle`, whose index shifts when a line above it moves. Lines are drawn along the layout's right-angled routes with rounded corners; a stacked-rectangle node (`@{ shape: processes }`) is three plates, as Mermaid draws it; a boundary's title sits in its top-left corner, drawn over crossing lines with a halo of the boundary's fill. The ELK implementation (`merman-elk-layered`) is EPL-2.0, allowed in `deny.toml` and the dependency-review workflow; the generator is a build tool, not a distributed artifact. Three rules fail the build: only flowcharts are drawn; a diagram needs `accTitle:` and `accDescr:` lines (its SVG `<title>`/`<desc>`); and **every labelled line links to the page's heading of the same name**, which must exist — a label is a promise that the page explains that line (several lines may share one label and one section). `click <id> "<target>"` makes a node a link, rewritten like any other link on the page, and a click naming no node fails the build (Mermaid would ignore it). Lines carry a wide transparent twin so a thin line is easy to hit. A diagram is drawn at its natural size, the size `merman` measured its 14px text for, except that one wider than the 648px figure column is drawn at the column's width, if that keeps its text at 10px or more (`COLUMN` in `diagram.rs` mirrors the column in `site.css`; ELK takes no width to lay out within). Where the column is narrower than the drawing it scrolls sideways, which is why `.layout > main` has `min-width: 0`.
- GFM alert blockquotes (`> [!NOTE]` / `[!TIP]` / `[!IMPORTANT]` / `[!WARNING]` / `[!CAUTION]`, via `ENABLE_GFM`) render through pulldown-cmark's `markdown-alert-*` classes; `site.css` styles them in the hairline blockquote idiom using the app's status slots (`info`/`success`/`warning`/`danger` in `circadian.rs`; important = `accent-foreground`).

## Visual system

**The app's circadian theme, ported.** `src/circadian.rs` duplicates the palette constants and tint math from `crates/eidola-gui/src/theme.rs` (day/night neutral anchors, cool/warm targets at 0.08/0.12, the 0.6× day-paper soft-tint list) and generates `/assets/circadian.css` at build time — unit tests pin the derived hex values so drift from the app palette is loud; **if the app palette changes, update `circadian.rs` to match**. `www/static/circadian.js` ports `solar.rs` + the `theme.rs` resolution logic (NOAA sunrise equation, canonical-hour warp, ±2h character windows); geography comes from the IANA timezone via a committed `zones.js` snapshot of `zone.tab` (regeneration snippet in `README.md`), never geolocation. Site defaults mirror the app: appearance `auto`, tint on; a footer control can pin day/night (localStorage). Typography is the app's book metaphor: variable Newsreader woff2 (same OFL license as the app's bundled faces) at 17px/1.65 on a 600px measure, flat heading ramp, system-ui 14px chrome, the background→transparent title-band fade.

**The mark is the hexagon grid; the wordmark is still the word.** `favicon.svg` and `apple-touch-icon.png` are generated into `www/static/` by `just update-brand` (geometry and rationale: `brand/AGENTS.md`) — regenerate there, never hand-edit them. Both are `ROOT_STATIC`, so they land at `/` rather than `/assets/`, and `render.rs`'s head links them. The favicon carries no ground: it is ink by day and warm grey under `prefers-color-scheme: dark`, so the tab follows the same circadian rule as the page. The site header's `Eidola` wordmark is text and stays text.

## Build & deploy

`just build www` builds to `target/www`; `just run www` serves at `127.0.0.1:8000` with drafts + rebuild-on-change. Deployment via `.github/workflows/website.yml` (PR validating build; `main` pushes deploy to GitHub Pages). `tests/build.rs` builds the real site as a regression test.
