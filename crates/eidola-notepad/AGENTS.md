# eidola-notepad — Agent Development Guide

A plain markdown file editor: one window per document, each the composer's editor (`gpui-markdown-editor`) on Eidola's writing surface. It is a personal tool beside the product, not part of it — no account, no backend, no app-core state. It exists because the composer's editing surface is a good place to write, and files are where writing goes. macOS is the target; it compiles elsewhere but has no Linux chrome (no CSD, no primary menu).

## The visuals are Eidola's by construction

Nothing visual is copied. The theme (`eidola_gui::theme` — the Circadian palettes, Newsreader, the clock), the prose style (`space_view::prose_style`), the page geometry (`BODY_MAX_WIDTH`, `POST_PAD_Y`, `TITLE_BAR_RESERVE`, `layout::COMPACT_PAGE_INSET`), the title band's gradient and drag gesture (`titlebar::make_draggable`), the scroll indicator (`scrollbar::vertical`), the transparent titlebar, `chrome::themed_root` and the default window size (`writing_surface_size`) all come from `eidola-gui` itself, which exposes them publicly for this crate. A change to how Eidola writes reaches the notepad on the next build, and the two cannot drift. That dependency is also why this crate is GPL-3.0-only.

- **Appearance follows the reader's Eidola settings, read only.** `follow_eidola_appearance` reads `config.toml` through `eidola_app_core::config::Config::load_from` (no `AppCore`, no database, no lock — the notepad runs beside a running Eidola) and drives the theme through `theme::set_settings`, re-reading whenever a document window comes forward so a change made in Eidola arrives. `theme::start_clock` runs the time-of-day tint. Nothing is ever written to Eidola's config.
- **View ▸ Zoom is this app's own and lasts the session.** Until it is used the type scale follows Eidola's; afterwards `Notepad::zoom` wins over the config on every re-read.
- **Where the text sits**: under the title band, one `POST_PAD_Y` down — where a docked composer's text begins — in a column capped at `BODY_MAX_WIDTH` with `COMPACT_PAGE_INSET` margins. The editor takes `min_height` to the bottom of the page, so a click below the last line lands at the end (the editor's own notes-editor affordance). The title band shows the document name, muted, with "— Edited" while dirty.

## A document's life on disk (`src/document.rs`, `src/file.rs`)

- **The buffer is canonical; the file keeps its shape.** `file::decode` takes a UTF-8 BOM, CRLF or lone-CR (classic Mac) line endings and exactly one final line ending off what the editor sees, recording each in a `Format`; `file::encode` puts exactly that back. An untouched file saves back byte for byte (`an_untouched_file_saves_back_byte_for_byte`), and an edit is saved in the file's own line ending. Non-UTF-8 files are refused at open with a reason, never decoded lossily.
- **Saves are atomic and serialized**: a sibling temporary file, unique to the write, created exclusively and with the target's permissions before it holds a byte (a private note is never readable through it), renamed over the target; a symlink is written *through* (a note symlinked into a vault stays a symlink, and one whose file has gone recreates that file rather than being replaced). Writes run on the background executor one at a time under a per-document lock, and each reads the buffer — and a plain Save its destination — when it starts writing, so a quick second ⌘S never lands before the first, nor follows a Save As back to the old path. Save As adds `.md` to a bare name, and since the panel only confirmed the name as typed, an existing file at the amended path gets its own Replace / Cancel sheet.
- **Dirty is a comparison, not a flag**: `is_dirty` is `buffer != saved_text`, recomputed on every `Change`, so undoing back to the saved text reads clean. It drives the window's edited dot (`set_window_edited`), the title band, and every unsaved-changes question.
- **Closing asks, through one door.** ⌘W, File ▸ Close and the close button (`on_window_should_close`) all reach `review_unsaved`, the Save / Don't Save / Cancel sheet; Save runs the ordinary save (a Save As panel for an untitled document) and closes only once the bytes are down — and only if nothing was typed meanwhile; otherwise the window stays, still edited. ⌘Q reviews every edited document in turn, with the macOS "review changes / discard / cancel" sheet first when there are several, and one Cancel keeps the app open. Windows stay editable under those sheets, so after each round the review takes the list again, and a document edited since it was settled is asked about again before the app quits. **Residual:** a quit that bypasses the menu — the Dock icon's Quit, logout — goes through gpui's `applicationShouldTerminate`, which this crate cannot intercept, so it quits without asking.
- **Another program may write the file.** When a document window comes forward its modification time is compared with the one this process last read or wrote: an unedited document reloads silently (keeping the scroll position), an edited one asks Keep This Version / Reload, once per change on disk. A file that disappeared leaves the text in the window, and Save writes it back.
- **Relative images resolve beside the file**: the editor's `set_image_base_dir` is the document's folder, kept current across Save As and loads.
- **The editor canonicalizes on edit, document-wide.** Its invariant promotes every lone mid-paragraph newline (outside lists, fences and tables) to a paragraph break on the first edit (see `crates/gpui-markdown-editor/AGENTS.md`), so a hard-wrapped file opened here comes back with blank lines between its lines once anything is typed. Files written in the notepad are already canonical; this is the editor's doctrine, deliberately not worked around here. Frontmatter is outside it: the editor treats a block opening the file as code, so a vault note's metadata survives editing line for line (`editing_the_body_leaves_frontmatter_alone`).

## The app (`src/lib.rs`)

- **Windows and files.** `open_paths` (deferred — a drop or a menu item arrives mid-update of the window it may need) raises a window already showing the file, otherwise loads it into the front window when that is an untouched Untitled (the Mac idiom), otherwise opens a new window cascaded from the front one. Files arrive from the command line, File ▸ Open, Open Recent, a drop onto a window (`ExternalPaths`), and AppKit's `application:openURLs:` — Finder's Open With and the Dock icon — through `Application::on_open_urls` and a channel, because launch-time files can arrive before the run callback. **The launch open runs inside a spawned `update`, not the run callback itself**: that callback is not an update, so an effect queued there (the deferred open, a refusal's sheet) waits for some unrelated event to flush, and a launch with a file showed no window at all. The test platform cannot see this — `run_until_parked` flushes everything — so it is held by the comment at the call site and this note. `CFBundleDocumentTypes` in `Support/Info.plist` (Markdown and plain text, `Alternate` rank, with an imported `net.daringfireball.markdown` declaration) is what makes the app a drop target at all.
- **Open Recent** is this crate's (`src/recent.rs` — gpui does not surface AppKit's recents menu): most recent first, bounded, only files that still exist, persisted one path per line under the platform config directory; every open and save also feeds `App::add_recent_document` for the Dock's own recents. The menu is rebuilt on each change.
- **Menus** follow Eidola's wiring rules (`crates/eidola-gui/AGENTS.md` → macOS UX): keys bound before `set_menus`, a menu literally named "Window", the clipboard verbs as `os_action`s, Undo/Redo on gpui dispatch. Document-scoped commands (Close, Save, Save As, Revert to Saved, Show in Finder) are registered on each document's root element, so macOS greys them with no document in front, and Revert only while there is something to revert. Bold/Italic and Paste and Match Style reach the editor's own actions.
- **Accessibility**: every window is titled (Window menu, switcher, VoiceOver's chooser), documents report their path as `AXDocument` (`set_document_path`), and the editor carries a `TextInput` probe whose value is the text as it last *settled* (open, save, blur) — never per keystroke, Eidola's settled-value rule. The editor itself carries no text semantics yet (no caret tracking or line review for a screen reader) — the same gap Eidola's composer has, and the editor crate's to close.

## Building and testing

`just run notepad` builds, bundles (`scripts/package-notepad-app.sh`, which also registers the bundle with LaunchServices) and opens `crates/eidola-notepad/build/Eidola Notepad.app`; `just build notepad` stops before opening. A release bundle is `cargo build --release -p eidola-notepad && ./scripts/package-notepad-app.sh release`. The bundle borrows Eidola's generated app icon; the notepad has no identity asset of its own.

- `cargo test -p eidola-notepad` — unit tests (file format, recents, caret reveal geometry, URL and argument parsing), `tests/behavior.rs` (a document window through real keystrokes, actions, sheets and save panels: dirty tracking and undo, format-preserving save, Save As, the close sheet's three answers, revert, external changes, image base) and `tests/app.rs` (opening into windows, the pristine-Untitled replacement, de-duplication, recents, refusal of non-text files, the quit review).
- `EIDOLA_RUN_VISUAL_TESTS=1 cargo test -p eidola-notepad --test visual` renders a document and an untitled window in Day and Night to gitignored PNGs under `tests/snapshots/` — a local debug aid, like Eidola's visual tier.
