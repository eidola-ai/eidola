# crates/eidola-gui — gpui-based Eidola

Guidance for AI coding agents working on the gpui app. Cross-cutting workspace context lives in the top-level `AGENTS.md`; app-core doctrine in `crates/eidola-app-core/AGENTS.md`.

## What this app is

A native Rust client for Eidola, built on [gpui](https://github.com/zed-industries/zed/tree/main/crates/gpui) (Zed's immediate-mode UI framework) and [gpui-component](https://github.com/longbridge/gpui-component) (a shadcn-style widget library on top). The CLI shares the same `eidola-app-core` backend. macOS is the primary target; Linux is a supported build/run/release target (see [Linux build/dev target](#linux-builddev-target)).

**State & async doctrine — read first.** All state ownership, async tasks, and cross-window synchronization follow `crates/eidola-gui/STATE.md` (domain stores, `Loadable`, task-as-field with replace-cancels, the invalidation bus, `WindowInput`). Where existing code contradicts the doctrine, the doctrine wins; do not extend the old patterns (`Core::spawn`/busy flag, detached tasks, view-owned domain data).

## Stores (`src/stores/`, `src/loadable.rs`, `src/bridge.rs`)

gpui can't host `AppCore` directly (gpui's executor is smol-based; `AppCore` owns a tokio multi-thread runtime). Per-domain stores own all domain state; views call store methods and observe the store entities they render — they never call `AppCore` directly.

- **Domain stores** (`src/stores/`): one gpui entity per domain — `ConfigStore`, `BackendsStore`, `ModelsStore` (per-backend model catalogs, one `BackendCatalog` + fetch slot per enabled fetch-based backend so one dead server never blanks another's list), `LocalModelsStore` (downloads/engines are core-owned, so closing a window interrupts nothing), `AccountStore`, `WalletStore`, `SpacesStore` (the Library index + the space-entity registry; **rename/archive are optimistic *and* write-through** — each edits the cached row, then composes `write; re-list` in its own **per-space** slot, so a refusal lands in that space's standing `op_error` and the index reconciles on every exit), `UpdateStore`, `ParticipantsStore` (**per-space** membership, keyed `HashMap<SpaceId, Loadable>`; `Change::Participants` carries no id, so every cached space re-lists; CRUD takes **one write slot per `(space, participant)`** — the roster offers a verb on every row at once — and the read that resolves a space's roster is taken once that space's last write settles), `TemplatesStore` (refreshed on `Change::Templates` **and** `Change::Participants`, since a template snapshot embeds referenced globals' effective config), `AgentsStore` (the shared agent library — a **store-wide** `Loadable<Vec<GlobalAgentInfo>>` refreshed on `Change::Participants`, the third store that signal fans out to, with **per-agent** write slots and per-agent `op_error`: the roster offers Edit and Retire on every row at once, so those writes are independent and a store-wide slot dropped one of them; **no optimistic edit**, so a refused write has nothing to take back — the simple half of the keyed shape), `SpaceSettingsStore` (**per-space** cascade limit + router model — the inspector's data; `Change::Space` carries the id, and only a **cached** space re-reads, since every post emits that signal; **each setter advances the cached snapshot as its write leaves**, so the stepper's next press derives from what is being written — see STATE.md's derived-value rule), plus the data-less `RecordStore` bus-relay. Created once at startup, bundled in `Stores` (held by `AppGlobal`), handed to every view constructor. Each store owns its `Loadable` snapshots, its in-flight `Task` *fields* (one slot per operation, replace-cancels), its bus subscription, and all mutations of its domain.
- **Refreshes and mutations never share a slot.** A store is refreshed by bus signals it doesn't raise (and, for the write-through stores, by the very `Change` its own write emits before returning), so a shared slot lets a refresh cancel the gpui half of an in-flight write — the core write runs but the continuation carrying `op_error` + re-list never does. The split is ordered: a mutation takes over the read (dropping an in-flight refresh — a debt its **unconditional re-list** discharges on every exit, success or failure), and a refresh signalled meanwhile defers to the mutation's completion. `stores::settle_mutation` (shared by `TemplatesStore`/`ParticipantsStore`/`SpaceSettingsStore`/`SpacesStore`) resolves the cell either way — a cancelled refresh may have left it `Loading`, and an error merely dropped leaves a spinner with no live task; `Loadable::resolve` lands `Failed { prior }` while the write's error wins the separate op-error slot. Regressions: `a_refresh_landing_mid_write_keeps_the_{templates,participants,space_settings}_ops_error` and `a_refresh_landing_mid_rename_keeps_the_spaces_ops_error` (`tests/stores.rs`) + the settle quadrants unit-tested beside `settle_mutation`.
- **An optimistic edit is a promise the failure exit has to keep** (STATE.md's rule; the `SpacesStore` case is task 48). The edit is what makes a list answer without a round trip, so it stays — but the operation owes a reconcile on every exit and a reason when it refuses, or a refused write reads as an accepted one for as long as nothing else invalidates the cell. A refusal that arrives as a *value* counts: `AppCore::archive_space` answers `Ok(false)` when it archived nothing, which the store turns into a refusal because the row it had already removed was not its to remove. **And the promise binds the quadrant where reconciliation is unavailable**: when the write is refused *and* its re-list fails too, `Failed { prior }` keeps the cell's rows on screen — so the operation restores the listing its optimism replaced before resolving (`settle_index_mutation`, built in the same breath as the edit because `write_then_relist` applies the edit itself and takes back its inverse). Order is load-bearing and stated there: the undo precedes the resolve, so a **successful** re-list still supersedes it, and it is gated on the *write* failing, since a write that landed durably is honest to keep on screen. Regressions: `a_refused_rename_reconciles_the_index_and_surfaces_the_refusal`, `an_archive_that_changed_nothing_says_so`, and the four quadrants unit-tested beside `settle_index_mutation`.
- **Independent mutations get keyed slots — and keyed reports.** A store-wide mutation slot is the silent-loss defect one move away: the second of two writes replaces the first, dropping an in-flight write's continuation (refusal + re-list) or cancelling an unpolled one outright. Where the domain's mutations are independent — `SpacesStore`'s rename/archive, keyed per space, the `Space` entity's `turn_runners`, `AgentsStore`'s edit/retire, keyed per agent, `ParticipantsStore`'s roster CRUD, keyed per `(space, participant)` — the slot map is what makes them so, and the deferred refresh then waits for the *last* of them. **A key must name the control, not the surface**: `ParticipantsStore` keyed by space alone because its *snapshot* is per space, and the inspector's share-then-remove made the mismatch cost real — the second write replaced the first, which unpolled never ran at all (Codex review, PR #279; `two_writes_on_two_participants_of_one_space_both_land`). The cell stays per space; only the slots and reports moved. **The keyed shape has a simple half and a full one, and a store takes only what its honesty needs**: `AgentsStore` makes no optimistic edit, so it needs the keyed slots, the keyed reports and the read-taken-after-the-last-write — and none of the inverse machinery below, because with no local edit outstanding a refused write has nothing to take back and the roster can never show a value the database refused (Codex review, PR #279). **The op-error slot is keyed the same way**, because a per-space surface reading a store-wide slot cannot tell "no refusal" from "another space's refusal overwrote mine". Same-key writes are **chained, not replaced**: last-wins was documented as a residual of replace-cancel, and that claim was false — dropping a `Task` cancels only the gpui half, and `bridge` leaves the core write running, so a superseded write could reach the database *after* its successor, or (unpolled) never run at all (Codex review, PR #279). The successor now takes ownership of the predecessor's task and **awaits** it before its own write, so it starts strictly after that round trip: last-wins is true by sequencing rather than by hope, and no write is silently lost. Each task carries a **generation**, and only the current one settles — a superseded op records no refusal (its successor's start already cleared the key's report, and the outcome the reader waits on is the newer one's) and never removes the slot, which by then is its successor's. Applies to `AgentsStore` and `ParticipantsStore` alike; regression `two_saves_on_one_agent_are_sequenced`. The superseded write's *edit* is still taken back as the successor's is applied, so no operation ever treats another's optimism as the value to restore. **And keyed slots mean a shared cell now has several writers**, which moves the resolving read: **it is taken after the last write, not merely applied then**. No operation carries a listing — settling only reports its refusal and takes back its own edit — and the read that resolves the index is issued once `op_tasks` is empty, through `refresh` (so the rule re-arms recursively: a mutation starting during that read drops it and owes the next one; the newest batch-end read wins). A read each operation issued for itself begins right after *its own* write, so the operation still standing when the last slot cleared could resolve the cell with a snapshot predating an accepted sibling write — dropping a durable rename from view, and preserving it as `Failed { prior }` when that read failed. "Applied last" is not "read last". Each refused write takes back **its own edit only**, which is why the undo is an inverse rather than a snapshot of the whole listing (a snapshot erases a sibling's pending edit, and one captured after another op's edit resurrects that op's refused edit when restored later) — and why the inverse stores **no position**: a rename's is by id, and an archive's seat is derived from `last_activity_at`, the key `list_spaces` orders by. A recorded slot goes stale the moment a sibling's removal shifts the list (two archives of `[A,B,C]` each record slot 0, seating them `[B,A,C]` in one of the two settle orders — an order the database never held, standing as `Failed { prior }` when the batch-end read fails too). Regressions: `two_renames_on_two_spaces_both_land`, `two_refused_mutations_each_keep_their_own_refusal`, `a_superseded_rename_leaves_no_optimism_behind`, `a_batch_of_renames_lands_on_a_listing_read_after_all_of_them` (a **stability** assertion — a batch's optimistic edits agree with the database the moment its writes commit, so comparing once passes long before the resolution lands), `two_refused_archives_restore_the_databases_order_{first,last}_settling_first`, and the interleaving quadrants unit-tested beside `settle_index_mutation`.
- **Multi-call ops stay in one `bridge` closure — and one closure is not one transaction.** A two-core-call op (e.g. a router-bearing template create/update) must not return to gpui between calls: the first call's `Change` drives a refresh that replaces the mutation's slot and swallows the second. Validate what can be validated before the first write (zero-trace refusal), and re-list whether the op succeeded or failed. **But the closure only closes the gpui-side gap.** Its two calls are still two transactions over a database several windows share, so a state the first call's success depended on can change before the second runs — and the op then commits half of what the reader asked for, under a message saying it failed. **When "a refusal leaves zero trace" is the contract rather than a nicety, the transaction has to be core-side**: hand the second call's inputs to the first as one operation and let app-core validate-and-write them together. Task 36's share is the worked example (Codex review, PR #279): an `update_space_participant` + `promote_participant` pair published a renamed persona to *every* space when another window shared the same agent in between, so the persona became an argument to `AppCore::promote_participant`, applied inside the promoting transaction behind its own guard. Regressions: `a_share_that_loses_the_race_writes_no_persona` (`tests/stores.rs`) and app-core's `a_persona_travels_into_the_promoting_transaction`.
- **`Loadable<T>`** (`src/loadable.rs`): `NotLoaded` / `Loading` / `Loaded { value, stale }` / `Failed { error, prior }`. A re-fetch over existing data stays `Loaded { stale: true }` (never a blank `Loading` flash); `Loading` is initial-load-only and always implies a live task in the sibling slot.
- **Method shapes:** `refresh_*` is fire-and-notify (store owns the task). `request_*` is awaitable (returns a `oneshot::Receiver`; the caller awaits in its own slot, so the work dies with the caller). Ownership = cancellation authority.
- **The bus bridge** (`stores::install_bus_bridge`, once at startup): a task on `AppCore::runtime()` forwards every `Change` through an mpsc into one gpui main-thread loop dispatching to the owning store(s); `Lagged` refreshes everything. The **only** place tokio receivers touch gpui, and its app-lifetime task is the **one sanctioned `.detach()`**. Returns a `BusBridge` whose `quiesce()` stops dispatch; the quit hook calls it first (see [App lifecycle](#app-lifecycle--the-app-outlives-its-windows-and-q-retires-it)).
- **`src/bridge.rs`**: runtime-agnostic `oneshot`/`mpsc` glue. `bridge(core, f)` runs `f` on tokio and awaits on gpui. Free functions (`chat_stream`, `get_space_tree`, `list_attestations`, …) hand back receivers the owning entity awaits inside its own `Task` slot.
- **No shared busy flag.** Each operation has its own slot, so concurrent refreshes never starve each other (the wave-2 launch-order bug; replay in `tests/stores.rs`). Multi-part work composes inside one store task or by *event* (write through `AppCore`, let the bus drive each store's refresh); one store never orchestrates another's tasks.
- **Stub mode (tests):** `Stores::stub_with(StoresStub { … }, cx)` builds backend-less stores from a declarative fixture; `refresh_*`/`request_*` are no-ops, so views transition local state and stop at the backend guard — what behavior tests assert. `Stores::for_test(Arc<AppCore>, cx)` injects a real tempdir-backed core for store-machinery tests.

## The Space entity

`space.rs`'s `Space` is the per-conversation **domain entity** (STATE.md → "Space entities — shared, registried"). It owns everything about one conversation, so a window opening/closing never re-derives or destroys it.

- **State it owns:** `id: String` (present from birth — a space's row is committed when its window opens), `transcript: Loadable<Vec<ChatMessageView>>`, live `streams: Vec<StreamingTurn>` (one per in-flight response turn — `seq` render key, responding `participant_id`, `target_action_id`, its own reasoning/content buffers + disclosure flag), `failed_turn: Option<FailedTurn>` (the Retry record), `last_submitted_model`. There is **no per-space model selection** — who answers, and with what model, is Participants configuration.
- **Tasks-as-fields:** `post_runner` is the exclusive mutation slot (submit / post-only / edit / regenerate; a mutation while one is in flight is a no-op). `turn_runners: HashMap<u64, Task<()>>` is the keyed slot map for streaming turns — a fan-out runs several turns side by side, one turn's failure never disturbs siblings. `load_task` is the supersede slot for the initial transcript load.
- **The optimistic user turn carries its reply antecedent** (`optimistic_user_turn`): an unparented row chains onto the flat-list tail, which momentarily unthreaded branch posts and lost the branch selection. Regression: `space_post_in_a_new_branch_stays_on_that_branch`. The antecedent is kept honest by `SpaceView::rebuild` → `rethread_drafts`: a draft names its parent by *action* id, and an edit supersedes that generation, so the draft is forwarded to the item's current tip on rebuild.
- **Submit = post + plan + fan-out.** `Space::submit` appends the optimistic turn and drives `AppCore::submit`; on `NotificationPlan::Turns` it runs one `start_turn` (→ `bridge::respond_stream_as`) per planned responder; on `Paused` it emits `SpaceEvent::CascadePaused` (rendered as the quiet cascade notice). Each turn's completion re-plans the cascade on its fresh post (best-effort) until the guard pauses. `Space::ask(participant_id, target_action_id)` is the explicit ask (band Ask, cascade continue, Retry) — an independent keyed turn that bypasses the cascade guard by construction.
- **Load-vs-mutation is serialized inside the entity.** Every mutation entry point runs `supersede_load_for_mutation` when accepted (drops the in-flight `load_task`, steps a data-less `Loading` back to `NotLoaded`), and `apply_loaded_transcript` is a no-op while anything owning the transcript's truth is in flight (`is_busy`). **Cancelling that load is a debt the operation owes at every exit** (STATE.md): success arms reload inline; every failure arm goes through `fail_mutation` / `fail_turn`, which **restarts the transcript load** and emits `Failed` — otherwise a cancelled bus-driven refresh is silently lost and durable rows a failed mutation committed never render. `fail_turn` removes only that turn's buffers + runner and records the `FailedTurn`. Replay tests: `space_stale_initial_load_does_not_replace_submitted_prompt`, `space_edit_and_regenerate_supersede_in_flight_load`, `space_mutation_failure_restarts_superseded_load`.
- **The transcript's own failure surface — "Failed is not empty" reaches the conversation.** `transcript_visible` was the window's only consumer of the transcript's `Loadable`, so a failed **initial** read rendered a blank page: no error, no Retry, and — correctly, there being no tree to attach to — no composer either, which is what made it a dead end rather than an ugly state. Nothing the reader could do re-ran the load; recovery meant another writer's `Change::Space` or closing every window on the space so the registry re-created its entity. `SpaceView::render_transcript_failure` now renders the house `load_error_panel` + Retry in the reading column's empty state, driving `Space::retry_transcript_load` → the same `load_transcript` everything else does. **Which failures it is offered for is the entity's decision** (`Space::transcript_load_failure`), and it is exactly the ones a later read could learn something from: a failed *refresh* keeps its posts and its composer and needs nothing; a **settled-negative row** (`row_is_gone` — a refused creation, a disposal's verdict) answers `None`, because `load_transcript` starts nothing there and a Retry could only refuse — that window already says so through its error band. Probe `space/transcript/retry`; regressions `a_failed_initial_transcript_load_offers_a_retry` (`tests/probe.rs`, both arms of the offered/not-offered rule) and `a_failed_initial_transcript_load_can_be_retried` (`tests/stores.rs`, real-core: the retry that fails lands back on `Failed` rather than the `Loading` it passes through, and the retry that succeeds opens the conversation); driver scene `space_transcript_failed`.
- **A failed turn never bricks the space:** the saved post stays; `Space::retry()` re-asks the recorded `failed_turn`'s participant via `Space::ask` (no re-post), gated by `can_retry()` (a failure is recorded and the exclusive slot is free; sibling streams don't block it). `retry` returns the retried turn's `seq` so `SpaceView::retry_failed` can select the branch that turn lands on before the next render (otherwise the streaming node attaches under whatever branch the user navigated to meanwhile) — the same deferral as an ask, below. **The recovery notice's lifetime is owned by the `failed_turn` record**, not the view-local error string: `StreamEnded` clears the notice only when no `failed_turn` stands (a sibling's success never hides it), and `Space::ask` clears the record only on an exact `(participant, target)` match — a real Retry. Dismiss (`SpaceView::dismiss_error` → `Space::clear_failed_turn`) ends the recovery. Recovery-path tests: `space_failed_ask_*`, `space_turn_failure_leaves_sibling_streams_untouched`, `space_sibling_success_keeps_failed_turn_notice`, `space_ask_other_post_keeps_unrelated_failed_turn`, `space_post_fans_out_one_turn_per_planned_responder`.
- **Incoming references are per-space domain state**: `incoming_refs: HashMap<action_id, Loadable<Vec<IncomingReference>>>` + keyed fetch slots — durable, per-space data (two windows must paint identical highlights). `ensure_incoming_references(action_id)` is the lazy per-post load (highlights are decoration: not-yet-loaded paints nothing; failed is not re-requested every frame). `SpacesStore::notify_space_changed` invalidates the cache on **every** live space, because a quote written in space B changes what space A highlights and the bus event carries only B's id.
- **Trace disclosures are per-space domain state**: `traces: Loadable<HashMap<anchor_action_id, Vec<PostTrace>>>` + one supersede slot over `AppCore::space_traces`. Loaded once per space (a turn's rounds are written in the space that ran them), so invalidation is **the changed space only** — contrast `incoming_refs`. `traces_expanded` rides here (a reload or another window must not collapse a disclosure), keyed on **`PostTrace::id`** (the turn), not the anchor — a post can carry several turns' disclosures.
- **Reasoning is durable** (app-core persists a `thinking` block — see `crates/eidola-app-core/AGENTS.md`). `ChatMessageView::from_post` splits: `text` blocks are the reading column (and the only quotable spans), the `thinking` block becomes `reasoning`. The live buffer is attached at finalize (by `response_action_id`) so the disclosure never blinks between stream end and reload; `merge_from_db` treats prior reasoning as **fallback only** (never overwrites what the tree supplied). `reasoning_expanded` is view state and always carried forward.
- **`EventEmitter<SpaceEvent>`** — `MessagesChanged` / `StreamDelta` / `StreamEnded` / `TurnEnded { seq, response_action_id }` / `Failed(AppError)` / `CascadePaused`. `StreamEnded` is also emitted when a plain post persists — the "this space settled" announcement either way. **`TurnEnded` names the turn on the way out** (both halves of its identity: the `seq` `ask` handed back, and the post it wrote — `None` for a decline), because a turn's streaming leaf is an ephemeral render key: work deferred onto that leaf has to follow the turn onto its post the moment the turn lands (see the ask's branch selection).

**The registry lives in `SpacesStore`** (`HashMap<SpaceId, WeakEntity<Space>>`):

- `open(id)` is get-or-create with join-existing: two windows on the same space share **one** `Space` (one transcript load; a submit/stream in window A appears live in window B). Tests: `space_joins_shared_entity_for_same_id`, `spaces_registry_joins_existing_and_blanks_are_distinct`.
- **`create()` is the ⌘N door, and it creates the space.** It mints the id client-side (`eidola_app_core::new_space_id`, UUIDv7 — the same source every other space id comes from), constructs the entity with an answered-and-empty transcript so the page is instant, registers it under that id **before returning**, and commits the row in a store-owned keyed slot (`AppCore::create_space_with_id` — the default template instantiated, the same door `post` takes for a space-less save). Two consequences worth stating: the window is addressed by a real space from its first frame, so every per-space surface works from birth and every store-wide broadcast reaches it by ordinary registry membership; and the insert outlives the window, so a ⌘N closed a keystroke later still leaves a whole space rather than half of one. **A refused insert leaves no space and therefore no registry entry** — `fail_creation` drops the key, records the refusal (the Library banner + the inspector's per-space one) and tells the entity, whose `row_is_gone` puts the error in the transcript cell: `transcript_visible` goes false so no composer is minted over a space that does not exist, and the window's own error band says what happened. Regressions: `a_new_space_is_registered_under_its_id_from_the_first_frame`, `a_refused_space_creation_says_so_instead_of_showing_a_blank_page` (`tests/behavior.rs`), `spaces_registry_joins_existing_and_new_spaces_are_distinct` (`tests/stores.rs`).
- **Closing the last window on an untouched space disposes of it.** ⌘N creates a space, so without this every abandoned new window (and every launch that opens a blank one) leaves a durable empty conversation in the Library forever. The GUI answers exactly one question — *was that the last window* — and app-core answers everything else: `SpaceView`'s `cx.on_release` **is** the close (a view lives exactly as long as its window), `Space::has_other_open_window(closing, cx)` answers the question by naming the window it is about (a view is released in the same effect flush that removes its window, so whether `cx.windows()` has caught up is not something the caller should have to know), and `SpacesStore::window_closed` hands the id to `AppCore::discard_if_pristine`, which decides — inside the transaction that deletes — whether anything here is worth keeping. **A space whose insert is still in flight is deferred, not skipped** (`reap_after_creation`, released by the creation task's success arm): disposing of one before it exists would answer "no such space" and leave the very orphan this exists to prevent, and ⌘N-then-immediately-close is the paradigm case rather than an edge one. **A reopen and a disposal can never both proceed, and the boundary is a main-thread segment.** Store calls run on gpui's main thread, and so does every stretch of a spawned task between its `await` points — and `bridge` issues its core call on the **first poll** of the future being awaited, before it suspends. So the disposal task's registry recheck and the issuance of the delete are one uninterrupted segment, and a `SpacesStore::open` can only land on one side of it, never between. **Before it**: the recheck upgrades a live entity (the entity outlives the frame its last window closes in, so by the task's first poll the release has run and an entry that still upgrades can only mean a *new* window), the disposal abandons the space untouched, and the window it found is released with `row_committed` — a reopen cancels a disposal. **After it**: the delete is already travelling, so `open` may not proceed blind — it constructs its entity with the row **undecided** (`RowState::Deciding`, the same gate ⌘N's insert uses), and that entity's transcript load and every save queue behind the verdict the task then settles: kept → `row_committed` and the window works normally; taken → `row_is_gone`, and the window reports the conversation is gone instead of offering a composer over nothing. A disposal therefore never judges a space a window is already using, and no window ever reads or writes against a space a disposal is about to judge. One verdict per id is in flight at a time, because replacing a live disposal would drop the task whose settle a waiting window depends on. **A write this client has already issued outranks the disposal, and the close is where that is decided**: a `bridge`d core call outlives the gpui task that issued it, so a Send (or a rename, or a roster edit) a moment before ⌘W leaves a write travelling to the database the disposal is about to reserve the writer on — and if the disposal gets there first the space is still pristine, so it goes, and the write lands on nothing with no window left to report it. `stores::space_writes_in_flight` is that question, asked at the release **while every owner is still alive to answer** (the entity dies with its last window, so afterwards there is nothing to ask), and it is spread across four owners no one of which can see the others: the conversation's own saves and turns (`Space::is_busy` — `post_runner`, `streams`, `turn_runners`, which is also what covers edit, regenerate and a queued first Send waiting out its insert), `SpacesStore`'s rename/archive slots, `SpaceSettingsStore`'s cascade/router slots, and `ParticipantsStore`'s roster slots. `window_closed` honours the answer and adds its own store's. **Nothing is deferred or retried on that arm**: the write either lands (marking the space, which keeps it for good) or fails (leaving a pristine space nobody holds), and the next launch's sweep collects the second case exactly as it collects a crash's orphans. A stale `true` only keeps a space; a stale `false` cannot happen, because nothing can begin writing to a space whose last window has gone — which is also why the deferred-behind-the-insert arm needs no second look. A refused or failed disposal says nothing to anyone: nobody asked for it, the Library is unchanged, and the next launch's sweep gets another go. **Residual, and its accounting:** a per-space **configuration** write issued *after* the delete is on its way — a rename from the Library row that is still listed, or a cascade/router/roster edit in an inspector — is refused rather than gated, because those live in three other stores and the reopened window is not the only surface that can reach them. **Refused, not merely unlucky: every one of those doors decides the space's existence at its own write** (app-core's decide-at-the-write rule — `rename_space` reads `update_space_title`'s rows-affected, the two settings setters already did, the participant writes carry their predicate in their own `WHERE`, and the roster adds are refused by the foreign key and then *named* by a read that only explains). So none of them can report success for a write no row took, which is what would leave an optimistic edit standing over a database that never agreed to it. Each refusal is typed, renders in its own per-space `op_error`, and has its optimistic edit reconciled by the unconditional re-list, so the reader sees what happened and what to retype. What it costs is re-entering a title or a label. It is not gated because the verdict window is one local transaction wide, reaching it needs a human to open a panel and edit a field inside that, and none of these writes consumes prose the way a composer does — which is the one the entity's gate does cover. Pinned by `every_configuration_door_refuses_a_space_that_is_gone` and `a_refusal_names_the_missing_space_rather_than_its_constraint` (`crates/eidola-app-core/tests/reap_pristine.rs`). Regressions: `a_new_space_nobody_touched_goes_with_its_window`, `a_conversation_someone_wrote_in_survives_its_window`, `closing_one_of_two_windows_disposes_of_nothing`, `a_save_still_in_flight_holds_off_the_disposal` + its mirror `a_settled_space_is_still_disposed_of_at_the_same_close` (`tests/behavior.rs`, real-core, real windows), `a_window_closed_over_its_own_insert_still_leaves_nothing_behind`, `a_reopen_before_the_verdict_cancels_the_disposal`, `a_window_waiting_on_a_verdict_never_writes_and_then_reports_it`, `a_refused_creation_after_an_early_send_says_so_instead_of_spinning`, `the_store_never_disposes_over_an_outstanding_write` (`tests/stores.rs`). The deferral regression observes **both ends** — the deferral taken while no row exists, and app-core's own report that it deleted a space under that id (`disposed_for_test`) — because a disposal that succeeded and one that never ran both leave the id naming nothing, so "it is gone" alone is satisfied by the state that test starts in.
- **The first Send waits out the insert — the entity's mutations do, the frame does not.** The store's insert and `Space::submit` are independent work on one runtime, so a Send pressed in the frames after ⌘N could reach `post`'s space-existence check first: refused with "space not found" for a space that then exists, and `fail_mutation`'s reload took the optimistic user turn off the screen with it — the reader's words gone from a perfectly good conversation. The entity therefore holds **whether its id is known to name a row** (`RowState::Deciding` / `Gone`, settled by `row_committed` / `row_is_gone`) and every save-side mutation — submit, post-only, edit, regenerate, the four that share `post_runner` — awaits it **inside its own task**, so the draft is still accepted on the frame and only the write is ordered. `Gone` answers immediately with the reason rather than leaving a waiter on a settle that has already happened. **One gate, two writers**: the insert is deciding whether the row will exist and a disposal is deciding whether it still does, and both leave every call with the same question to ask — so the disposal reuses this gate rather than adding a second thing each mutation has to remember (see the close trigger below). The transcript **load** waits on it too, which is what keeps a window from being handed a loaded-and-empty conversation over a row that is still being judged — **and once the row is settled-negative it does not start at all**: `row_is_gone` puts the verdict in the transcript cell, which is the whole of what the window shows about a dead space, and a reload would flip that terminal failure to `Loading` (`Failed { prior: None }.to_loading()` is `Loading`) and then refuse at its own gate before anything could resolve it — a permanent spinner with the real error destroyed on the way. The path is ordinary rather than exotic: every save-side failure completion restarts the load, and a Send that beat its space's insert (or its disposal's verdict) fails. Regression: `a_refused_creation_after_an_early_send_says_so_instead_of_spinning`. The turn path needs no clause: `start_turn`/`ask` require a persisted target, which only a completed save produces. **The configuration writes deliberately do not wait** — the inspector's title, cascade, router, roster and invite all take a human interaction after ⌘N (orders of magnitude longer than a local insert), each refuses with a typed `NotConfigured` rather than writing partially, each renders that refusal in its own per-space `op_error` with the optimistic edit reconciled by the unconditional re-list, and none of them consumes the reader's prose. The composer is the one that does, which is why it is the one that is ordered. Regressions: `a_first_post_into_a_brand_new_space_waits_out_its_insert`, `a_post_into_a_space_that_was_never_created_is_refused` (`tests/stores.rs`, real-core, staging the interleaving rather than hoping for it).
- **Its reads race its own insert, and the bus is what settles them.** The window issues this space's roster (and, on ⌥⌘I, its settings) read in the frame it opened, which can precede the commit it is reading behind — answering "empty" / "no such space". So instantiation announces all three of what it wrote: `SpaceIndex` (the listing), `Participants` (the membership rows) and `Space(id)` (the space row the settings live on), and each store reconciles through its ordinary subscription rather than one store orchestrating another. See `crates/eidola-app-core/AGENTS.md`; regression `inspector_participants_work_on_a_fresh_space_with_no_posts`.
- `Change::Space(id)` routes to `notify_space_changed(id)`, which tells the live entity to refresh its transcript (ignored while its own operations are in flight — each reloads on completion).
- **`Change::Participants` routes to `notify_participants_changed()` — every live space, no id.** A transcript is where an author's *name* lives: `get_space_tree` resolves each post's byline **and** each reference edge's carried author identity through `COALESCE(space_participant.override_label, participant.label)` at read time, and nothing re-derives them afterwards. A rename emits `Change::Participants` and nothing else, so before this every open window kept naming the author as it did when it loaded — post gutters, minimap labels and footnote rails alike — until an unrelated `Change::Space` or a reopen (Codex review, PR #292). The signal carries no id (a global agent is renamed everywhere at once, an override is written per space), hence every space; deliberately **not** through `notify_space_changed`, whose other two effects are about *posts* (nothing a participant edit does invalidates an incoming-reference index or a trace round). Each entity's own `is_busy` gate still applies — and it **defers, never discards** (`Space::invalidate_transcript` → `pending_transcript_refresh` → `settle_transcript_debt`, called from every exit that can clear `is_busy`, the same debt-at-every-exit rule the superseded load obeys). The operation's own exit reload is not synchronization: `get_space_tree` is several reads, so a rename committing while they run is caught by none of them, and the event announcing it arrived while the space was still busy — dropped, with nothing left to correct the stale names (Codex review, PR #292). A read issued while nothing is in flight discharges the debt by construction (a `Change` is emitted only after its commit is durable and delivered on this thread), which is why the failure exits need no call of their own. **`Lagged` reaches the live spaces too** — `refresh_everything` re-read `SpacesStore::refresh`, the *Library index*, and told the entities nothing, so a lag that swallowed a rename left every open transcript stale indefinitely while the recovery claimed to have refreshed all state; `notify_lagged` now drops all three things a space resolves at read time (transcript, incoming-reference index, trace rounds — the latter two are per-entity caches whose only other route is `notify_space_changed`, which the lagged path never called either). **And "every live space" is the registry** (`SpacesStore::live_spaces`, the one door all three store-wide sweeps go through — Codex review, PR #292): a space created a moment ago is an ordinary member of it, so a rename landing while its first read is in flight reaches it like any other, and the entity's own mechanism does the rest — the debt is recorded on the busy space and its save's exit discharges it (`finish_reload` / `submit`'s success arm; the failure arms restart the load unconditionally). Regressions: `a_participants_change_re_reads_a_live_transcript`, `a_lagged_bus_re_reads_a_live_transcript`, `a_participants_change_arriving_mid_operation_is_replayed`, `a_participants_change_reaches_a_brand_new_space_mid_save` (`tests/stores.rs`, real-core). **Residual:** `on_space_changed` still discards on the busy gate, a one-line change deliberately not taken — that signal fires on every post and almost every one is this space's own write, already in the exit reload, so deferring it buys a redundant whole-tree re-read at the end of every turn to close a window only a *foreign* concurrent post can open.

## Onboarding window

`onboarding/mod.rs`'s `OnboardingView`: a standalone **singleton window** presenting one continuous scrolling page of stacked slides, sized like a new space window (`lib.rs::writing_surface_size`), each slide content-sized (`min_h` of one window, growing past it). Opened automatically at launch when `ConfigState` has no account **and the eidola backend is enabled** (a user who chose "continue without an account" disabled the backend; a failed registry read errs toward showing the dismissible window), and via Eidola menu → Get Started.

- **At launch onboarding opens *instead of* a blank space.** The corollary: `OnboardingView::leave` (the deliberate exits) opens a blank space **only when onboarding is the last window** (`cx.windows().len() <= 1`). **Order is load-bearing: open first, close second** — `remove_window` only flags; gpui tears down as the update unwinds and then runs its quit-on-empty check, so the replacement must already be in `cx.windows()` (a `cx.defer`'d open would land after a Linux windowed launch already quit). A bare ⌘W stays a plain `remove_window`. Tests: `onboarding_skip_account_disables_eidola_and_hands_off_to_a_space`, `onboarding_leaving_with_a_window_behind_opens_no_extra_space`.
- **Structure — stateful view + stateless slide components.** `mod.rs` owns all state (reveal machine, scroll/snap physics, async account ops) and a `render_slide` router; each slide in `slides.rs` is a `#[derive(IntoElement)]` + `RenderOnce` component carrying its own `MARKDOWN` const, extras, and CTAs. The slide's disabled prose editor is element-owned state (`window.use_keyed_state`, keyed per slide) — safe *only because* every revealed slide paints every frame (no virtualization); if slides ever render conditionally or through `list()`, lift that state onto the view (element-owned parsed state dies with an unmounted `list()` item). State the view must read (input states, the `agreed` consent bit, async results/slots) stays lifted. Flow sequencing stays in the router so the branch structure is visible in one match.
- **Reveal state machine.** `revealed: Vec<Slide>` starts `[Slide::Pause]`; only revealed slides render. `reveal(after, next)` appends and animates-scrolls; when the choice *changes*, it truncates the stale downstream slides first (re-choosing a branch replaces the tail). Idempotent when `next` already follows. `reveal` records a `pending_scroll` index consumed in `render` (where `window` is available) so async callbacks can reveal without a `Window`.
- **Back navigation:** every slide past the first carries an up-chevron (`slides::back_button`, probe `onboarding/back/{index}`) gliding to the previous slide. The `pinned_y` resting offset is set synchronously by the glide — the behavior-test seam.
- **Slides:** `Pause → Tool → Control → Responsibility → GetStarted`, then **new** (`CreateAccount → NewAccount → Purchase`) or **existing** (`ExistingAccount → Purchase`) — or the quiet third choice "Continue without an account" (`skip_account`, probe `onboarding/cta/skip-account`), which disables the eidola backend and closes the window. `CreateAccount` gates its CTA on a required agreement checkbox; `NewAccount` shows the minted id/secret with Copy affordances; `ExistingAccount` swaps CTAs on the balance-check result; `Purchase` renders `plans::plan_rows`.
- **Snap = proximity, not mandatory.** While the finger is down the page scrolls natively (recording release velocity); at finger-lift `nav::proximity_snap_target` decides over live slide-top offsets: near a boundary → glide to it (`drive_snap` frame loop) and **suppress the OS momentum that follows** (macOS delivers post-lift momentum as `TouchPhase::Moved` with no end signal at this gpui pin, so we `stop_propagation` + `reassert_scroll` on every trailing step); deep in a slide → release and let momentum settle. Reveal/back glides are programmatic and always land exactly. `SNAP_PROXIMITY_FRACTION = 0.25`; `proximity_snap_target` is a pure fn unit-tested in `nav.rs`.
- **Account ops** go through `AccountStore`'s awaitable `request_*` methods, each owned in a view task slot: `begin_create` (stores id/secret, refreshes, reveals `NewAccount`), `begin_verify` (sets credentials, fetches balance, **rolls the write back on failure**), `begin_checkout` (→ `cx.open_url`). The `Purchase` slide narrows to one-time top-ups when the account already subscribes (the server refuses a second) and points at Settings ▸ Account for management rather than growing a second portal door; revealing the slide is what asks for the subscription read, since the existing-account branch can arrive here with one. The server collapses "no such account" and "wrong secret" into one 401 (anti-enumeration), so `verify_error_copy` shows one honest message.
- Tests: `onboarding_*` in `tests/behavior.rs` (incl. `onboarding_slides_size_to_content_and_grow_on_small_windows`); probes `onboarding/cta/*`, `onboarding/input/*`, `onboarding/back/*`; driver scene `onboarding` (the headless dispatcher doesn't pump `on_next_frame`, so glides don't visibly complete there — behavior tests assert `pinned_y` synchronously). **Deferred:** not-found vs wrong-secret (server-limited), post-checkout balance poll.

## Theme — Circadian (`src/theme.rs`)

Two user-facing axes, persisted in app-core config, surfaced in Settings → General:

- **Day/night** (`AppearanceSetting`, key `appearance`): `system` (default) / `day` / `night` / `auto` (follow the sun; fixed 06:00–18:00 without geography).
- **Time of day** (`TimeOfDayTint`, key `time_of_day_tint`): `on` (default) tints the palette with the light's character *right now* — cool around sunrise, neutral at solar noon/midnight, warm around sunset; `off` pins the character to the `light_character` choice (`cool`/`neutral` default/`warm`; serde aliases keep pre-rename `bluish`/`orange` parsing), a third Settings row shown only while the tint is off. Six palettes (Dawn, Sunrise, Day, Sunset, Dusk, Night) anchored to the real solar day.

**Type scale (`font_scale`)** is the third persisted axis — View → Actual Size / Zoom In / Zoom Out and the Settings Text-size row. It multiplies the ramp at exactly **two** anchors, the app's two font-size roots: (1) the theme UI font size (`UI_FONT_SIZE` = 14) — gpui-component installs it as the window **`rem_size`**, so every `rems()`-relative size scales in one move; (2) the prose reading size (`space_view::prose_style`, the one place spelled in absolute px, so it multiplies `theme::font_scale(cx)` itself). The space view's height cache is keyed on `(body_width, scale)` — a zoom reshapes every post — and `estimate_post_height` multiplies by `Layout::scale()`. Clamped `[0.8, 2.0]`, stepped through app-core's `FONT_SCALE_STEPS`. Fixed-px chrome (titlebar reserve, Settings nav width) does not scale.

**Geography from the timezone** (`src/solar.rs`): the IANA zone name (`$TZ` or the `/etc/localtime` symlink) resolves to representative coordinates via the OS's own tzdb tables, and the standard sunrise equation (pure, unit-tested against solstices + polar cases) yields today's `DayPhases` — no location permission, no network, no chrono. `canonical_hour` warps wall time so sunrise lands at canonical 06:00 and sunset 18:00; the tinted slots hug the sun's events ±2 canonical hours with long neutral middles. Degrades honestly: geography-free zones / unreadable tzdb → `DayPhases::Clock`; polar no-event days → `PolarDay`/`PolarNight`. Coordinates are memoized per zone name; the zone name is re-checked each tick (a readlink), so travel is picked up.

The tinted variants are **derived, not hand-authored**: `tinted` blends every neutral-palette color a few percent toward a per-family blue/ember anchor (`tint_spec`), preserving alpha and relative contrast — tuning a neutral color tunes all six palettes. One exception: the day variants tint the near-white paper grounds (`DAY_PAPER_SOFT_TINT` list) at 0.6×, so the sheet stays continuous while the cast reads in chrome and mid-tones. The day chip/chrome family is neutral grey with warm brown foregrounds (day's mirror of night's cool-chip/warm-text tension). `resolve(settings, system_is_dark, now_min, phases)` is the pure core (unit-tested); `apply` is the only path that changes the global `Theme`.

Wiring:

- `theme::install` (after `gpui_component::init`) loads fonts and applies the **neutral** palettes under the system appearance — tests, the visual harness, and the driver stop here, so their palettes are deterministic.
- `theme::wire_config` (production `run()` only) seeds `ThemeSettings` from `ConfigStore`, re-applies on every config change, and runs a once-a-minute clock task that re-applies on slot-boundary crossings. Both are app-lifetime (the sanctioned `.detach()`).
- Each window subscribes via `theme::observe_window_appearance(window)` — macOS Light/Dark updates live under `system` and is correctly ignored otherwise.
- Local civil time comes from `libc::localtime_r`; `tm_gmtoff` supplies the UTC offset.

Anchors (the product's "good paper at noon, reading lamp at midnight" pair): **Day `#ffffff`** — neutral near-white paper; the base's only warmth is a few accent foregrounds, never the ground. **Night `#15191e`** — cool blue-grey dark; elevated surfaces follow the blue-grey ramp (R < G < B throughout), text stays warm-grey (`#d4d0c8`), brand warm orange (`#c39669`). The warm-on-cool night tension is deliberate; don't "fix" it by cooling the foregrounds. These anchors are the reference (not the marketing site).

**Body font is Newsreader 16pt** (SIL OFL 1.1) — **six static TTF instances** (Regular, Italic, Medium, SemiBold, Bold, BoldItalic) in `assets/fonts/`, embedded via `include_bytes!`, registered with `cx.text_system().add_fonts`. Statics rather than the variable fonts because **gpui's macOS text system does not apply variable-font weight axes** — each TTF registers as one face at its default instance, so with only variable TTFs every weight request resolved to Regular and rendered un-bold. The Medium (500) face backs the prose heading weight. The theme family name is `"Newsreader 16pt"` (the typographic family, nid 16, that all six faces report).

## Localization (`locales/`, `build.rs`, `src/i18n.rs`)

User-facing strings live in Fluent (`.ftl`) files under `crates/eidola-gui/locales/<tag>/`, one directory per shipped locale — **`en` (the source), `es`, `fr`, `zh-Hant`, `zh-Hans`** — and reach the views through **generated typed accessors**, never through raw ids. This is a GUI-only concern: `eidola-app-core` stays locale-free and keeps returning typed errors, which is the layering the "UIs route on variants, not strings" rule already set up. The CLI and website are out of scope.

**Every string is compiled in; nothing is ever read from disk.** `build.rs` emits the FTL as string literals into `$OUT_DIR/i18n_generated.rs`, which `src/i18n.rs` `include!`s. That is a **security** property, not packaging convenience: the artifact hash is the trust root, so a translation loaded at runtime would be an unmeasured input able to rewrite security-critical UI text — "this connection could not be verified" becomes "verified" with a text edit and no signature to break. The accepted cost is that **adding a language is a release**. Do not introduce a runtime loader, an env-var override, or a "load extra translations from the profile" door.

**Adding a message** — write it in `locales/en/<topic>.ftl`, rebuild, and call the generated accessor: id `about-version-value` becomes `i18n::msg::about_version_value(cx, version)`. A locale directory may hold several `.ftl` files (they are concatenated in filename order); the file's *name* carries no meaning, so group by surface. Translations restate the same ids in their own directory and may omit any of them.

**The codegen contract** (`build_support/codegen.rs`, included by both `build.rs` and `tests/i18n.rs` so it is testable without committing malformed FTL). The module doc carries the authoritative enumerated list — keep the two in step, and add a rule there whenever you add a way to fail. In summary:

- One accessor per **English** message, with one parameter per placeable variable, in first-appearance order — so a **mistyped id is a missing function** and a **changed argument set is a changed signature**. Both are compile errors at the call site.
- **A locale directory must be a canonical language tag.** The directory name *is* the tag at runtime and negotiation resolves to canonical spellings, so a `zh_Hans` or `zh-hans` directory would ship a translation nothing could ever select — silently, since it still parses and still embeds.
- **Malformed FTL in *any* locale is a build error**, not just the source.
- **A translation may not need a variable English does not pass** — in its own body or through anything it references. Nothing would ever fill it.
- **A translation inventing an id is a build error** — either dead weight or a typo silently falling back.
- **A missing translation is fine.** Hard-failing on an untranslated string is the wrong production behavior; the untranslated message renders as English (see the merge, below).
- **Every reference must resolve through the merged view** — locale first, English behind it, which is exactly what the runtime bundle holds. **Term chains are followed to their end**, not checked one hop deep: `-brand` being defined says nothing about the `-missing` it reaches for. **Reference cycles** (message or term) are refused; Fluent gives up on one at runtime, so the build gives up first.
- **Every message that can format in a locale validates under that locale's merged view** — *all* source messages, not just the translated ones, plus every term either side defines. Two exemptions refused at once: nothing is skipped for being unreferenced (dead text today is referenced tomorrow, and the reference site would not be the broken one), and nothing is skipped for being untranslated (an untranslated message still formats in that locale, through *its* overrides). So every rule that depends on what a reference **resolves to** is decided per locale, never once against the source: a source message reaching a term some locale overrides can be perfectly legal in English and over Fluent's placeable limit in that locale, with each side validating alone.
- **No function references.** Nothing registers a Fluent function: `FluentBundle::new` starts with an empty entry table, and fluent-bundle's `add_builtins()` is opt-in and supplies only `NUMBER` at 0.16 (`DATETIME` is still a TODO upstream) — `bundle_for` calls neither. So `{ NUMBER($n) }` would render `{NUMBER()}`. The number/date formatting work is what will register functions and loosen this to the registered names.
- Selectors (plurals/gender) are supported in message bodies and their variable counts as a parameter. A message reference folds the referenced message's variables in — resolved through the merged view, so a translation referencing an untranslated message inherits *English's* variables.
- **Attributes are refused** on messages *and* terms, loudly rather than ignored — the model is one message, one accessor, and ignoring an attribute would let a translator write text that ships inside the binary and never reaches a screen. References to attributes are refused for the same reason (nothing could resolve them). A **term** stays closed: its body may reference other terms, never messages or variables, so nothing can reach through one for a variable to fill.
- **Duplicate message or term ids are refused** — a later definition would silently shadow the earlier one.
- **No message may resolve past Fluent's placeable limit.** fluent-bundle counts placeables *through* reference expansion on a single per-format counter and bails at 100 (`MAX_PLACEABLES` in its `resolver/pattern.rs`), returning the message truncated or with raw ids left in it — so a perfectly legal, acyclic chain that doubles (`a = { b }{ b }`) still breaks at seven levels. The build computes each message's resolved count per locale through the merged view with the resolver's own semantics: one per pattern element, a reference paying its own cost with multiplicity, a select paying only its **worst** variant (exactly one is ever written), and a placeable nested inside an expression paying nothing extra. Memoized, because evaluating a doubling chain naively is exponential.

Together these are what make a runtime formatting error impossible rather than something to recover from, which is what the `debug_assert` in `Localization::format` asserts.

**Fallback is structural, not a lookup order.** A locale's bundle is **one** `FluentBundle`, built as the English resource then that locale's own via `add_resource_overriding` — so an untranslated message is *present as English* rather than absent. This is not an optimization over a chain of bundles; a chain is wrong. **Fluent resolves a message reference against one bundle only** (`fluent-bundle`'s resolver asks `scope.bundle` and nothing else), so a translated message reaching through `{ about-title }` for a wordmark its locale never translated resolves to nothing, and `format_pattern` answers with the reference's own error text — `关于 {about-title}` — while reporting a `ResolverError`. A chain never gets a turn: its first bundle *has* the message, so it returns the broken string, and in a release build the `debug_assert` on those errors is compiled out. The merge makes the promised fallback true by construction and leaves no error branch for it to depend on. The build-time reference checks resolve through the same merged view, which is what keeps a formatting error impossible. **The accepted cost:** the bundle's locale is the active one and fluent-bundle takes plural rules from `locales[0]`, so an *untranslated* message carrying a plural selector selects with the active locale's categories — a string already showing in the wrong language, whose cure is to translate it. Regression: `a_translated_message_can_reference_an_untranslated_one` (the About window's title is the live case — every locale translates it and every locale reaches through `{ about-title }`, which none of them translate).

**The runtime.** `Localization` is a gpui `Global` (per `STATE.md`) holding the active tag and its bundle; `i18n::install(cx)` seeds the source locale beside `theme::install`, and `i18n::wire_config(&stores.config, cx)` — production `run()` only — resolves the real one and re-resolves on every `Change::Config`. `i18n::apply` is the single path a locale ever changes through (it refreshes every window). Isolation marks are off (`set_use_isolating(false)`): they are invisible bidi controls, we ship no RTL locale, and gpui would have to shape them.

**Locale resolution** is one pure function, `i18n::resolve(stored, system_preferred)`: the persisted `language` config key decides, and only when it says `auto` does the OS list (via `sys-locale`) get a say. **Chinese is matched by script, not by exact tag**, because platforms report a region and we ship the two writing systems: an explicit `Hans`/`Hant` subtag wins, then `TW`/`HK`/`MO` are Traditional, and everything else — including a bare `zh` — is Simplified. Every other language matches on its language subtag alone. A stored tag naming no shipped locale falls back to "follow the system"; nothing matching the system list falls back to `en`. The config key is stored **opaquely** by app-core (see `crates/eidola-app-core/AGENTS.md` → Config) — resolving it is this layer's job. **There is no Settings picker yet**; the override is config-level until the settings sweep adds one.

**Tests are locale-independent by construction, and nothing pins anything.** A lookup with no `Localization` global installed answers from the source locale, so every behavior/probe/visual context is English without a line of setup. Do not install a non-English locale in a shared fixture — a wording assertion elsewhere would then depend on it. The driver starts on the source locale too and takes `{"cmd":"locale","tag":"zh-Hans"}` to switch (scene `about`).

**Localized strings *are* the accessible labels** — `probe(name, role, label)`'s `label` takes the message, which provably cannot break QA because the driver keys on `name`. **Probe names never localize**: they are stable slash-scoped selectors, and translating one breaks a selector the way translating an id breaks a lookup.

**Menus localize wholesale or not at all.** A single translated entry inside an otherwise-English menu reads worse than a consistently English one, so no menu item moves into FTL until its whole menu does. That defers three surfaces, deliberately and as a set: the native menu bar (`install_menus` in `src/lib.rs` — six menus, ~26 labels plus the dynamic template submenu), the in-window "Eidola menu" (`chrome::ChromeRoot::render_menu_panel`), and the status-item menu (`src/status_item/`). Both menu builders are already idempotent and re-invoked (`install_menus` rebuilds on every template change), so re-installing them on a locale change is a line of wiring when the sweep arrives — the reason to wait is consistency, not mechanism.

**A window title is not a view string.** `Window::set_window_title` is called once, at open, and lives outside any render, so it does not follow a locale change the way a drawn string does. `run()` re-applies the localized titles from `retitle_windows`, hung off `cx.observe_global::<i18n::Localization>` — `i18n::apply` is the single path a locale changes through and it replaces the global, so the observer catches every change without `lib.rs` knowing how one is decided. Any newly localized window title joins `retitle_windows`. Note what the title is *for*: it paints nothing (transparent title bar, `NSWindowTitleHidden`), but it names the window in the macOS Window menu, the window switcher and VoiceOver's window chooser, and labels the accessibility tree's root node — so it is part of the window's accessible surface, and it has no readable test seam (gpui's test platform keeps `PlatformWindow::get_title`'s empty default; `Window::a11y` is crate-private). `a_locale_change_notifies_global_observers` covers the trigger instead.

**What is localized today**: the About window — its body (`src/about.rs`) and its OS window title. `about-title` is deliberately untranslated in all four non-English locales (the wordmark is the same everywhere), which makes it the fallback chain's live proof. The two entry points that *open* About — the native menu bar's "About Eidola" and the in-window menu's — remain English under the wholesale-menu rule above; everything else is still English pending its own extraction. Tests: `tests/i18n.rs` (negotiation incl. the `zh` mapping and an unsupported locale, the fallback across an untranslated reference, every message formatting in every locale, the locale-change notification, and each build-error rule asserted against the codegen directly).

## Prose typography — book metaphor

Conversation prose gets typography of its own (settings/wallet/account stay on the 16px UI baseline). Knobs in `space_view/mod.rs` — `PROSE_FONT_SIZE` (17px), `PROSE_LINE_HEIGHT` (1.65), `PROSE_PARAGRAPH_GAP` (1.5) — feeding `space_view::prose_style`, the `MarkdownStyle` shared by every post body *and* the composer, so a post renders pixel-identical to what the user typed.

- Body 17px / 1.65× leading; reading measure capped at `BODY_MAX_WIDTH` (600px). Side gutters remain while they leave that full measure; below that threshold their metadata and actions stack above/below a centered column with a symmetric `POST_PAD_Y` edge inset. The column stays capped until the page becomes narrower than `layout::compact_full_measure_page_width()`, then yields with the page. The **default window width is derived from the side-gutter threshold** (see [Window model](#window-model)).
- Heading ramp anchored to body size (h1 2.5× / h2 1.75× / h3 1.25× / h4–h6 1.125×), every level at uniform **Medium (500)** weight — size carries hierarchy; mirrors the website's prose ramp (`www/static/site.css`). (The editor crate's *default* ramp is flatter; only the app's prose surface overrides it.)
- Inline code in Courier New — its x-height (0.423 em) matches Newsreader's (0.426) almost exactly, where Menlo reads ~28% larger. Fenced code blocks keep Menlo.

**Identity travels with each post**: the byline gutter is part of the post row — no separate persistent participant indicator, and neither the title band nor the composer carries model chrome (who answers is Participants configuration). The gutter stacks up to three lines: author, the serving **backend's display name** (assistant rows only, suppressed when it repeats the author), time. In compact layout those labels share one clipped line: author and backend shrink and truncate independently while time stays fixed, but the article's accessible name always carries the complete author/backend/time string. The split comes from `SpaceView::model_display`, resolved into `PostData` at `rebuild` (also triggered by the `local_models`/`backends` store observers, so a late-landing display name re-labels the gutter); the minimap's a11y labels inherit it. The raw selection id remains what's persisted.

## WindowInput — per-window modifier state

`src/window_input.rs` — a per-window gpui entity holding the live modifier state. It exists because `ModifiersChangedEvent` at our pin dispatches along the **focused element's ancestor path only** — a listener on a sibling branch never fires.

- Each `open_*_window` builder creates one `WindowInput` and passes it to the view constructor.
- The root view registers the window's **single** `on_modifiers_changed` listener and forwards into the entity.
- Descendant views observe the entity and read `alt_held()`; they never register their own listener. **No view below the root may call `.on_modifiers_changed`** — adding a new ⌥-affordance means observe `window_input`.
- Staleness: gpui has no window-activation hook at this pin, so `alt` may linger `true` after switching away mid-hold; self-healing on the next event and harmless (the ⌥ reveal is cosmetic).
- Test helpers: `set_alt_for_test` (snapshot tests); `VisualTestContext::simulate_modifiers_change` drives the real dispatch path.

## Streaming chat

The `Space` entity drives response turns via `bridge::respond_stream_as` inside its keyed `turn_runners` slots. The core posts `stream: true` and forwards `delta.content` as `ChatStreamEvent::ContentDelta` and `delta.reasoning_content`/`delta.reasoning` as `ReasoningDelta`; the terminal `ChatResult` arrives on a oneshot after the delta channel closes.

Each in-flight `StreamingTurn` holds its live buffers + disclosure flag; each delta emits `StreamDelta`. `SpaceView` renders every turn as a streaming leaf attached at its **target** post — concurrent replies land as timestamp-ordered sibling branches, each with its own per-`seq` body editor and "Thinking…" disclosure; branch dots include streaming leaves (tinted `info`) so a fan-out's second stream is discoverable. On done, the runner removes its stream entry, reloads the transcript, attaches captured reasoning to the persisted response (belt-and-braces for the frame before reload), emits `StreamEnded`, and re-plans the cascade.

- **A turn waiting on its engine says so**: while the responding participant's model is engine-served and still warming, the streaming leaf leads with a quiet "Loading model…" readout (`Role::Label`, probe `space/streaming/{seq}/loading`). Pure GUI correlation (`SpaceView::turn_engine_is_warming`) over two snapshots the view already re-renders on (`ParticipantsStore` model_ref → `LocalModelsStore` status). A remote backend, unknown participant, or loaded engine shows nothing — the silence is then genuinely the model thinking. Regression: `space_streaming_turn_reads_loading_model_while_its_engine_warms`; driver scene `space_model_loading`.
- **The disclosure toggle has three states** in the shared quiet-verb look (`post::verb_button`): "Thinking…" live, then "Show/Hide thinking" (`post::thinking_labels`; the accessible name always says what the click *does*). It survives finalize and reload (reasoning is persisted).
- The CLI streams too: `ContentDelta` → stdout, `ReasoningDelta` → stderr (dimmed, `thinking: `-prefixed on a TTY) so piped stdout captures only the answer.
- Streaming refunds always go through the `/v1/credentials/refund` recovery endpoint after the stream ends (SSE has no inline body to carry the token) — the same endpoint as the blocking path's network-error fallback.

## Space view — tree-navigation conversation surface (`src/space_view/`)

`SpaceView` is the window root for a conversation (it replaced `ChatView`; `chat.rs` is deleted). It renders a space as a tree of **recursively-nested scrollers** — vertical scroll walks the selected root→leaf path; horizontal scroll flick-snaps between sibling branches, each page carrying its whole subtree — with a right-edge topology **minimap** and a floating/docking **composer**. A window-local lens over the shared `Entity<Space>`.

Submodules (impl blocks split across files on one `SpaceView`):

### `model.rs` — the UI tree

`Space` loads a flat `Vec<ChatMessageView>` (DFS pre-order, each row carrying `parent_action_id`); a per-frame-cheap `PostData` snapshot (rebuilt only on transcript change) feeds `build_tree`, which relinks the flat list into `TreeNode`s. Unparented rows chain onto the previous row so the conversation forms one spine. Pure + unit-tested. `NodeSrc` is `Msg(idx)` | `Streaming(seq)` | `Draft`; each in-flight turn is a synthetic leaf attached at its target post; the composer draft attaches at its reply target (`attach_overlay`). **`PostData` carries `item_id` beside `action_id`** because a window-local reference can outlive the generation it names: `rebuild` → `rethread_drafts` forwards any draft whose parent action id vanished to that item's current tip — without it, a draft that outlived an edit of its parent mis-threaded and could land durably at the space tail. Regression: `space_draft_rethreads_onto_an_edited_parents_current_tip`.

### `layout.rs` — the performance core

- A `Layout` height cache (interior-mutable, `Clone`) holds each post's measured height keyed by node id for the current width; only posts intersecting the viewport (± `VIRT_MARGIN`) render the real `MarkdownEditor` (with a measuring `canvas` refreshing the cache) — off-screen posts render as sized placeholders (`estimate_post_height`). Per-frame shaping is bounded to visible posts while document total/scroll-range/minimap stay correct.
- **The cache is keyed on the reading-column width (`body_width`), not the raw window width** — side gutters remain while they leave the column at `BODY_MAX_WIDTH`; below that threshold metadata stacks above and actions below, preserving the full measure until the page itself narrows. A settled actionable post always reserves its compact action line, even while the hover-gated verbs are hidden or another turn is streaming; the streaming, synthetic and draft rows themselves reserve none. Resizing without changing that effective width doesn't invalidate anything (keying on raw width cleared the cache on every resize and jittered the page + minimap as estimates re-measured). Regressions: `space_resize_above_column_cap_does_not_churn_height_cache`, `compact_actionable_post_keeps_its_height_when_actions_reveal`, `compact_settled_post_keeps_its_action_height_while_another_turn_streams`.
- **The warm pass**: lazy estimate→real measurement of an on-path post shifts the whole document below it (jumping the composer's dock threshold and minimap columns). When the selected path has an unmeasured post (`path_has_unmeasured`), `render` arms `warm_remaining` and forces every on-path post to render real for a couple of frames (prepaint fires for off-screen elements, so they measure without being shown). Self-terminating; inspects only on-path posts (off-branch siblings never render on the path and would keep it armed forever).
- **The document's top reserve is unconditional** (`doc_reserve` = `TITLE_BAR_RESERVE`), paired with two runway floors. A lone blank composer claims one window below the reserve, so the notebook has no phantom scroll. Once a branch has a post, its trailing runway claims **exactly one window** — the composer's minimum height is the window height, no more or less: the docked bar's top edge is its slot top (so the surface abuts the separator band above it exactly as a post row does, and docking engages the moment the slot reaches the float line), and at the document floor the slot and the painted surface both fill the window edge-to-edge, the previous separator band just cleared above, rather than leaving the reserve's last separator visible. Composer-to-post continuity remains structural: a docked composer's editor starts `POST_PAD_Y` below its slot top, exactly where a post's body sits. Regressions: `space_blank_composer_does_not_scroll`, `a_populated_composer_has_full_window_docking_runway`, `space_composer_text_sits_where_its_post_will_land`, `space_reply_draft_text_sits_where_its_post_will_land`.
- Also holds the selection/height computations reading the scroll handles (`active_child_index`, `selected_levels`, `selected_subtree_height`, `placeholder_doc_top`).

### `keyboard.rs` — the two-level keyboard model

Arrow navigation, the Enter/Escape levels, type-to-compose — contract + Escape chain in [Accessibility & QA probes](#accessibility--qa-probes). **Tree focus is forwarded through item identity** on every rebuild (`retarget_tree_focus`, beside `rethread_drafts`): `TreeFocus::node_id` is an action id, which an edit/regeneration supersedes, and a stale one is silently inert (every arrow no-ops until the reader escapes the conversation) — so the vanished id resolves through the outgoing snapshot to its item and forwards to that item's tip, preserving the level; focus clears only when the item genuinely left. Regressions: `space_tree_focus_follows_an_edited_post_to_its_new_generation`, `space_tree_focus_follows_a_regenerated_post_and_clears_when_it_vanishes`.

### `nav.rs` — snap physics and gesture bookkeeping

`SnapAnim`, `ease_out_cubic`, `snap_target_index`, `snap_duration`, the `ScrollAxis`/`ScrollOwner` locks, `resolve_scroll_axis`, `start_snap`/`drive_snap`, `reassert_horizontal`, `remap_for_resize`, `select_path_to` — plus **`PageGlide`**, the vertical twin.

**Navigation scrolls glide; gestures don't** (task 46, bug 4). Being taken somewhere in the same space — a footnote row, a highlight's referencer, `select_item_tip`, "See in context" — eases the page there over `snap_duration` (`glide_page_to` → `drive_page_glide`, an `on_next_frame` loop over wall-clock progress; `apply_page_glide(t)` is the frame body, split out because no test dispatcher pumps `on_next_frame`). Everything the reader drives (the wheel, a minimap press or drag) is already their own motion and stays instant — and **cancels any glide in flight** (`cancel_page_glide`, called from `note_scroll_activity` and `minimap_press`). Keyboard tree navigation (`keyboard::scroll_into_view`) and the tail scrolls (`scroll_to_tail`, `settle_on_new_post`) stay instant too: the first repeats faster than a glide can land, the second is owned by tail-following.

**A glide owns `page_scroll` for its whole duration** — `apply_page_glide` writes each frame's position from the trajectory alone — so an offset written between two glide frames is silently overwritten on the next one. **Every programmatic instant page scroll therefore goes through `nav::set_page_scroll_y`**, the one door that retires the glide before writing; the glide's own frame body is the *only* other writer of that offset in `space_view`. Adding a `page_scroll.set_offset` call anywhere else re-opens the class (a keyboard move, a caret reveal, a settling post, each undone until the glide landed — regression `space_keyboard_navigation_takes_the_page_from_a_glide_in_flight`). Whoever writes last owns the page, and a glide can never take it back.

**A branch switch retires it too, though it writes no page offset at all**: the switch changes *which document* the page is scrolling through, so a vertical trajectory measured on the branch just left is meaningless — it dragged the reader down a `y` belonging to somewhere they had navigated away from. Each reader-driven switch cancels at its own entry, and the four are exhaustive: the wheel through `note_scroll_activity`, the minimap through `minimap_press`, a keyboard branch move through the instant-scroll door (its `reveal_focused_post` always writes), and a **branch-dot click** through `glide_to_branch` — the one that reached a switch without passing through any of the others (regression `space_branch_dot_takes_the_page_from_a_glide_in_flight`). A `select_path_to` driven by a *completion* rather than the reader (`PendingSettle::Stay`) deliberately cancels nothing: that is bookkeeping, and stranding a traveling reader is the same mistake tail-following makes below.

**Tail-following stands down while a glide is in flight** — the two are the only motions spanning frames, and a reader parked at the end who asked to be taken somewhere is on their way; the follower would otherwise take the page back through that same seam on the first frame after the navigation. The reverse needs nothing: once the glide moves the reader off the end, `at_tail` reads false and following disengages on its own. Regression: `space_streaming_tail_yields_to_a_navigation_glide`.

**Reduce-motion:** both navigation glides return `cx.reduce_motion()` straight to the destination. That is gpui's own app-level flag (it also stills every `Animation` element, including the minimap fade) — **nothing feeds it from the platform at this pin**: no gpui backend reads `NSWorkspace.accessibilityDisplayShouldReduceMotion` or the GNOME `gtk-enable-animations` setting, so it is `false` until something calls `App::set_reduce_motion`. Honoring it is our half; wiring the OS signal is upstream's. *Removal trigger for this note: gpui setting the flag from the platform.* Tests: `space_navigation_glides_to_its_destination_instead_of_jumping`, `space_navigation_lands_at_once_under_reduce_motion`, `page_glide_eases_between_its_endpoints`. Take-over-at-finger-lift (macOS exposes no momentum-end signal). **Horizontal branch scrolling locks its owning strip for the whole gesture** (`h_scroll_owner`): sibling branches differ in height, so as pages slide the cursor can drift over a *nested* strip on the incoming branch and gpui dispatches the wheel to that innermost strip — without the lock it would steal the gesture. A non-owner strip undoes the built-in scroller's step on itself and forwards the delta to the owner; finger-lift snaps the owner (sized by its own branch count from the per-frame `scroller_counts` map). Reset on `TouchPhase::Started`.

### `post.rs` — one post + the separator band

- The byline gutter is the shared `byline_gutter` helper used by posts, inline drafts, and the Sides-scheme composer, so gutter geometry can't drift (activating a draft must not shift its byline). **The compact composer's byline is docked-only**: the floating bar carries no attribution — a dead-space inset plus an absolutely-positioned "You" fade in over `layout::dock_reveal_progress` as the bar docks, landing the byline at a post's metadata position (`POST_PAD_Y` under the slot top, a metadata-gap above the first text line) so the docked stack is pixel-for-pixel a post's, and continuous with the inactive draft row. Regression: `compact_composer_gutters_hold_post_parity_and_the_bottom_bar` (`tests/probe.rs`). Posts render through a **`disabled` `MarkdownEditor`** styled with the same `prose_style` as the composer — pixel-identical to what the user typed. `render_post_or_placeholder` is the virtualization decision.
- **Per-post affordances** (the action gutter's tenants): hover reveals quiet verbs — **Edit** on your own posts, **Regenerate** on the assistant's (`Space::regenerate_post` with the post's **own recorded model**); hidden while streaming (the entity refuses mutations mid-stream, so dead verbs would lie) and only on rows with a real `action_id`. Hover uses the Library's out-of-order-leave guard.
- **Compact affordance focus reveals the action line, not the whole post.** Tree-level navigation keeps the established rule that an oversized post aligns its beginning for reading; Enter and horizontal affordance cycling minimally scroll the compact action line into the usable viewport. Wide rows keep their existing page position. Regression: `entering_compact_affordances_reveals_an_oversized_posts_action`.
- **Edit is in place**: `begin_edit` enables the post's own body editor (`sync_bodies` deliberately skips the editing node, so a bus reload mid-edit can't clobber typing — `space_edit_buffer_survives_transcript_sync`), stashes the original, retires any active draft, and routes ⌘↩ to `commit_edit` → `Space::edit` (a new human generation). Esc restores the stash; the gutter shows Save/Cancel during the session.
- **Finalized reasoning keeps its disclosure** — a post carrying re-attached reasoning renders the same "Thinking…" toggle as the streaming leaf.

### `composer.rs` — the draft model

A `Draft` (`SpaceView::drafts`) is a **window-local UI node** with its own editor, attached to the persisted tree as a leaf of the post it replies to (`None` parent = a blank-space root). Because `drafts` is view state, "drafts live in the UI, not the data" and "empty drafts never persist" fall out for free. Two kinds:

- **Tail draft** — the always-present docked composer at the end of every branch (the leaf's reply affordance; a leaf's band never offers *Reply*). `sync_tail_drafts` (each frame, idempotent; skipped while streaming and until the transcript loads) ensures one per leaf and prunes empty, inactive, non-leaf drafts. An empty tail draft persists (docked); Escape only deactivates it.
- **Fork draft** — the band menu's **Reply** (offered only on a post with a committed reply) starts a new branch via `create_draft`; the fresh draft selects its branch (`pending_select`), then `dock_active_draft` scrolls it home. An empty fork draft is deleted on retire.
- **Dots tint with activity** — `subtree_has_draft_content` tints a branch dot `info` once its draft is non-empty; streaming dots are `info` too.

Composer machinery (shared by empty/active):

- `create_draft_node` mints the editor (focus→activate, Enter→submit). An inactive draft reserves `max(its own measured height, runway_floor)`; it never borrows the active composer's natural height, especially when that composer floats over a sibling branch. One draft is active; focusing another or **Escape** retires the current one; clicking an inactive draft re-activates it.
- **Accept-before-consume:** ⌘↩/⌘⇧↩ (Post / Post quietly) consume the active draft into a post **only once the space accepts the submit** (`send_active_draft` consumes on a `true` return; a rejected submit — streaming, or an in-flight save — leaves the draft intact: `space_post_during_save_window_preserves_draft`). An accepted post runs `settle_on_new_post`: **rebuild** the snapshot (the optimistic turn's `MessagesChanged` lands after this handler, so `self.posts` is otherwise a post short), **select** the branch the post joined, **scroll** to that branch's end, and **arm the tail pin** (see Tail-following; `space_post_parks_the_reader_at_the_tail_and_holds_it_there`).
- **The recovery notice** (`SpaceView::render_error_band`): a typed failure surfaces an on-theme, dismissible danger card bottom-anchored to the failed exchange — error text with **Copy** (gpui text isn't selectable here), **×** dismiss (`dismiss_error` — clears notice **and** `failed_turn`, so a later sibling success can't resurrect an orphaned notice), and **Retry** (`retry_failed` → `Space::retry`, shown only when `can_retry()`). The notice is owned by the `failed_turn` record, not the view-local error string. Probes `space/error/{dismiss,copy,retry}`.
- **Notes-editor click target:** a docked composer / inactive draft is mostly blank runway; a click below the text lands the caret at the end. Owned by the **editor** (the host passes `MarkdownEditor::min_height(..)` so the editor fills the runway and resolves a click below its last line to document end) — one listener, no ancestor click handler. (An ancestor-`on_click` approach reset the caret even on text clicks — the editor doesn't stop the click gesture on ancestors.)
- **Bar height accounting:** the active composer sizes the editor to `body_h − rail`; the bar's height is a **straight sum of rendered elements**: `content` (the editor's `content_height()`, decoupled from the `min_height` floor so no feedback loop) plus the rail's measured occupancy (the `flow_mark` pair — see `references.rs`; the rail's own padding is `rail_pad`) plus the trailing `bottom_breath()` spacer — the mirror of the editor's top `scroll_gap`, a real in-scroll child so a scrolled draft's last line stops a breath above the fold (under a rail, `rail_pad + breath` totals a post's full bottom pad — the breath is drawn exactly once). Compact occupancy is synchronized once per frame and splits by state: the docked byline row (`top`) joins only the docked natural height and the runway — the floating bar carries no byline (`composer_floating_natural_height`) — while the bottom action bar (`bottom`) joins both. All recorded by the `record_height` canvas in its paint phase; every term is read off real rendering. Regressions: `space_composer_counts_the_bottom_breath_once`, `compact_floating_composer_uses_complete_natural_height`.
- **Top chrome renders split at the scroll clip** (`composer_chrome()` = the full `POST_PAD_Y` — bar top edge sits at the slot top, so the whole inter-post pad is bar chrome — remains the *total* in all height computations; the split is render-only): a thin `COMPOSER_SEPARATOR_H` separator sits outside the scroll clip (the bar's only dead space when internally scrolled, where the fold shadow paints), and the remaining `composer_scroll_gap()` rides *inside* the scroll content as an in-flow spacer (a spacer child, **not** container padding — gpui adds padding to the scrollable extent, which would mint a phantom scroll on a fit-height composer). Invariant `separator + gap == composer_chrome()` pinned by `top_chrome_split_preserves_the_text_position`.
- **The inactive draft placeholder** fills the editor to `runway_floor − 2·POST_PAD_Y`; its row keeps a thin `on_click` only for clicks on the byline gutter that miss the editor — the editor itself activates via its `Focus` event and owns caret placement.
- **Composer scroll — always-on tracking, gated ownership:** `overflow_y_scroll` + `track_scroll` stay on unconditionally; what's gated (on `composer_scrollable = overlayed && chrome + content > bar_h`) is *ownership* — the composer owns the wheel (`ScrollOwner::Composer`, `stop_propagation`) just when floating with real overflow; otherwise `ScrollOwner::Body`, so a fit-height floating composer scrolls the page toward its dock. Tracking staying on prevents a phantom scroll (a fit-height composer has `scroll_max == 0`; the measuring canvas is pinned to the origin so it adds nothing to `content_size`).
- **The dock transition** is smoothed by the **pre-dock glide** (`glide_composer_toward_dock`, run once per `render` after the frame's page offset is final): while the dock threshold sits under the floating bar (within the last `float_bar_h` of page travel before docking), each increment of page scroll consumed toward the threshold scales the internal offset by the ratio of dock runway remaining (pure, unit-tested `dock_runway` / `approach_glide_offset`), so the content sits at exactly its top the moment the composer docks. The multiplicative form is path-independent over any stop/restart descent; a retreat leaves the offset alone yet a resumed descent still lands at zero; landing on/past the threshold multiplies by zero (exact, no drift). Running at render time makes every page-scroll source participate (wheel, minimap drag, tail-follow, programmatic docks); `composer_dock_runway` carries the previous frame's runway and resets when no active on-path draft renders. Behind it, the **dock ramp** stays as geometry plus backstop: as the docked bar rises, `bar_h` grows toward the full content height (pure `composer_bar_h` ramp), so `scroll_max` reaches 0 and gpui clamps out residual offset the glide couldn't see (mid-zone resize, reflow). Regression: `space_scrolled_floating_composer_glides_to_its_top_by_the_dock`.
- **The float height is per-window, draggable state** — `composer_fraction` (ratio of window height, default `COMPOSER_MAX_FRACTION` = 50%; deliberately never persisted) applied per `ComposerSizing`: **Max** (bar grows with content up to the fraction — the resting behavior) or **Exact** (bar pinned to the fraction while floating). While floating, the separator doubles as a **resize handle** (centered dot, vertical-resize cursor, probe `space/composer/resize`, absent when docked): the grab switches to Exact snapshotting the current ratio (nothing jumps), motion applies as a clamped delta, the drag tracks window-globally, and the pre-dock glide suspends its runway tracking for the drag (the float line itself is moving). Deactivation or selecting a different draft reverts sizing to Max; the fraction survives as the window's cap. Everything reads the bar through one helper (`layout::composer_float_bar_h` / pure `composer::float_bar_height`). Tests: `float_bar_height_caps_under_max_and_pins_under_exact`, `space_composer_resize_drag_pins_exact_height_and_reverts_on_deactivate`, `space_composer_resize_reverts_to_max_when_the_draft_posts`.
- **`bar_h` is virtual geometry, not the painted quad** — what makes the ramp reach `full_h`. Window clipping belongs to the *quad* (`quad_h = (bar_h + content_shift).min(win − bar_top)`); clamping `bar_h` itself pinned the scroll viewport to the visible height so `scroll_max` never reached zero (regression: `dock_ramp_reaches_the_full_content_height`).
- **Caret-into-view on edit:** the editor has no internal scroll (it lays out to full height; the host scrolls), so an edit or keyboard-nav move that puts the caret past the fold must scroll *something* — which handle depends on how the composer sits this frame. `Change` **and** `SelectionChanged` arm `composer_caret_scroll_pending`; a zero-visual `caret_into_view` canvas (a later sibling of the editor, so its paint sees this frame's state) reads `caret_content_y()` and writes a clamped offset via pure `caret_scroll_offset(..)`, then clears the flag (one-shot, so a manual scroll isn't yanked back). The canvas branches on the render's own docked/floating decision **passed into the canvas** (frame-consistent) — not the `composer_overlayed`/`composer_scrollable` cells, which derive from the frame-behind `composer_content_h` and read inconsistently across the transition.
  - **Floating with overflow**: scroll the composer's own `composer_scroll` (viewport = `body_h`). A fit-height floating bar is a no-op (the caret already shows).
  - **Docked**: the caret's window visibility is a **`page_scroll`** concern. The caret's document position is `placeholder_doc_top + POST_PAD_Y + compact_top_occupancy + caret_content_y` (all page-scroll-independent, so it converges in one shot). The compact top occupancy belongs here because stacked metadata precedes the editor; total compact occupancy remains a separate natural-height/runway input. **The `POST_PAD_Y` term is load-bearing**: the editor content starts `POST_PAD_Y` below the slot top (the docked `top_y` *is* the slot top, and the bar's top chrome — the whole pad — precedes the editor). The page `scroll_max` is computed from the editor's **fresh** `natural` height, not the frame-behind `scroll_min_y` (which would clamp the target back on the edit frame). Guarded by `space_docked_composer_edit_scrolls_page_into_view` (asserts the frame-independent slot-relative offset); floating case: `space_composer_edit_arms_caret_scroll_into_view`. **Deferred:** inline post edits (an editor living in `page_scroll` at the post's doc position) don't follow the caret yet — needs its own arming plus a fresh page-`scroll_max` reconstruction for a mid-document post.
- **The floating composer is its own stacking layer** (`layered(composer, reach)` — one `Window::paint_layer`). gpui assigns draw order from a `BoundsTree` over *registered* bounds, and a drop shadow's registered bounds grow by spread only — **the blur reach is not included** — so near the dock threshold an inline shadow lands in a disjoint order chain from the separator band and renders behind it, "jumping" in front once rects overlap. `paint_layer` gives every composer primitive one shared order computed from the layer bounds, which `layered` dilates upward (`reach = blur − offset_y + margin`) to cover the blur. **No `deferred` wrapper**: paint order already works (the composer is a later root child than the scroll subtree; the minimap is later still, so it stays on top), and staying in the normal pass keeps both below window-level overlays like the gpui inspector.

### The action gutter & the asks (in `composer.rs` / `post.rs`)

The page geometry is symmetric — `[byline gutter | reading column | action gutter]`, both `GUTTER_WIDTH` — the left gutter says who wrote a post, the right is where you act on it. The **active composer's** gutter carries one CTA: **Post** (pointer twin of ⌘↩); holding **⌥ reveals "Post quietly"** (⌘⇧↩) plus keyboard hints; while floating, **"See in context"** joins them (attribution says who wrote this; the action side is where you act on it). Affordances render only once actionable (non-empty draft or ⌥ held). **In the compact scheme the composer's verbs ride a bottom action bar** — their own surface on the separators' muted ground, anchored to the window's bottom edge (the quad's bottom is provably always the window bottom, floating and docked alike), the verb line vertically centered with Post at the right, See in context at the left while floating; its height rides `composer_gutters.bottom` so the editor's viewport ends above it, and when internal scroll clips content behind it an upward fold shadow marks the cut. **A docked, inactive tail draft keeps the bar** (`render_inactive_tail_action_bar`, a pane child beside the composer's): it fades in over the same `DOCK_REVEAL_SPAN` as the draft's slot scrolls into view — but mounts only once it would cover no more than its own slot (`slot_top ≤ win − bar_h`), so the strip is never a near-invisible interactive surface eating clicks and a phantom tab stop over the post above — and its verbs adopt the draft as active before acting, so Post meets the reader at the end of the branch without a click into the editor first. The nonempty inactive row reserves the bar's occupancy as an in-flow tail spacer (the inactive twin of `composer_gutters.bottom`), so a draft tall enough to fill its runway can still scroll its last lines clear of the bar. The bar carries no keyboard hints (they stay in the Sides gutter) and "See in context" shrinks and truncates first, so the verb groups fit the supported extremes (2.0 type scale in a 480px window); Exact float sizing clamps above the bar-plus-chrome fixed surfaces, and the clamp binds the **stored** fraction, the drag, the arrow steps, and the slider's reported range (`composer_min_fraction`, which also reserves one scaled prose line of editor viewport beyond the fixed surfaces — a writing surface's minimum shows writing, never chrome alone) — not just the rendered height — so stored and rendered agree at every reachable position and no slider value is visually inert (regression `compact_resize_floor_rises_with_the_bars_fixed_surfaces`); the render-side clamp remains only as the backstop for a fraction the window shrank out from under. On the muted ground the verbs hover to paper chips (the band's own idiom, inverted from the paper gutter's muted chips). **The composer carries no model chrome.**

**Explicit asks live on the separators** (`render_band`): a band's "+" opens the inline **Reply-or-Ask menu** (`band_menu`, one open at a time) — **Reply** (new branch; offered only on a post with a committed reply) and **Ask <agent>** per agent participant (`space_agents`, from `ParticipantsStore`). A tail band offers Ask only; a band with neither verb shows no "+". Ask routes through `ask_participant` → `Space::ask` — bypasses the cascade guard, **selects the branch the new turn's own streaming leaf lands on** (`Space::ask`/`retry` return the turn's `seq`; the leaf does not exist in the acting frame's tree, so the selection is deferred through `pending_select`, consumed in `render` after `sync_scrolls` has minted the strip's handle). Selecting the *target's* path alone left an ask on an already-answered post streaming on a branch the reader never saw (task 46, bug 3; regression `space_ask_selects_the_new_branch_the_reply_will_stream_in`). **Selection follows the turn through its completion** (`follow_completed_turn`, on `SpaceEvent::TurnEnded`) — the streaming leaf is an ephemeral render key, and the doctrine is that of `rethread_drafts` / `retarget_tree_focus`: a window-local reference forwards through *identity*, never through a position that outlived what it named. Two things can be aimed at the leaf when the turn lands, and both re-aim at the post it wrote:

- **A pending selection.** Nothing sequences a render between the ask and the turn's completion (gpui draws from the platform's frame callback; a turn lands in an ordinary foreground task), so a fast turn removes the leaf before any frame consumes the request. The settle stands (`BranchEnd` — the reader has not been taken anywhere yet), and *that* is the end of what was **written**: the frame consuming the request has already run `sync_tail_drafts`, so settling at the document end would scroll straight past the answer into the fresh composer's runway — bug 2's overshoot reached through bug 3's path. One definition serves both (`layout::page_end_ys`; see Tail-following). Regressions: `space_ask_selects_the_reply_when_the_turn_lands_before_the_next_render`, `space_ask_that_lands_pre_render_settles_at_the_end_of_the_answer`.
- **A reader parked on the leaf** (`selected_turn`, recorded each frame from `layout::selected_turn_seq` — the leaf is gone by the time the question is asked, so only the last frame can answer it). Branch selection is **positional** (a strip's scroll offset → child index) and a persisted response is inserted among the target's *posts*, ahead of any still-streaming sibling overlay: in a fan-out where the selected turn completes first, that index then addresses another participant's stream. Re-selecting by identity fixes the index and the page must **not** move (`PendingSettle::Stay`). Regression: `space_selected_turn_keeps_its_branch_when_it_lands_before_its_sibling`.

**The settle mode records the reader's situation, and a retarget never upgrades it** — `BranchEnd` because they asked to be taken to this answer, `Stay` because they are already somewhere they chose. Only the *node identity* forwards. Two turns landing in the same window make this concrete: the sibling's landing preserves the reader's own branch with `Stay`, and when their turn lands a moment later the request is re-aimed at the written post — still `Stay`, or a reader who had scrolled back up their branch is dragged to the tail of a reply they never asked for. Regression: `space_two_turns_landing_together_keep_a_scrolled_away_reader_still` (with `space_ask_that_lands_pre_render_settles_at_the_end_of_the_answer` holding the other side: a plain fast ask still lands at the content end).

**The parked case yields to a pending request for anything else** — the newest-intent rule: a pending selection is an ask (or a fork draft) the reader made *after* the turn now landing, so following the older turn onto its post would quietly undo it and leave them on the answer they had already read. Regression: `space_a_newer_ask_outranks_a_completing_turns_retarget`.

`selected_turn` is brought up to date the moment any branch navigation steers a strip, rather than waiting for the next render to observe the new path — otherwise a completion landing in that between-frame window reads the cached old leaf as still parked and undoes the newer navigation. **Every branch switch records where it is going**, because every one of them knows: `select_path_to` records the leaf it just selected, and `glide_to_branch` / `start_snap` record the *destination* child (`layout::turn_seq_under_child`) — which is not what the strip's offset says, since an animating switch rounds to the child being **left** for the first half of its slide. So `render` leaves the record alone while `snap` is in flight (what is *painted* still follows the frame's observation); the destination stands until it lands. The only entry that clears is a horizontal drag in progress, where there genuinely is no destination until the finger lifts — and the lift records one. Regressions: `space_dot_chosen_branch_survives_its_turn_landing_at_once` (the arm that lands immediately, which renders nothing in between) and `space_dot_chosen_branch_survives_a_sibling_landing_mid_switch` (the animating arm, where a completion used to re-select the branch being left and cancel the switch). Recording is not enough on its own: the reader who navigated onto *another* turn's stream still has to be carried across the insertion when some third turn lands, and a cleared cache cannot say where they were — so `follow_completed_turn`'s third case holds a **bystander's** branch by naming the leaf they are on (`PendingSettle::Stay`). Regression: `space_newer_branch_navigation_outranks_the_cached_turn_when_it_lands`.

A decline wrote no post: the pending request is dropped rather than left naming a node that can never appear, and a parked reader is left alone. The request lives exactly one frame either way: `render`'s `take` is unconditional, so a node that never appears (a failed turn, a retired draft) leaves nothing dangling.

The ask also applies the **tail-draft rule**: an *empty* draft replying to the target is discarded (the response becomes the tail); a draft *with content* is kept as its own sibling branch and stays active. Dismissal: click-out, Esc (the composer's key handler closes the menu before deactivating the draft), a choice, or retiring/sending the draft.

**The cascade notice** (`render_cascade_band`, window-local): on `CascadePaused`, a quiet dismissible bottom card — muted, not danger — names the limit and offers one "Ask <agent>" chip per agent (the failure notice takes precedence). Probes: `space/composer/post`, `space/composer/post-quiet`, `space/band/menu[/reply,/ask/{i}]`, `space/cascade/{dismiss,ask/{i}}`. Per-request config (temperature etc.) is deferred until app-core plumbs it; it belongs on the participant or a future per-ask affordance.

### `context_menu.rs` — right-click over any editor (task 28)

The pointer route to verbs that already exist on the keyboard and in the Edit menu. A read-only post body offers *Select All*, plus *Copy* with a selection and *Quote* / *Quote in Reply* while the selection is quotable; an editable editor offers *Cut* / *Copy* (with a selection) / *Paste* (only while the clipboard holds text) / *Select All*. **Nothing is greyed** — an affordance appears when actionable (gpui exposes no `aria_disabled` at this pin, so a dimmed row would read to AT as live). **No parallel paths:** clipboard verbs *run* the editor's own `MarkdownEditorState::perform` and are *offered* on its `can_perform` twin (asked once at open), so a row can never advertise a command the editor declines; quote verbs call the same `SpaceView::quote`/`quote_in_reply` handlers the Edit menu dispatches. The gesture comes from the editor's `on_context_menu` prop, which places the caret first (a press outside the selection collapses to it — what makes Paste land where you pointed); **opening is deferred by a turn** because the editor invokes the callback from inside its own `update` (resolving the selection inline would re-enter the entity), and the deferral also lets the menu re-resolve the quotable selection synchronously. Rendered as the root's last child so it sits above minimap and composer.

- **Dismissal is the band-menu pattern with one owner for Escape.** Key dispatch bubbles inner→outer, so the view root's handler runs last — the root is the only place that closes the menu, and every inner Escape handler *yields* via `context_menu_absorbs_escape` (the composer, before deactivating; a post row, before cancelling an edit session). An inner handler that forgets to close is harmless; one that forgets to yield acts on the same press that dismissed the menu (on the edit-session row, that silently threw away an unsaved edit). Pinned by `space_edit_session_escape_dismisses_the_menu_before_cancelling`.
- Probes `space/context-menu` (Menu) + `space/context-menu/{cut,copy,paste,quote,quote-in-reply,select-all}` (MenuItem). Tests: `space_post_context_menu_*`, `space_composer_context_menu_*`, `space_context_menu_probes_its_rows`.

### `references.rs` — quoted references

The space view's half of the ordinal seam (`action_antecedent.ordinal` ↔ `{{ embed N }}` ↔ the editor's embed map ↔ the footnote index — see `crates/eidola-app-core/AGENTS.md`). Three surfaces over two editor plugins:

- **Quote creation.** Each post body editor is subscribed for `SelectionChanged`; a live selection resolves to a `PostSelection` (concrete generation, content block, **block-relative** byte range, passage) via pure `block_range_for` over `PostData.blocks` — a selection crossing block boundaries names no single block and **is not quotable**. `Edit > Quote` attaches it to the active draft (next ordinal, `PendingReference`, `set_embeds`, `insert_embed_marker` at the caret); `Edit > Quote in Reply` does the same into a draft replying to the quoted post (reusing its empty tail draft). Both actions are registered **only while a quotable selection exists** (a `.when(..)` around the `on_action`s), so macOS greys the menu items; `note_body_selection` re-renders only on transitions that flip it.
- **Drafts carry pending references.** `Draft.references` is window-local, ordinals `1..` in add order, **never renumbered on removal** (survivors' markers already address them; a gap is correct). Removing one drops the row *and* its marker via `remove_embed_marker`. The gap reconciles exactly once, at the durability boundary: `compact_draft_references` (pure, unit-tested) renumbers onto `1..=N` and rewrites recognized markers, because `post_with_references` assigns ordinals in supplied order. Computed, never written back — accept-before-consume extends to quotes.
- **The footnote rail** (`render_post_footnotes` / `render_draft_footnotes`) renders **outside the markdown** — the editor never learns what a reference is. A hairline rule over single-line rows: index, quoted post's byline, passage. **A row names the quoted author from the first source that has one** (`reference_byline`, task 68): the quoted post's own **gutter byline** when this window holds the post, then the edge's carried author **identity** — the pair `(antecedent_author_kind, antecedent_author_label)`, the *source* space's effective naming of that participant, joined on the antecedent's space — read through `space::byline_for_participant`, and only then `ELSEWHERE` ("another space"). The order is not arbitrary either way. The rail used to search `self.posts` alone, so a **cross-space** quote — the case a reference exists for — showed its real byline while composing (the picker had the post in hand) and lost it the moment the post persisted. And the in-space byline wins over the carried identity because the two are the same effective participant label only *before* the view transforms it: an assistant row resolves again through `model_display`, so preferring the label would print a model ref on a rail row two inches under a gutter naming the agent — two names for one person inside one window.

  **The carried half is an identity, not a rendering, and it is read by the same rule the gutter uses.** `space::byline_for_participant` is that rule and the *only* place the pair is read: it answers "You" for the one human, "Eidola" for an unnamed agent, "System" for the harness, and `None` for an identity that names nobody (each caller owns its own word for that — the gutter's dash, the rail's `ELSEWHERE`). A label alone is not renderable, because a space **overriding a label to empty** is a real state (the schema's non-NULL "override to empty") and what to say instead depends entirely on the kind. Carrying only the label meant a cross-space quote of an unnamed author still changed attribution at the durability boundary — composing said "You", persisting said "another space" — the very defect one layer down (Codex review, PR #292), which is why `PostReference` now carries the kind beside the label (app-core's `get_space_tree_data` join; regression `a_cross_space_quote_carries_its_authors_kind_beside_its_label`). Deriving the byline rather than persisting the draft's rendered string is what makes the two agree by construction: **"You" is viewer-relative, and today the relation is total** — `HUMAN_PARTICIPANT_ID` is one globally-seeded row referenced into every space, so every human-authored passage anywhere on this machine is the reader's own. If a second human ever exists, that rule is wrong in the *gutter* first, and the rail inherits the fix because both read one function.

  **And the rule governs every surface that *names a participant row*, not only the ones that attribute a post.** `space::display_name_for_participant` is `byline_for_participant` with one fallback (a roster row always has a row to name, so an identity the rule declines to name falls back to its own label). It is what the Participants inspector's rows, its verb labels, its share confirmation and its error lines read, plus the Space Templates pane's referenced-participant rows and the template row's participant summary. It exists because the label is the **wire** representation: task 64 renamed the seeded human's stored label from `You` to `User` so a model is never told the other participant is "you", and every surface printing `p.label` directly would have shown that rename to the reader, contradicting that task's contract that display is unchanged (Codex review, PR #294). **Not for an editor's field** — a Name input edits the stored label and its value is written back, so seeding it from the presentation rule would rename the participant to its own display name on the next Save; the inspector's editor deliberately seeds raw. The stub fixtures carry the wire label (`User`), which is what gives the mapping teeth: `space_inspector_participants_probes_cover_rows_editor_and_add`, `templates_pane_router_probes_and_remote_cost_note`, `templates_editor_referenced_rows_follow_the_live_registry`, `a_template_row_names_its_routers_backend` (`tests/probe.rs`).

  **And the gutter's rendering is two passes, so the rail's is too.** An agent's resolved byline is handed on to `SpaceView::model_display` exactly as `rebuild` hands an assistant row's — the *same function*, not a second rule in the rail. A participant label that parses as a model selector renders as the model's display name in the gutter **and in the draft rail** (both read `PostData::byline`) while the carried label is the raw selector, so composing said "Gemma 4 E4B" and persisting said `gemma-4-E4B_q4_0-it@local`: the attribution changing at the durability boundary again, one layer further down (Codex review, PR #292). Nothing *mints* such a label — `db::default_agent_label` strips the `@backend` suffix and title-cases, and every other insert site takes a user-typed name — but a reader can type one, which is why the pass is applied rather than the state argued away. For an ordinary name the pass is identity, so it is keyed on the **kind** (an agent authors inferences — the rail's reading of the gutter's `role == "assistant"`) rather than guessed at per label. Regression: `space_footnote_rail_names_a_cross_space_author_the_way_the_gutter_would`.

  **The byline is bounded** (`BYLINE_MAX_W`, in `rems` so it follows the type scale): labels have no maximum length and the byline sits `flex_none` beside the `flex_1` passage, so a long one squeezed the quoted text out of the row it is there to attribute (Codex review, PR #292). Visual only — the row's accessible name is built from the whole byline and the whole passage before either is laid out, so an ellipsis is a fact about this row's width and never about who wrote the passage. Regressions: `space_footnote_rail_names_a_cross_space_author` (`tests/probe.rs`, asserting every arm of the rule on one post through the rows' accessible names) and `space_footnote_rail_speaks_a_long_byline_in_full`; the elision itself is visible in the `space_cross_space_quote` scene. `FootnoteBody` is a three-way state: `Quote` (resolves), `Unresolvable` ("quoted an earlier version" — a stale range is **never** remapped), `Backlink` ("referenced" — no range recorded). The active composer reserves rail room out of its own bar, and the reservation is **measured, not derived**: two zero-height in-flow probes (`flow_mark`) bracket the rail; their difference is its exact occupancy (a row-count formula drifted from styling and the rail was cut off). With no rail the marks coincide — no special case. The rail carries the bar's bottom breath as its own padding (`rail_breath`, a full `POST_PAD_Y`) — why `record_height` takes the max of rail and breath. **The rail is laid out against the bar's *visible* bottom** (`clipped_tail`): `bar_h` is virtual and the dock ramp carries the bar's bottom past the window edge; subtracting exactly what the quad clipped from the editor's runway floor lifts the rail onto the visible edge, degrading correctly when the text is taller than the runway (the floor doesn't bind; the rail follows the text below the fold). Regression: `space_docked_composer_keeps_its_footnote_rail_on_screen`. Clicking a row navigates to the quoted post. A draft's rows carry an **embed** affordance (re-inserts the marker; offered only while that ordinal has no recognized block) and a remove ×; a **post's** rows become removable chips inside the Edit session (`edit_post_with_removals` — drops from the new generation only). **A removed footnote takes its marker with it**: `commit_edit` runs the submitted string through `strip_removed_markers` (the editor's own recognition over just the removed ordinals, so a fenced or surviving marker is untouched) — left behind it would render as literal wire syntax and go upstream literally. The strip is pure over the submitted value, so Cancel still restores the stash and a rejected submit loses nothing. **Ordinal 0 (the reply edge) never renders and is refused here as well as core-side.** A rail row's role tracks whether it navigates (`footnote_row`'s `navigable`): `Link` only where a navigate handler attaches; `ListItem` on draft rows and mid-edit-session rows (not a tab stop, so no activatable-looking link with no listener).
- **Source highlights + navigate-back.** Passages other posts quoted paint through the editor's opaque highlight plugin: `highlight_ranges` maps each incoming reference back onto buffer offsets (a range that no longer maps is dropped, never approximated). A click routes through `on_highlight_click` — one referencer navigates directly; several open a small picker (band-menu pattern; row labels run through `strip_embed_blocks`). Navigation is `select_path_to` + scroll in this space. **A target absent from the current-tip tree is not assumed foreign**: references name a concrete generation, so `navigate_to_absent_action` resolves `bridge::action_location` → `(item, space)` and tries `select_item_tip` first (selecting the superseding tip in *this* window); only a genuinely cross-space reference opens that space's window. The stored range is never remapped onto the new generation. Highlight styling is `quoted_passage_wash` — warm amber at very low alpha, deliberately fainter than `theme.selection` in both palettes.
- **Where the data lives**: the incoming-reference index is per-space domain state on the shared `Space` (see The Space entity), loaded lazily per **rendered** post (`want_incoming_refs` fills a `RefCell` during render; `sync_references` drains it next frame — the defer-one-frame idiom `record_height` uses).
- **Quoting into another conversation** (task 37's creation UI, wave 3). The mechanism pinned at implementation is a **destination picker, not a cross-window drag**: `Edit ▸ Quote in Another Conversation…` (`QuoteElsewhere`, registered under the same quotable-selection condition as the other two, plus a context-menu row) opens a popover listing the Library's conversations — and choosing one **arms a confirmation carrying the visibility statement**, `references::visibility_statement` (pure, so the wording is asserted directly and no destination can be shown without it): *"This passage will be visible to everyone in <space>. Quoting copies it — later edits here won't change it there."* Two steps, because the sentence has to name the destination; a drag has nowhere to put it, and the reader is the flow-control point the whole permission model leans on. **The handoff is the `Space` entity, because a draft is window-local**: `Space::offer_quote` posts into an **addressed queue** the receiving window drains in `render` (`adopt_offered_quotes`, after `sync_tail_drafts` so they land in the real tail composer), after which each is an ordinary `PendingReference` — same ordinal, same footnote row, same accept-before-consume. **A queue, not a slot** (Codex review, PR #280): each entry is a confirmed act over a passage the reader chose, and quotes *compose*, so a second confirm before the destination redraws — ordinary when that window is minimised — must add a reference, not replace the first silently. The drain takes **all** of a window's entries in one frame, oldest first, so their ordinals are the order they were confirmed in; the transcript-loaded gate below governs the drain as a whole (either the frame can hold the batch or none of it leaves the queue). Three kinds are a window's to take: **addressed** to it, addressed to **no one** (the sender opened a window and could not name it yet), and **orphaned** — addressed to a window that has since closed, which has no better claimant than a live window on the same conversation and would otherwise strand a confirmed passage in an entity nobody drains; *which* live window takes an orphan is a deliberate race, since its addressee is gone. The raise-failure path re-addresses **every** entry waiting on the window it failed to raise (`readdress_offers_to_any_window`), because a failed raise says nothing about how many passages were waiting on it. Regressions: `space_two_quotes_offered_before_a_draw_both_land`, `space_a_quote_addressed_to_a_closed_window_still_lands`. **The window presented is the window holding the quote**, and both halves of that are structural (Codex review, PR #280): the sender **raises an existing window** on the destination (`crate::raise_space_window`, the newest of them) and opens one only when the conversation is closed — a targeted navigation, not the `⌘N`/Library open the window model's "no window dedup" residual covers — and the offer is **addressed to that window** (`PendingOffer::to`; `take_offered_quote(window)`), because a one-shot drained by *whichever view renders first* is a coin flip the moment two windows share the space: the raised window shows an empty composer while the passage sits in the one behind it. An **unaddressed** offer means the sender found no window and opened one (the view does not exist yet at offer time), so the next view to draw the space takes it; if the raise fails because that window has since gone, the sender re-addresses the offer to no one and opens instead. The entity is what knows this: `Space::attach_window` (from `SpaceView::new`) records the windows drawing it, and `open_windows` answers against `cx.windows()`, so a closed window self-heals out of the list. Registered on the **entity** rather than in a store map keyed by id because the entity is the one thing every window on this conversation already shares, so the answer lives with the thing the question is about and a collected entity takes its window list with it. Regression: `space_a_quote_into_an_open_conversation_lands_in_the_window_it_raises`. **And the take waits for a tail to land in**: a window opened *for* the quote draws its first frames before the transcript answers, where `sync_tail_drafts` deliberately mints nothing — so taking the offer there picked a parent from a tree with no posts in it and produced a **root** draft, attached to nothing on screen, submitting with no `reply_to` and persisting under whatever the tail turned out to be (Codex review, PR #280). `adopt_offered_quote` gates on `Space::transcript_visible` — literally the predicate `sync_tail_drafts` gates on, so the two cannot drift — and the mailbox, which already survives frames, is the waiting room; no second pending mechanism. **The predicate is has-a-value, not `Loaded`**: `messages()` reads through `Loadable::value`, so a *refresh* that failed over posts we still hold (`Failed { prior: Some(..) }`) is a tree on screen with a tail composer already hanging off it — asking only for `Loaded` left a quote sent to such a window waiting in the mailbox indefinitely (Codex review, PR #280). What waits is a load with **no** value behind it: `NotLoaded`, `Loading`, and a failed *initial* read. A failed initial read used to be a **dead end** the offer waited behind indefinitely — no composer, no transcript-level Retry, and `Space::load_transcript` re-running only on construction, a bus `Change::Space`, or a mutation's failure exit, none of which the reader could cause. That is now the reading column's own failure surface (below, "The transcript's own failure surface"), so the wait ends when the reader presses Retry; the mailbox needed no change, because an offer was never lost — only stalled. Deliberately **without** that gate's *streaming* half: a streaming space has a loaded tree, so `draft_for_quote`'s fallback picks the branch's last real post, and waiting would leave the reader looking at the window they were just shown with an empty composer. Rethreading cannot cure it after the fact — `rethread_drafts` forwards through the identity a parent named, and a root draft names nothing ("root because this space is empty" and "root because we had not read it yet" are one value); a draft minted against an unloaded tree is a guess, and drafts attach to what exists. Regression: `space_a_quote_into_an_unloaded_conversation_waits_for_its_tail`. Nothing durable happens until that draft is posted, where app-core validates the reference (a quote into a conversation you have left is refused *there*, zero-trace, rather than second-guessed here). The picker joins `transient_overlay_open` and the Escape chain, since it holds a passage on its way out of this conversation. **It takes the keyboard when it opens and hands it back when it closes** — the two halves of the focus contract every form in this app owes, and both were owed here because the picker's rows and verbs are real tab stops (Codex review, PR #280). *Mount*: `quote_elsewhere` focuses the picker, which covers both doors (the Edit-menu action and the context-menu row) because both dispatch through it — and the context-menu door is what made it a defect rather than an inconvenience, since `run_context_item` unmounts the focused menu row *before* dispatching, leaving a keyboard reader on a dead handle while the surface they asked for stood unfocused. *Unmount*: `close_quote_destination` (the one door Escape, the click-out and Cancel all go through) and the "Quote there" send both call `hand_back_quote_focus`, which asks **containment of the picker's subtree** before the drop — so a reader composing beside it keeps their caret — and restores `keyboard_home()`: the reader's own place in the conversation (their tree-focus level) if they have one, else the view root. That answer is deliberately the same one `sync_tree_focus`'s falling edge gives, so the explicit handback and the observation a frame later **agree**: restoring the level leaves that edge's `live` check true and the level intact, where a blanket root-focus would have cleared it as "the conversation lost focus". After a successful *Quote there* the passage has left for another window (which this raises), so what is owed here is only that this window's keyboard stays live — `keyboard_home()` again, never the quoted post (a post is focusable but deliberately not a tab stop, and moving focus there would fake a navigation the reader never made). Regression: `space_the_quote_picker_takes_the_keyboard_and_gives_it_back`. **It is bounded *and* virtualized** — the Library is unbounded, and an unbounded column in a popover clipped its own overflow, putting every conversation past the first handful out of reach; a capped height alone cured the reach and left the cost, building an element (hover style, click closure, probe) for every conversation the reader has ever had, on every frame the picker stood open (Codex review, PR #280, twice). Round 3's "a dropdown of conversations is a dropdown" was the wrong reference class: a model list is a menu, a Library is a **history**. Regressions: `space_the_quote_picker_roves_a_cursor_over_its_whole_index`, `space_the_quote_pickers_cursor_leaves_escape_alone`, and the materialization arc in `space_quote_destination_list_is_bounded`. **And it reads the index's states apart** — `list()` answers `&[]` for a failed read exactly as it does for a real empty Library ("Failed is not empty", again), so one sentence covered all three: a read in flight says "Loading…", a failed *initial* read says it failed and offers the quiet retry (the Library's "couldn't refresh" strip, not its centred panel — this is 320px of popover), a failed *refresh* keeps the rows and adds the same line, and only a `Loaded` empty says "No other conversations yet." Regressions: `space_quote_destination_list_is_bounded`, `space_quote_destination_reads_the_index_states_apart` (`tests/probe.rs`).

Regression: `space_dismissing_a_bottom_band_hands_the_keyboard_back`. **The sentence is ours, fixed** (`references::FOLLOW_DENIED_HERE`), not the error's `Display`: it may confirm the passage came from somewhere (existence is public *here*, which is where the reader is) and names no title, participant or content — and wording it locally means no future change to a typed error can widen what this surface says. Precedence: error band, then this, then the cascade notice. Probes `space/reference-notice{,/dismiss}`, `space/quote-destination{,/{i},/note,/confirm,/cancel,/empty(Label),/retry}`. Tests: `space_quoting_elsewhere_names_who_will_see_the_passage`, `space_a_quote_from_another_window_lands_in_this_ones_draft`, `space_a_denied_follow_says_so_without_naming_the_conversation` (`tests/behavior.rs`), `space_probes_record_the_quote_destination_and_denied_follow` (`tests/probe.rs`); driver scenes `space_quote_destination`, `space_quote_visibility`, `space_reference_denied`.

### `traces.rs` — trace visibility (task 34)

The quiet disclosure that lets a reader audit what a turn did without leaving the space. `AppCore::space_traces` is the parallel read putting back the actions the post tree collapses; each `PostTrace` is anchored to a post the tree already renders (keeping `PostNode` and virtualization untouched). **Two anchors:** a turn that answered anchors on its inference; a turn that produced no post (decline, cap, failure) anchors on the post it answered — the gap *is* the audit value. **One disclosure per turn, not per post** (several turns share an anchor): the view renders one line per `PostTrace`, keyed on its per-turn `id`, and `Space::toggle_trace`/`trace_expanded` key on it too. Collapsed: one `text_xs` line at the bottom of the reading column, below the footnote rail — "3 tool calls", or "Mara — declined to respond · 1 tool call" where the turn left no post to carry the byline. Expanded: a ruled rail in the footnote rail's language, one line per round (index, tool name, `arguments → result`, flattened/elided by pure `summarize`). **Disclosure, not duplication:** a round's line is a `Link` opening the Record on that round's own raw exchange (`request_id` rides the DTO); a `decision` has no exchange and is a plain `ListItem`. An unexecuted round reads "not run". Probes `space/post/{i}/trace/{t}` (a `probe_value` whose value is the summary line — settled, since the index refetches wholesale on `Change::Space`) and `.../round/{n}`. Cross-window: `crate::open_record_request` raises-or-opens the Record singleton and drives `RecordView::show_request` — reachable because `AppGlobal` holds the Record's `WeakEntity<RecordView>` beside its `WindowHandle`. Tests: `space_trace_disclosure_is_collapsed_until_asked`, `space_decline_renders_in_the_gap_under_the_post_it_answered`, `space_trace_row_deep_links_into_the_record`, `space_change_invalidates_the_trace_index`, probe tests, driver/visual scene `space_traces`.

### `inspector.rs` / `inspector_participants.rs` — the per-space settings panel (task 26.2 + 26.3)

The space window's right-hand **inspector**: per-space settings belong visually inside the space, so it is a **real split**, not an overlay. `inspector_layout(open, viewport_width)` (pure, unit-tested) is the whole decision — the content column compresses first, and only below `MIN_CONTENT_WIDTH` (480px, the narrowest space *window* we allow) does the panel float over the page behind a click-to-dismiss scrim (`Overlay::Popover` on the scrim, `Overlay::Scrolling` on the panel, both painted last). `INSPECTOR_WIDTH` is 320px.

- **One width accessor.** `SpaceView::page_size`/`page_width` = the window's content box less the split; **every** page-geometry consumer reads it (composer dock, minimap, branch strides, context-menu clamp, `scroll_into_view`) instead of `chrome::content_size`. The conversation lives in a `relative`, `overflow_hidden` pane, so its absolutely-positioned surfaces anchor to the pane and can never paint over the panel. A toggle is a width change, so the existing resize machinery (`remap_for_resize`, the height cache's `body_width` key) already handles the reflow.
- **The doors are the menu item and ⌥⌘I only** — no visual toggle in the space (Mike, 2026-08-01). `ToggleInspector` is registered per-`SpaceView` (the `CloseWindow` pattern), so macOS greys `Space ▸ Show/Hide Inspector` with no space window; the Linux primary menu carries the same row. gpui's **element** inspector (the dev overlay) gave up ⌥⌘I and is now `ToggleElementInspector` on ⌥⇧⌘I.
- **Open state is per window** (a view field): two windows on one space are two vantage points. It is not persisted — a window has no durable identity to persist against (see the deferral note below).
- **Closing hands the keyboard back** — `RecordView::close_detail`'s rule ("Focus comes back from a detail"), and `set_inspector_open` is the one door every opener and closer funnels through, so it is one place rather than a call per close site. The title field is a *view field* that survives the close, so without the handoff its handle stays the window's focus while its element is gone — a dead handle: keystrokes reach nothing, `focus_next` restarts from the top of the window, and type-to-compose is inert until a click revives it. **Restore only from a panel that is actually holding it** (`overlay_borrowed_focus`'s "a borrow is only returned by a lender who still has nothing"): a reader composing beside an open inspector never lent the keyboard and must keep their caret. ### `minimap.rs` — the topology minimap

Drawn from the selected path's cached heights + the live scroll offset (no per-frame canvas sweep), with the macOS-overlay show/linger/fade. A draft counts on its own branch; a floating off-branch draft pads other branches by its bar height (`layout::floating_pad`) so the indicator maps 1:1. Because the denominator is the same `total_h` as the real scroll range, the column is a linear 1:1 image of the document — which the scrollbar-like interaction relies on (pure mapping math in `doc_at_minimap_y` / `cell_fraction` / `scroll_for_press` / `handle_range` / `drag_grab` / `drag_scroll`, unit-tested). `minimap_press`: a press on a **different** branch switches to it and positions by direct manipulation (the pressed document point lands under the cursor), then completes — no drag (the page height changed); a press on the **selected** branch or the handle begins a **thumb drag** locked to that branch (grab at press offset — no jump; track press jumps the handle center to the cursor, then drags). The drag snapshots scale/floor at start and tracks the cursor window-globally via `Window::on_mouse_event` (re-registered each frame from a hitbox-free canvas that also records container bounds), so it survives leaving the 36px strip. Interactive only while the overlay is up. Accessibility: a `Group` "Conversation map" of per-node `Button`s labelled "*byline*: *snippet*", `aria_selected` on the active path. Probes `space/minimap` + `space/minimap/cell/{level}/{i}` double as driver click targets.

### Read-only rendering, selection, tail-following

- **Read-only `MarkdownEditor`:** a `disabled` editor renders as published markdown (`render_readonly`, no-cursor — a disabled editor's offset-0 cursor used to reveal leading delimiters). Still selectable (drag, double-click word, triple-click line) and copyable. **Re-seeding is keyed on the post, not the buffer**: `sync_bodies` re-seeds only when the post's content changed since the last seed (`body_seeds`) — comparing against the buffer turned any divergence into a per-frame `set_value` reset loop that killed pointer selection. Regression: `space_readonly_selection_sticks_on_noncanonical_post`.
- **Selection autoscroll for tall posts:** a post editor lays out full-height (the page owns scroll), so `autoscroll_selection` (each frame in `render`, after `scroll_min_y` is set) scrolls `page_scroll` toward the pressed viewport edge while a readonly post reports `is_selecting()`, re-extending the selection from the stationary pointer via `drag_extend_to` (pure `selection_autoscroll_delta`, unit-tested). Self-terminating. Drafts are excluded (they route caret-into-view separately).
- **Tail-following while a turn streams:** `follow_streaming_tail` (in `render`, immediately after `scroll_min_y` is set) keeps a reader parked at the end of the branch pinned to the growing tail, and leaves a reader who scrolled away alone. **"The end" is the end of the *written* content, not of the document**: a trailing draft's slot is a window of speculative runway (`layout::trailing_draft_slot_h`), so following stops short of it — as does **every** programmatic settle at a branch's end (`scroll_to_branch_end`), both reading the one definition, `layout::page_end_ys`, so no caller can invent a second — otherwise the frame the stream closes on, where `sync_tail_drafts` docks a fresh composer under the finished exchange, carries the reader straight past the reply they were watching (the trailing-runway overshoot). The two coincide on every frame a turn is actually streaming (no draft trails a streaming path). The value is cached per frame in `follow_anchor`, which is **also** what the at-the-end observation reads, so a followed correction can't read as "the reader scrolled away" on the next frame. **"At the end" is answered by observation, not a sticky flag**: following iff the current offset still sits at the *previous* frame's end (± `TAIL_FOLLOW_EPSILON`) — every scroll source participates for free, and there is no mode to get wedged in. Gated on **the selected path carrying a live stream** (`layout::selected_turn_seq`), not "is some turn streaming" — a document growing for any other reason (composer runway, first-time measurement, a sibling branch's fan-out stream) must not move the reader. **The one deliberate widening is a just-submitted post** (`tail_pin`): a submit is the reader's own branch producing, but the stream starts only after persist+plan, and across that gap the document still grows (the persisted post comes back re-keyed and re-measures) — the pin forces the tail only until the handle reaches the measured content end with no glide or unmeasured rows — **or until the reader takes the viewport first**: the glide-cancel seams (the wheel, a minimap press, keyboard navigation), the glide door itself, and selection autoscroll (a drag pulling the page is the reader's motion too) call `demote_tail_pin_for_reader`, so a reader who scrolls or navigates away mid-convergence is never snapped back (regression `a_reader_scroll_during_convergence_takes_the_viewport`). Demoted or converged, it then remains an observing lifetime marker through the save/stream gap without bypassing the ordinary at-tail observation, so a reader scroll or navigation immediately wins. Bounded both sides: retired the moment the space is neither producing nor busy — which is *after* the stream ends (the turn runner reloads the tree and re-plans the cascade with its stream entry already gone), which is why the content-end rule above, not the pin's lifetime, is what keeps the fresh tail draft from being chased — and by `activate_draft` (a reader composing owns the viewport). Tests: `space_streaming_tail_follows_when_parked_at_the_end`, `space_streaming_tail_does_not_yank_a_reader_who_scrolled_away`, `space_streaming_tail_ignores_a_sibling_branchs_stream`, `space_post_parks_the_reader_at_the_tail_and_holds_it_there`, `space_following_reader_stops_at_the_end_of_the_streamed_content`.

## Window model

**Space windows are non-singleton; the space *entity* they share is not.** `NewSpace` opens a fresh `SpaceView` (`space_id: None` → `SpacesStore::create()`, which mints the id and commits the row behind the window — instant ⌘N, addressed by a real space); the Library reopens via `open_space_window(cx, stores, space_id)` → `SpacesStore::open(id)`, which joins the registry — two windows over one shared `Space`. The composer draft stays per-window by design. No window dedup for the *opens* — `⌘N`, a Library row, a Record link (acceptable v1). **A targeted navigation is not one of those**: the cross-space quote handoff raises the window already on its destination (`raise_space_window`) rather than opening a second one, because it hands that window something the reader must then see (see `references.rs` → quoting into another conversation). `open_chat_window` calls `cx.activate(true)` after `cx.open_window` so a window opened from another app's context comes to the front.

**The writing surface's default size is derived, not chosen** (`lib.rs::writing_surface_size`, shared by space windows and the onboarding window). Width = `space_view::layout::full_measure_page_width()` + `chrome::opening_content_inset()` on each side (the Linux CSD shadow/border, which sits *outside* the content box `page_size` measures; zero on macOS) — the narrowest window whose full-width reading column still has side gutters. Nothing else narrows the page at open: the inspector starts closed and the minimap overlays the right gutter. Height stays 90% of the smaller display dimension capped at 840px, and the width yields to a display too narrow to show it. Change `BODY_MAX_WIDTH` or the gutters and the default window follows.

**Settings, Library, Updates, Record, About, and Onboarding are singletons.** `AppGlobal.*_window` (`Option<WindowHandle<Root>>`) caches handles; the open actions raise an existing window via `try_focus_existing_singleton`. Open paths are **synchronous** (`App::open_window`) so the cache is populated before the handler returns. Liveness is checked by matching the cached `WindowId` against `cx.windows()` (our root type is always `gpui_component::Root`, so Zed's downcast-by-type trick doesn't apply); a stale id self-heals on the next invocation. `OpenLibrary` also calls `SpacesStore::refresh` on every invocation; `CheckForUpdates` re-runs `UpdateStore::check_now` when raising an existing window.

## App lifecycle — the app outlives its windows, and ⌘Q retires it

`src/lifecycle.rs` (task 17, wave 2) + `src/status_item/` and `src/login_item.rs` (waves 3 / 3b). The process is longer-lived than any window (loaded local engines already belong to it). Wave 2's half is expressed at gpui's own seams — the spike found no upstream gap at our pin; the module docs carry the survey. Wave 3's half is AppKit, which gpui does not wrap at all and does not need to: a status menu is not a window, so it is built directly on `objc2` behind a macOS cfg (no gpui fork).

**Quit is two-tier on macOS (wave 3b, Mike 2026-08-03 — this revises wave 2's "Quit kills everything", which now describes the full-shutdown tier only).** Wave 3 flipped the Dock icon off on the *window count*; living with it showed that to be the wrong call — the reflexive ⌘N after closing the last window landed in whatever app was now frontmost. The shape is now LM Studio / 1Password:

| | What it does | Where it lives |
|---|---|---|
| **While open** | ordinary `Regular` app — Dock icon and menu bar with **zero** windows, so ⌘N still works. No window-count-driven flip anywhere. | — |
| **⌘Q / Eidola ▸ Quit** | **retire to the background**: close every window, go `Accessory`, keep the process, the status item, the stores, the bus bridge and the loaded engines | `actions::Quit` → `status_item::quit_or_retire` |
| **Status menu ▸ Quit Eidola** (also its own **⌘Q** key equivalent) | **full shutdown** — wave 2's `on_app_quit` teardown, engines drained, `cx.quit()` | `actions::QuitApp` |

- **The safety gate is one pure function**, `status_item::quit_intent(status_item_present, already_retired)`, and both inputs mean `FullShutdown`. *No status item* ⇒ there is no background layer to retire into, so ⌘Q keeps its old meaning rather than leaving an invisible, unquittable process (`macos::build` returns `None` unless what it made is a door the user can find, and only a `Some` installs the global — so the gate holds by construction, not by AppKit trivia). *Already retired* ⇒ the only way ⌘Q reaches an `Accessory` app is while its status menu is open, and encoding "quit" there means we never depend on AppKit's ordering between an open `NSStatusItem` menu and the app's unshown main menu: **both routes land on a full shutdown.**
- **The retire sweep is deferred, and that is load-bearing.** `App::dispatch_action` routes an action *through the active window*, so the Quit handler runs inside that window's `update_window`, which holds its registry slot — the window is still listed by `App::windows()` but `handle.update` on it fails. An undeferred sweep therefore skips exactly the window the user is looking at (measured against the live bundle: the app went `Accessory` with its window still on screen and no menu bar). `cx.defer` runs `lifecycle::close_all_windows` + the `Accessory` flip after the update unwinds, in that order. Regression: `retiring_from_a_windows_own_update_still_closes_that_window`.
- **⌘Q also abandons window opens that were already in flight** (`lifecycle::OpenIntent`). Several opens are started by a click but finished after an `await` — the launch-time onboarding branch waits on a backend read, "New Space from Template" on a durable write, a cross-space reference on an action lookup — and one landing after the retire opened its window and *un-retired* the app, which had just been told to go away. Each such site takes a ticket at the click (`lifecycle::intend_to_open`) and checks it at the open (`still_wanted`); the retire bumps the generation **synchronously**, before its own deferred sweep, so there is no gap in which a ticket still reads as wanted. **`cx.defer`d opens need no ticket** — gpui flushes effects FIFO and the sweep is deferred too, so a defer queued before it runs before it and its window is swept. **A missed site degrades to the old behaviour, never a broken one:** `window_will_open` still asserts `Regular`, so an unticketed stale open is an unwanted window, never a menu-bar-less one. That asymmetry is why the ticket is an opt-in at the async sites rather than a veto at the choke point — a veto would have to *refuse* opens, and a refusal at a door we forgot to sanction means "Open Eidola" doing nothing. Regressions: `a_window_open_set_in_motion_before_the_retire_is_abandoned`, `a_ticket_survives_everything_except_a_retire`.
- **Retiring never touches the quit path.** No `cx.quit()`, so `on_app_quit` never fires and the engines stay up — the entire point of task 17. The bus bridge and stores keep running with them, which is why the status menu's engine lines stay live while the app has no face.
- **`base_window_options` is the single door back.** `status_item::window_will_open` asserts `Regular` from the one choke point every `cx.open_window` passes through, which makes "open a window while `Accessory`" unrepresentable and covers every reopen path at once — the status menu's Open / New Space, Spotlight, `open -a`, `Application::on_reopen`. `Accessory → Regular` also calls `cx.activate(true)`: AppKit raises the menu bar for a newly-regular app only once it is frontmost. Measured: retired instance + `open -a` → same pid, `UIElement` → `Foreground`, Library window back.
- **Quit policy is one pure function**, `lifecycle::quit_mode(opts)`, handed to `Application::with_quit_mode`: **windowless** (either platform) never quits by itself; **macOS windowed** never quits by itself (the platform idiom `on_reopen` exists for); **Linux windowed** quits with the last window. Unit-tested.
- **Reactivation** (`lifecycle::reactivate`, wired to `Application::on_reopen` **and** to the status menu's Open Eidola via `lib.rs::reactivate_app` — one behaviour, so the two cannot drift): focus a window — the active one, else the front-most of `App::window_stack()` — and otherwise open **the Library**. `cx.activate(true)` runs either way. **"Most recent" is `window_stack()`, not `windows().last()`**: `App::windows()` enumerates a `SlotMap` that reuses closed windows' slots, so its last entry is whatever landed in the highest slot; `window_stack()` is the platform's real front-to-back order. `windows().last()` remains the fallback where the platform returns `None` (including the test platform, so behavior tests still walk a real path). On Linux gpui stores the reopen callback and nothing ever fires it — "a second launch asks the running instance for a window" is the wave-4 socket's job there.
- **The full shutdown is a full shutdown — engines, everything.** `install_engine_shutdown` registers an `on_app_quit` hook that calls **`AppCore::shutdown_engines`** — synchronous, infallible, reading the **live engine registry**, never a `local_models_state` snapshot (the snapshot is reconstructed by scanning the model directories, so an engine whose backing `.gguf` was renamed/deleted mid-session is absent from it while its subprocess runs). Signalling is not reaping, so the hook then yields on gpui's own executor to let the tokio threads run. **The hook's first act is to close the bus bridge** (`BusBridge::quiesce`) — any `Change` dispatched after `App::shutdown` sets `quitting` reaches a store's `refresh` → `cx.spawn` → "Can't spawn on main thread after on_app_quit", and gpui keeps driving the app-lifetime bridge task through the shutdown block; quiescing the single door every `Change` comes through covers every emitter, present and future (app-core keeps its own quiet-on-quit rules for the CLI consumer — neither layer relies on the other). Regression: `a_quiesced_bus_bridge_dispatches_nothing` (`tests/stores.rs`, driving the live tokio→gpui plumbing). The app-core side pairs this with its shutdown latch and silent supervisors (see `crates/eidola-app-core/AGENTS.md` → Local models). **The grace is unconditional, not gated on the drained count** (`unload_local_model` returns as soon as it has signalled, so an unload-then-quit finds an empty registry — a count-gated yield would skip precisely when a child is still dying). On macOS this hook is the *only* real shutdown: `cx.quit()` → `[NSApp terminate:]` → `exit()`, so the tokio runtime is never dropped and `kill_on_drop` (which covers Linux) never fires — without the hook a quit orphans every loaded `llama-server` to launchd. Best-effort by construction: `gpui::SHUTDOWN_TIMEOUT` is 200ms and a quit that outruns it still exits. A hard guarantee wants the OS (`PR_SET_PDEATHSIG` on Linux; macOS would need a synchronous reap) — a follow-up.
- **`--windowless`** (`LaunchOptions`, parsed in `main.rs`): no window at launch, no foreground activation, nothing that closes later stops the process; every other launch step still runs. Parsing is lenient about unknown flags (LaunchServices passes `-psn_0_…`; Xcode adds `-NSDocumentRevisionsDebugMode`); `--help` prints `lifecycle::USAGE`. On a display-less Linux box gpui's `guess_compositor()` resolves to its headless client, so the mode needs no platform plumbing. On macOS it starts **retired** (`Accessory`) — it opens no window, so there is nothing for a Dock icon to point at, and its ⌘Q is therefore the full shutdown a service-shaped process should answer.
- **Signals** (`install_signal_quit`, unix, windowless only): `SIGTERM`/`SIGINT` translate into an ordinary `cx.quit()` so `systemctl --user stop` runs the quit observers. Awaited on the core's tokio runtime, handed to gpui through the standard `oneshot` bridge.
- **The status item is the face, and the thing ⌘Q retires into** (`src/status_item/`, macOS). **The promise is kept by construction**: `macos::build` returns `None` unless `button` is `Some` and `isVisible` is true, and only a `Some` installs the global — so "a status item stands" can never be claimed for an item nobody can see. Neither check is theatre: `button` is nil only for a deprecated custom-`view` item (unreachable today, live the moment someone adds one), and `isVisible` is persisted under the autosave name, so it goes false the day `behavior` gains `RemovalAllowed`. **Accepted residual:** a menu bar with no room simply does not draw the item and AppKit reports nothing (`isVisible` stays true, measured). It is not permanent, and it strands nothing — Spotlight / `open -a Eidola` reach the running process, so the failure mode is "hard to see", not "unquittable". `status_item::install` is called from `run()` **after** the action handlers (the menu dispatches them) and **before** any window.
- **The status menu's rows are a pure projection, materialised at open.** `status_item::menu_rows` / `engine_lines` (unit-tested) map two inputs — the live engine registry and the `LocalModelsStore` snapshot — to Open Eidola / New Space / ─ / engine lines / ─ / Quit Eidola. Neither end captures authority: a gpui observer mirrors the rows on every store notify (never sampled once at install), and `menuNeedsUpdate:` — AppKit's "the user is about to see this" callback — is what builds real `NSMenuItem`s from the mirror, keeping a download's ~2.5 Hz progress stream out of AppKit entirely. **The mirror exists so `menuNeedsUpdate:` never re-enters gpui**: it runs while AppKit is opening the menu, and a `borrow_mut` of the app cell inside a callback whose nesting we do not control is a panic waiting to happen. A menu **command** does re-enter synchronously through an `AsyncApp` — the same thing gpui does from its own `handleGPUIMenuItem:`, and safe for the same reason (invoked from the run loop once the menu has closed). Every command routes onto a path that already exists: `Open` shares `lib.rs::reactivate_app` with `Application::on_reopen`, `New Space` dispatches ⌘N's action, and **Quit Eidola dispatches `QuitApp`** — deliberately *not* the app's ⌘Q, which now retires. Only Quit carries a `keyEquivalent` (`StatusCommand::key_equivalent`): an `NSStatusItem` menu is not part of the main menu, so that ⌘Q is reachable only while the status menu is open, which is exactly the moment the user means the background layer.
- **The registry is authoritative for engine membership in both directions; the listing only decorates.** `AppCore::running_engines` (added for this — see `crates/eidola-app-core/AGENTS.md` → Local models) is the in-process truth: synchronous, infallible. `local_models_state` is a **directory scan** that consults the registry only to decorate a `.gguf` it already found, *and* is preserved as `Failed { prior }` across a failed rescan — which produces two mirror-image lies, both of which the one rule kills:
  - **The listing misses a live engine** (backing `.gguf` renamed or deleted, backend row removed, directory gone unreadable), so the menu printed "No models running" over a subprocess holding gigabytes. Every registry entry now produces a line, named from the engine's own **slug** where the listing cannot name it (the registry has no display name — that lives in the `.meta.json` sidecar beside the file that may be gone) and marked `(file missing)`, because "why is this model not in Settings while my memory is gone?" is the question that moment raises. The claim is made **only when the listing actually answered** — a listing still loading is not evidence. **Nor is a row the scan never found**: `find_listed` is the *naming* join (any row may lend its display name — a re-download row carries the catalog's own, and a name is no claim about a file), while presence is asked of `LocalModelInfo::on_disk`, so re-downloading the vanished slug reads "Gemma 4 12B — running (file missing)" rather than quietly dropping the marker. Regression: `a_row_the_scan_never_found_does_not_cover_for_the_missing_file`.
  - **The listing claims a dead one**: an engine exits or is unloaded, the rescan fails, and the preserved `prior` keeps its `Loaded` row standing indefinitely. That row is **vetoed**, not printed — the registry already knows it is gone.

  Both are the same scan-versus-registry defect wave 2 fixed on the quit path, in a readout instead of a teardown. **The registry owns the warming phase too**, so leading with it loses nothing: `reserve_engine` inserts the entry with `ready: false` *before* spawning the subprocess, and `scan_engine_dir` derives the listing's `Loading` status from exactly that bit — the listing can never report a warming engine the registry does not already hold, and the registry's `ready` is the fresher copy of the same fact. Lines are ordered by the **display name**, the way app-core orders the listing, so the menu and Settings agree. The mirror observer re-reads the registry on every `LocalModelsStore` notify, which app-core emits for every engine transition, so the live half stays fresh even when the snapshot refresh failed. Regressions: `an_engine_whose_file_vanished_still_shows_as_running`, `a_stale_listing_cannot_claim_a_stopped_engine_is_running`, `a_warming_engine_survives_the_registry_leading`, `a_listing_that_has_not_answered_does_not_accuse_an_engine_of_losing_its_file`, `the_readout_is_ordered_by_the_name_the_reader_sees`.
- **`engine_lines` takes the whole `Loadable`, not its value.** `Loadable::value()` folds `Failed { prior: None }` into the same `None` as an in-flight first load, so a failed initial refresh left the menu reading "Checking on-device engines…" forever — a spinner for a request that had already failed and might never be retried (the store re-refreshes only on a bus `Change::LocalModels` / `Change::Backends`; opening Settings does not). Now a failure says "Couldn't list installed models" — quietly, and *always*, even beside a full engine list, because a failed scan is why those names may be bare slugs. **No Retry row, deliberately:** the failure costs display names and the installed listing, never the running truth (the registry answers regardless); it self-heals on the next engine or backend change; and Settings → Backends → Local is the surface with room for the error text and a retry. A fourth verb in a three-verb menu would buy less than the line it displaced. Regression: `a_failed_listing_says_so_instead_of_spinning_forever`.
- **Auto-start is opt-in and the system owns its state** (`src/login_item.rs`, Settings → General → Startup). macOS `SMAppService.mainAppService`; the Linux analogue is `eidola service install`, shipped in wave 2 and deliberately not duplicated. **Nothing is persisted app-side** — `SMAppService` already stores the registration and the user can revoke it in System Settings, so a copy in our config would be a second answer to one question; the row reads the system at construction and re-reads after every write, and a refusal quotes macOS's own words rather than inventing copy. `NotFound` maps to `Unsupported`, never to `Off`: "you turned it off" and "this cannot be turned on" (an unbundled `cargo run`, a pre-Ventura system) are different facts. **`SMAppService` is macOS 13+ and our binaries declare `minos 11.0`** (no `LSMinimumSystemVersion` in `Support/Info.plist`, no documented product floor), and objc2's class lookup *panics* on a missing class — so both entry points ask `AnyClass::get(c"SMAppService")` first; without it, opening Settings → General on Monterey would take the app down from inside a `Render`. Removal trigger is written at the guard: delete it once the shipped floor is ≥ 13 in both the plist and `minos`. `RequiresApproval` still reads as **on** — the switch showing off beside "approve it in System Settings" would tell the user to enable what is already enabled. **Open question — login launches the *windowed* app, not the background layer.** `mainAppService` launches the bundle exactly as a Dock click would and takes no arguments, so `--windowless` (the shape ⌘Q retires *into*) is unreachable through it, and nothing distinguishes a login launch at runtime: `NSApplicationLaunchIsDefaultLaunchKey` covers only file/print/Service/state-restoration, and an ordinary `open -a` already has `ppid` 1 and an `application.<bundle-id>.…` `XPC_SERVICE_NAME` (measured), because LaunchServices routes every GUI launch through launchd — any guess would misfire on normal launches. The documented cure is a **LaunchAgent** (`SMAppService.agentServiceWithPlistName:`, whose bundle plist takes the standard launchd keys including `ProgramArguments`), deliberately not taken here: it moves the toggle to System Settings' "Allow in the Background", must ship from both `package-gui-app.sh` and the Nix bundle, needs a real signature to register at all (ad-hoc dev builds report `Unsupported`, so it cannot be exercised locally), wants a migration for anyone already registered, and re-opens the TCC-identity question task 17 settled by keeping one app-bundle process. Until that decision is taken the **copy says what happens** ("Eidola opens with your session", not "ready in the menu bar"); the full options are in `login_item.rs`'s module docs.
- **Linux is unchanged, and deliberately** (coordinator's call, recorded in the task): no tray. A windowed launch quits with its last window / Ctrl+Q (a full shutdown — `quit_or_retire` is `cx.quit()` off macOS), and the long-lived layer is the systemd user service (`--windowless` + `eidola service`), which is discoverable (`systemctl --user status eidola`), survives logout via loginctl linger, and needs no third-party GNOME extension. The wave-4 socket later connects the two.
- **Not here:** a second GUI launch on Linux still hits `AppError::DatabaseInUse` with no friendly path (the wave-4 socket). `status_item`'s whole public surface is a no-op off macOS, with the pure model still compiled and unit-tested everywhere.
- **What only a human can verify:** `TestPlatform::quit` is a no-op and no test dispatcher delivers Dock events, so tests prove the window-registry half (`every_window_can_close_and_a_new_one_opens_cleanly`, `retiring_closes_every_window_and_leaves_the_app_standing`, `retiring_from_a_windows_own_update_still_closes_that_window`) and the pure decisions; **the whole AppKit half is a live-system surface no test platform reaches** — the menu-bar glyph, the Dock icon coming and going, the login item, and the status menu's ⌘Q key equivalent. `lsappinfo info -only ApplicationType $(pgrep -x Eidola)` is the cheap oracle for the policy (`Foreground` vs `UIElement`), and it doubles as proof the status item exists (`apply` refuses to run without the global that owns the `NSStatusItem`). The full checklist is `crates/eidola-gui/manual-verification.md` (committed — it is the release-verification procedure for these surfaces).

## Library — table of contents, not a sidebar

`library.rs` (520×620): one column, hairline rules between entries, each row a title (or first-message snippet, muted, for untitled spaces) with a right-aligned relative date. Data from `SpacesStore` (archived excluded).

**Virtualized** via `uniform_list` (see [Virtualized lists](#virtualized-lists)): fixed-height rows, a dumb-indexer closure, stored `UniformListScrollHandle`. The centering wrapper is `h_flex().flex_1().min_h_0().justify_center()` around a `relative` column capped at `max_w(rems(34))` holding the list + the right-edge scroll indicator; the list carries `.h_full().w_full()`.

**Honest states** (STATE.md's "Failed is not empty"): a failed *initial* read renders the shared `load_error_panel` + Retry (`library/retry`) — `list()` answers `&[]` for a failed read exactly as it does for a real empty Library, so the old fall-through rendered "Nothing here yet — ⌘N starts a new space": a read error stated as a fact about the reader's spaces, with ⌘N as the only way forward. A failed *refresh* over a listing we hold keeps the rows and adds a quiet "Couldn't refresh — retry" strip (same probe name — the two are mutually exclusive, as in the inspector). Tests: `library_failed_initial_load_offers_a_retry_not_an_empty_page`, `library_failed_refresh_keeps_its_rows_and_offers_a_retry`. **This gap predates the write-through work** — every `refresh` has always been able to land `Failed`; the unconditional re-list only made it reachable through a second path.

Interactions: click opens the space (`open_space` defers `open_space_window` via `cx.defer`); hover reveals **two ghost buttons in a fixed-width reveal slot** — rename (`IconName::CaseSensitive`, "Aa" — the bundled Lucide set has no pencil) and archive ×. `archive` removes the cached row immediately, then runs the real archive + re-list (a refusal comes back as the banner below, with the row). `archive` / `open_space` / `begin_rename` are public so behavior tests drive them directly.

- **One banner, for every refused space operation.** A create, rename, or archive the store could not complete surfaces in `SpacesStore::op_error` and renders here as a single dismissible `Alert` strip (`library/op-error`, dismiss `library/op-error/dismiss`) — the Library is the window over the whole index, and a strip per verb would only make the page shout. The store words the sentence (it knows which verb was refused) and tags it with the space it was about (`None` for a create), which is what lets the space inspector show only its own refusal. Refusals **stand per space** (see the stores section), so the banner shows the most recent and its × dismisses *that* one — a second standing refusal then takes the banner rather than being discarded with it. Test: `library_op_error_banner_is_an_alert_with_a_dismiss` (`tests/probe.rs`).
- **Pencil/× propagation.** Each affordance is wrapped in a slot div that stops propagation on **both mouse-down and mouse-up**, and the pencil defers `begin_rename` via `cx.defer_in`. gpui arms a click on mouse-**down** (each hovered ancestor records `pending_mouse_down`) and captures on the mouse-up capture phase — both before a child's bubble `on_click` runs — so `cx.stop_propagation()` in the child click alone left the row's own click armed: `begin_rename` reshaping the row between down and up could land the up on the bare row and open it on top of the rename. Blocking the down stops the row from ever arming; deferring keeps the gesture resolving against the pre-rename layout. Regression: `library_pencil_click_does_not_also_open_row` (real simulated click).
- **Hover-event ordering:** `set_row_hover(idx, hovering)` clears `hovered` on hover-false **only if `idx` is still the hovered row** — moving up the list, the left row's `false` can arrive after the entered row's `true`. Replay: `library_hover_survives_out_of_order_leave`.
- **Inline rename.** The pencil calls `begin_rename(space_id, title, …)` (a double-click trigger was unreachable — a single click opens the row first): creates an `InputState` seeded with the title, focuses it, subscribes — `PressEnter` → `commit_rename` (`SpacesStore::rename`: optimistic update + write + re-list, the refusal into the banner above); `Blur` → `cancel_rename`. Escape propagates through the input, blurs, and thus cancels. The reveal slot is hidden while renaming. The bus-driven `Change::SpaceIndex` reconciles all windows.
- **From the keyboard the listing is one tab stop with a roving cursor** (`list_focus` / `focused_row`) — ↑/↓/Home/End move, Enter opens, the cursor row reveals the same verbs, which Tab then reaches (see [Accessibility & QA probes](#accessibility--qa-probes)).

## Settings — calm two-pane, edit-in-place

`SettingsView` (620×520): a narrow nav band (`NAV_WIDTH` 132px) on `theme.sidebar`, the selected pane in the content column. Panes: **General · Backends · Templates · Agents · Account · Wallet** — Account and Wallet render **only while the eidola backend is enabled** (the account *is* its config); nav visibility doubles as state. Gating is **optimistic**: `BackendsStore::is_enabled("eidola")` returns `true` until the registry loads, so a cold open shows the panes rather than flashing them hidden. `effective_selected` and the `BackendsStore` observer both fall a now-hidden selection back to Backends — never a blank body or phantom highlight. `visible_panes(cx)` is the single source of truth. Settings keeps no raw-data dumps — summaries link to the Record.

- **Selecting a pane is an event, and one place answers it.** All six panes are built in `SettingsView::new`, at *window* creation — so a pane constructor runs once, for a reader who may never choose that pane, and never again for one who chooses it, leaves, and returns. `sync_active_pane` (called from `new`, `select`, and the registry observer — the two inputs to `effective_selected`, so the set is exhaustive) tracks the **shown** pane and runs that pane's `pane_activated` hook when it changes. Only `AccountView` has one today, and the criterion is narrow: a pane needs it exactly when its data is a live server read **no `Change` can invalidate**. Every other pane's store is refreshed by the bus and needs nothing. Regression: `settings_asks_the_account_pane_for_its_live_reads_on_every_visit` (`tests/behavior.rs`, real-core — a stub store's `refresh_*` is a no-op, so "did the pane ask?" is only observable against a backend).
- **Scroll-width invariant:** the content pane is a `v_flex().relative().flex_1().h_full().min_w_0()` wrapping `div().id("settings-body").w_full().flex_1().overflow_y_scroll().track_scroll(&self.body_scroll)` + the overlay indicator as sibling. Without `w_full` on the scroll div, taffy content-sizes the pane (long lines refuse to wrap).
- **General**: the Appearance chips, then one **Startup** row — "Open at login" (the opt-in macOS login item; see [App lifecycle](#app-lifecycle--the-app-outlives-its-windows-and-q-retires-it)), the only state in Settings that comes from the system rather than a store. Nothing about the Eidola connection lives here (it all moved to Backends → Eidola; the old ⌥-reveal/disclosure machinery is deleted — `src/disclosure.rs` is gone, and Settings has no `WindowInput` wiring).
- **Backends** (`src/backends_settings.rs`): a pane title above an internal **tab strip** — gpui-component's `TabBar` in its segmented variant (`BackendsTab { Eidola, Local, External }`, probes `settings/backends/tab/*`, role Tab; selection view-local). `Tab` implements `StatefulInteractiveElement + ParentElement`, so it carries `.probe(..)` directly; its element id is written through `Interactivity::element_id` because `InteractiveElement::id` returns `Stateful<Tab>`, which `TabBar::child` cannot take — and without an id gpui builds no AccessKit node for the role.
  - **Eidola tab**: enable/disable the singleton; when enabled, the **connection + trust surface** (from `ConfigStore`'s cached `EidolaTrust`). An always-visible **danger warning band** (role `Alert`, probe `settings/backends/eidola/trust-warning`) renders whenever any part of the bundle is overridden, naming which values; overridden rows' status lines read in the danger color. **One row per setting, each row both display and editor** — nothing hides behind a disclosure (the trust surface is always visible), and a verb swaps the input in place: the **base URL** (Change… → input + Save/Cancel; Revert-to-pin on an override; saving a value equal to the pin is a revert); the **trusted measurements** (one compact line per measurement — middle-truncated via `hex_summary`, never full hex inline; the full triple travels via each line's Copy verb and the a11y value; the Record link is the door to raw evidence; **Untrust only on user-override entries** — the build pin is never untrustable; when an override drops the build pin, a muted "pin — not trusted" line offers **Trust** to re-add it (the "trust official + my canary" flow); "Trust a measurement…" reveals the add-a-triple input in the CLI's `<snp>:<rtmr1>:<rtmr2>` format); and the two **hardware-CA rows** (on the pin: "Set custom certificate…" reveals an auto-grow paste-PEM textarea; on an override: Copy (full PEM) · Replace… · Clear). Parse failures land in the op-error banner and keep the input. The read-only domain separator closes the tab. Editors write through `ConfigStore` setters that emit `Change::Backends` (routed to refresh the `EidolaTrust` snapshot as well as the registry/model stores).
  - **Local tab**: enable/disable; an **engine status line** (bundled `llama-server` path when resolved, else the honest dev-build "no bundled engine" message naming `just engine` / the `llama_server_path` override); the managed store — installed models with per-state verbs (loaded rows afford Pin/Unpin + Unload), a thin progress bar during downloads, the curated catalog with installed markers, a paste-a-URL row.
    - **A row whose whole content is an error affords a way out, not two dead verbs.** A download that failed and left nothing on disk is still a row (the error is the point), and its status is `Available` — the same status a scanned idle file carries — so the verbs cannot be read off the status: gating on it alone offered **Load**, with no file to open, and **Delete**, with no file to remove, on the one row where the reader most needs somewhere to go. `failed_download_row` (pure, unit-tested — managed store, `!on_disk`, a `last_error`, `Available`) is the discriminator, and such a row affords **Retry** (re-runs the download the row remembers, via `source_url`) and **Dismiss** (`LocalModelsStore::dismiss_failure` → `AppCore::dismiss_local_model_failure` — the report acknowledged, no file touched). Retry is offered only where there *is* a URL to re-run; the way out is offered always. Its status line reads "not downloaded" rather than "downloaded", which is what the shared `Available` arm says and is the plainest lie the pane could tell here. The catalog's own Download verb is unaffected — it is joined on `on_disk` for the same reason (the second door is convenient, not redundant). Probes `settings/backends/local/installed/{i}/{retry,dismiss}`; regression `a_failed_download_row_affords_retry_and_dismiss` (`tests/probe.rs`), driver scene `settings_backends_local_failed_download`.
  - **External tab**: each external backend (openai: URL/key-state/pinned-models subtitle; llamacpp: scanned models with load/unload only — never download/delete — plus a resolved-engine line and an **auto-start toggle**, a `Switch` in a probed wrapper, role CheckBox), each with enable/disable + remove; plus the add-a-backend inline form ("OpenAI-compatible server" / "System llama.cpp"). app-core owns validation; refusals surface in op-error banners.
  - Ops route through `BackendsStore` / `LocalModelsStore` / `ConfigStore`; the work is core-owned. The full probe inventory is in the probe tests (`settings/backends/...` — tabs, per-backend toggles, the eidola url/measurements/ca editors, local installed/catalog/url rows, the add form).
- **Account** (shown only while eidola is enabled): balance + pools (`humanize_expiry`), the **Subscription** section, plans via shared `plans::plan_rows` (same checkout flow as onboarding), Reset behind a **two-step inline confirm** (armed warning + "Reset account" / "Keep account"; no modal). The manual allocate-credits input was removed (app-core auto-provisions). **Create/reset failures are surfaced, not dropped**: `account_op_error` renders in the `error_banner` style under the controls. Test: `account_op_error_surfaces_and_clears`; visual cases `settings_account`, `settings_backends_*`, `settings_nav_no_eidola`.
  - **The credentials are on the pane, and the secret is masked until it is asked for.** `ConfigState` carries the persisted `account_id` and `account_secret`; each renders as a read-only `Input` with a Copy affordance (`account_credential_input` — one component painted twice, taking an `id_prefix`), and the secret's field adds a reveal toggle and starts masked. Both fields are pushed from config on every render through a seed (`sync_readonly_input`), so what they show can never drift from what is stored and nothing typed into them survives.
    - **State that describes an account must not outlive it — and one place says so.** Three findings in a row were the same defect wearing different fields (a revealed secret, then a stale mint, then a stuck `manage_pending`), so the rule is stated once as a class rather than patched a fourth time. `AccountView::forget_account_scoped_view_state` drops **everything** this pane holds that describes a particular account — the reveal, the armed reset, both pending markers, both in-flight tasks, both error strings — the moment the credentials on display change. Each is something the reader consented to, armed, or set in motion *for the account configured at the time*, and none of it means anything about the next one; left standing, each reads as a fact about the new identity, the pending markers worst of all (they render as "Opening…" and their early return refuses every click until a request belonging to a forgotten account happens to land). Dropping the tasks is the point, not a side effect: their answers are addressed to nobody.
      - **Keyed on observed state, not on an identity-change event, because only that is total.** `AccountStore::account_identity_changed` is raised by creating and linking and **not** by reset — which is done from this very pane — so a hook there could never cover the pane's own most obvious path. Observing the displayed credentials covers every author and every route by construction. **Onboarding takes the event hook instead** (`OnboardingView::forget_account_scoped_view_state`, called from the create and link commits) and is total *there* for the opposite reason: that view is the sole author of an identity change during onboarding, there being no reset slide. The rule is therefore **observe where the change can come from anywhere; the event hook suffices only where the surface is the sole author.**
      - **Two classes, not one — and they compose.** The mint guard above is *not* a member: it validates an artifact arriving from outside at an arbitrary moment, which no amount of clearing can cure, and the clearing is *not* a substitute for it, because the cache this rule keys on lags the authoritative config by a bus tick. The clearing owns the steady state (and cancels the task); the guard owns the race window before the change has been observed. Regressions: `a_new_identity_inherits_no_state_from_the_one_it_replaced`, `onboarding_linking_another_account_clears_the_checkout_it_started`, `a_revealed_secret_re_masks_when_the_account_changes_under_it`.
    - **A payment link is opened only for the account it was minted for.** Both billing doors mint against the credentials held at click time and then take a round trip the reader can outrun. The identity is captured with the request and re-checked when it lands (`AccountStore::account_identity` / `mint_is_current`), so a portal session for the previous identity — or a checkout that would fund an account whose secret the reader no longer holds — is discarded and said out loud (`STALE_MINT`) rather than opened behind the current account's name. **The onboarding Purchase slide takes the same guard**, because its back-chevron reaches the existing-account slide and linking a different account mid-request is the same money decision. Regressions: `a_payment_link_minted_for_a_replaced_account_is_never_opened`, `onboarding_checkout_will_not_fund_an_account_linked_over`.
      - **And it reads the authoritative config, never `ConfigStore`.** That snapshot is a *cache*: every account write commits to config synchronously and then emits `Change::Config`, which reaches the store only when the bus bridge dispatches on a later tick — so between the commit and that tick the cached id still names the account just forgotten. A guard reading it would be asking the stale copy about the staleness it exists to detect, and would pass. `AccountStore::account_identity` reads `AppCore::config_state()` (synchronous, no DB, no runtime re-entry), falling back to the caller's `ConfigStore` snapshot only on a stub, which has no config to read. **A stub-store test cannot see this** — there is no bus and no core — so the regression is real-core: `a_reset_disowns_a_pending_link_before_the_bus_catches_up`, which deliberately does not pump between the reset and the mint. *Not* cured by making the reset write `ConfigStore` synchronously: one store never orchestrates another's (the stores doctrine above), the bus is what keeps every window's copy honest, and the swept readers of that cache make no other money or security decision — `lib.rs`'s launch-time `has_account` gate reads it once before any race exists, and the credential fields re-seed from it, which is what the re-mask rule keys on.
    - **A11y: the fields are focus-bearing editors, their suffix controls are hoisted.** Each `Input` carries `.aria_label(..)` and its wrapper is `probe_bounds` (the widget owns the focus handle, so the widget is the node); the reveal and copy buttons living in the suffix take the hoist — a probed wrapper carries role, label, focus and the click, and the `Button` is presentational (`.role(None)`, `.tab_stop(false)`). Probe names *and* element ids both derive from `id_prefix` (`settings/account/{id,secret}`, each with `/copy`, the secret with `/reveal`), never a constant, because the component paints twice. The reveal control's label names what the click will do. Regression: `the_credential_fields_and_their_suffix_controls_are_each_one_node` — the source scan alone stays green with these buttons silent, which is exactly the failure it exists to catch.
  - **The pane's live reads happen on activation, not construction** (`AccountView::pane_activated`, dispatched by `SettingsView::sync_active_pane` — see the Settings section). Balance, prices and subscription are all re-read on every visit.
  - **Subscription** reads `AccountStore::subscription` — a live core read that persists nothing, so **nothing on the bus invalidates it** (`refresh_subscription`, its own supersede slot). Honest states: no account renders no section at all; then in flight ("Checking your subscription…"), answered (**Active**, **Inactive** or **NoCustomer** — every answer draws the section), failed **cold** (`load_error_panel` + Retry, the "Failed is not empty" rule), and failed over a **known** answer — which keeps that answer on screen, and in what the plans offer, adding "Couldn't re-check … showing the last answer", because a refresh error must never blank a cell that has data. **Only an answered, affirmative read narrows anything**: with a subscription in force the recurring plans come out via `plans::offered_plans` and a **Manage subscription** button takes their place, while one-time top-ups stay purchasable; unanswered, lapsed or failed leaves every plan offered, because the server is the authority on whether a second subscription is allowed and it refuses honestly, whereas hiding plans on a guess strands a reader who has none.
  - **A lapsed customer keeps their billing door, worded for what is behind it.** `Inactive` means a payment relationship with nothing in force — a saved card, invoices, receipts — so the section says "You don't have a subscription right now." and offers **Billing and receipts** (`settings/account/billing-portal`), never "manage your subscription", because there isn't one. Same `begin_manage` click, different standing. The copy is safe to make that claim only because the *server* now decides `inactive` on a real payment history rather than on the presence of a customer row (see `crates/eidola-server/AGENTS.md`) — an abandoned first checkout used to leave a customer id behind and this door promised it receipts that did not exist.
  - **`NoCustomer` gets the answer and the re-check, but no door.** What that state withholds is the billing door, not the section: a portal minted for an account money has never moved for is a door onto an empty room. It still says "You don't have a subscription on this account." and carries "Check again", because the reader who completes their **first** checkout is in exactly this state with the pane already open in front of them — activation only covers a revisit. Regression: `an_account_that_never_transacted_is_shown_no_billing_door`.
  - **The door is offered on the standing, and the standing is all the read carries.** Minting a portal session is its own server call (`AccountStore::request_portal` → `POST /v1/account/portal`), made at the click because the session is short-lived — so there is no link in the subscription response to gate the button on, and a door that depended on one would vanish for a paying customer over a blip in a call they never needed.
  - **The re-check is always offered** (`settings/account/subscription-retry`, beneath either answered state), not only after a failure. The reader changes their subscription in a browser window this app never hears about and comes back to a Settings window that never closed; activation covers the visit, this covers the reader who never left. Regression: `a_known_subscription_can_always_be_re_checked`.
  - **Manage subscription mints its link on the click** (`begin_manage` → the awaitable `request_portal`, a view-owned slot, the `begin_checkout` shape exactly): the billing-portal URL is a short-lived session, so opening one fetched when the pane opened would hand the reader an expired link. `subscription_summary` words the in-force standing (`active` / `trialing` / `past_due` each get their own sentence; an unfamiliar status is reported plainly rather than dressed up). Tests: `a_subscribed_account_is_offered_management_and_only_one_time_plans`, `a_lapsed_account_is_offered_its_billing_and_every_plan`, `an_account_that_never_transacted_is_shown_no_billing_door`, `a_known_subscription_can_always_be_re_checked`, `a_failed_subscription_read_offers_a_retry_and_withholds_no_plans`, `a_failed_re_read_keeps_the_subscription_it_already_knew` (`tests/probe.rs`), `subscription_summary_*` unit tests; driver scenes `settings_account_unsubscribed`, `settings_account_subscribed`, `settings_account_lapsed`, `settings_account_subscription_checking`, `settings_account_subscription_failed`, `settings_account_subscription_stale`.
- **Wallet**: the `credential_lifecycle` listing (active / in flight (warning, recoverable) / spent / expired (muted)); "Recover in-flight" appears only when something is in flight.

## The Record window — the trust door's engine room

`record.rs` (`RecordView`, singleton, ⇧⌘L, 860×640) exposes the raw local Turso trail. Three sections in a quiet text strip that doubles as the title bar (`STRIP_LEFT_PAD` clears the traffic lights / Linux wordmark; right side carries Refresh and an italic "The Record" wordmark):

- **Attestations** — `attestation` rows; click → the full raw document (pretty-printed JSON when it parses, UTF-8 text, hex otherwise).
- **Requests** — `request` ⋈ `connection` rows; click → full detail: kv rows (the attestation hash links through) + raw headers and bodies.
- **Spending** — the `spend_trail` view grouped by credential; rows click through to request detail.

Mechanics:

- **Windowed fetch, owned tasks.** `Listing<T>` per section; each page asks for `PAGE+1 = 51` rows to learn `has_more` without a COUNT. Data flows through the `bridge` free functions; the view owns every fetch in a task slot (per-`Listing` page slots + one shared `detail_task`). Replace-cancels is what makes `refresh()` safe — a superseded fetch can never land late and append duplicate rows (replay: `record_refresh_supersedes_in_flight_fetch`).
- **Bus-driven staleness (the doctrine's "Record pattern").** No global store owns the rows, so `Change::Record` routes to the data-less `RecordStore` relay, which bumps an `epoch`; each open `RecordView` compares and sets a `stale` flag — rendering Refresh as a quiet "New entries — refresh" instead of mutating rows under the user's scroll. `refresh()` resets all three sections, clears `stale`, re-snapshots the epoch. A bus `Lagged` also bumps the relay. Tests: `record_marks_stale_on_record_change_and_refresh_clears`, `bus_bridge_routes_record_change_to_record_store`.
- **Virtualized listings + flat display model.** Each populated section renders through `uniform_list`; to keep the closure a dumb indexer, each `Listing<T>` precomputes a flat `Vec<DisplayRow>` (`Header(i)` / `Data(i)` / `LoadMore`) on every state change. **Spending group headers survive virtualization** because they are precomputed rows, not a render-time `prev_nonce` branch the windowed closure couldn't reconstruct. All rows are normalized to one fixed `ROW_H`. The trailing `LoadMore` row appends the next page; in flight it renders an honest "Loading more…" (a real task, never an infinite spinner). Empty/loading/detail bodies stay in an ordinary `overflow_y_scroll` (`scroll_wrap`, tracking `detail_scroll`); only a populated listing is the self-scrolling `uniform_list`.
- **Raw payloads are never redacted** (the user's own traffic on their own machine). Inline rendering caps at 64 KiB with an honest note; the per-section **Copy** always writes the full payload. Raw text renders selectable through `TextView::markdown` inside a code fence whose backtick run exceeds any run in the content (`fenced`); `TextViewStyle` mirrors `theme.mode.is_dark()`.
- **Parse caching.** Opening a detail builds a `DetailCache` **once** (raw projection, capped inline string, full Copy string); render only reads it. TextView itself does not re-parse per frame at our pin (`use_keyed_state` + `set_text` early-return on unchanged text), so a stable id + stable string parses once. Perf guarded by `record_frame_work_is_constant_in_loaded_rows` (1 page vs 10 pages).
- **Detail-body frame cost — the selection scan is the thing to watch.** The detail body is deliberately not virtualized (one `TextView` per section — linear cost, ~8 ms/frame for 46 KB in dev, and keeping the payload whole is what lets a drag selection span it). The non-linear cost is `gpui-component`'s `Inline::layout_selections`, which ran O(characters × lines) on every paint while any window selection existed (measured: 64 KiB → 1117 ms/frame dev). The structural cure is upstream (skip lines outside the selection/content mask; per-character positions from one ordered glyph pass — flattens to idle cost with byte-identical selections); until it lands in our pin the wall exists, bounded by `INLINE_CAP` = 64 KiB. **Two traps:** (1) geometry must use `TextLayout::line_height()` (pixel-snapped), not `window.line_height()` — they differ by a device pixel, enough to move a hit; (2) `layout_selections` clips the reported selection to the content mask, so ⌘C on a payload selection yields only what was *on screen* — the per-section Copy is the honest whole-payload path and is why it exists.
- **The measuring instrument (`tests/record_perf.rs`).** Local-only (`harness = false`, macOS, `EIDOLA_RUN_RECORD_PERF=1`, never CI): opens a real offscreen window on a request detail and reports (a) `Window::draw` time in four states across a payload-size ladder, and (b) **selection fingerprints** — hashed text a fixed set of drag geometries selects; the differential gate on any selection-machinery change ("faster" must never mean "selects something else"). Feed real payloads via `EIDOLA_RECORD_PERF_REQ`/`_RESP`; `EIDOLA_RECORD_PERF_SHOTS=<dir>` writes PNGs. Run on **dev** as well as `--release` — dev numbers are what a developer feels.
- **Roving keyboard cursor per section.** Each `Listing<T>` carries its own `list_focus` + `focused_row`, so a listing is one tab stop and switching sections restores position. Enter opens a data row's detail / fetches on load-more / no-ops on a spending group header (a caption is navigable but not activatable — and it carries a `Role::Label` node so `aria_active_descendant` has something to name). `close_detail` hands focus back to the listing rather than leaving the unmounted handle focused.
- **Deep link in:** `show_request(id)` selects Requests and opens that request's detail — the door a space's trace row comes through (`crate::open_record_request`, via the `AppGlobal::record_view` weak handle). Backing out lands on the listing.
- **Space cross-link:** the request detail includes a "Space" kv row when `RequestDetail.space_id` is set (LEFT JOIN through `action → space`), rendered as a quiet link deferring `open_space_window`. Test: `record_request_detail_exposes_space_link`.
- **Mono is for data, the UI font for chrome** — `mono()` (Menlo 12/13px) wraps every hash/nonce/path/payload; labels and timestamps stay Newsreader. Timestamps are UTC and say so (`fmt_utc`, Hinnant `civil_from_days` — no chrono).

## Virtualized lists

Fixed-height lists render through gpui's `uniform_list` (STATE.md → "Lists"): the Record sections, the Library, and the space view's quote-destination picker. (Space-view posts are variable-height and use the height-cache virtualization instead.) The idiom:

- **Item-range closure via `cx.processor`** — a dumb indexer rendering only the visible range; any structure a bare range can't reconstruct (headers, load-more) is precomputed into a flat display model.
- **Fixed row height** — `uniform_list` lays every row at one measured height; normalize rows to an explicit `.h(ROW_H)` and push variable content into the detail view.
- **Stored scroll handle** — a `UniformListScrollHandle` on the view, passed to `.track_scroll` each frame (scroll survives re-renders; supports `scroll_to_item`).
- **Sizing** — `ListSizingBehavior::Auto` fills the flex parent and scrolls internally: place as a `flex_1` child or `.h_full()` inside a `flex_1().min_h_0()` parent. Do **not** wrap it in another `overflow_y_scroll` div (nested scroll surfaces; the inner list collapses). **Inside a bounded overlay there is no parent to fill**, so the quote-destination picker gives the list an explicit `count × ROW_H` capped at its own maximum — exact, because fixed-height rows make the content height knowable, and it is the same rule read from the other end. **That explicit height is also what lets a list live inside a scrolling panel**: the inspector's invite-candidate list sits in the panel's own `overflow_y_scroll` body, which the rule above reads as forbidden — but what the rule forbids is the *collapse*, and a list that states its height cannot collapse. The residual nesting (an inner scroller inside an outer one) is the panel's existing pattern, not a new one; its model dropdown has always been one. Pinned by a test that the rows actually paint there.
- **One tab stop, a roving cursor.** A virtualized list's rows cannot be tab stops — the order would omit whatever is not materialized. The handle goes on the element carrying the role, ↑/↓/Home/End move a cursor clamped on read, `scroll_to_item` materializes it, Enter activates; rows are `probe_delegating` managed descendants with `aria_selected`/`aria_active_descendant`. **A row claims the cursor only while the list holds focus** (it is the row's focus identity), and the ring is modality-gated on top of that; the a11y state is not. **A cursor and its scroll offset are one state** — reset together, or a list reopens showing one place while Enter acts on another. **The key map answers five keys and no more** — a list inside a popover or a form must let Escape reach the surface's own dismiss.
- **The range goes on before the clone.** A dumb indexer that materializes the whole display model and *then* slices it has virtualized the elements and left every allocation O(loaded). Apply the range to the iterator, and ask the store for a **count** rather than a vector's length (`quote_destination_count`).

## Scroll indicators (`src/scrollbar.rs`)

Every scrollable surface that isn't the space page carries a quiet overlay scroll indicator: a right-edge `gpui_component::scroll::Scrollbar` in `ScrollbarShow::Scrolling` mode — appears while scrolling, fades, reserves no gutter. Binds to a plain `ScrollHandle` or a `UniformListScrollHandle`.

- **Two constructors, by whether the viewport meets a window corner.** `vertical(id, handle, window)` — a window-edge strip; applies `chrome::corner_clearance` at both ends so the thumb never paints over a Linux CSD rounded corner (zero on macOS/SSD/tiled, so hosts apply unconditionally). `vertical_floating(id, handle)` — a bounded mid-window overlay (dropdowns/popovers); no clearance (window-corner clearance keyed off the window's decorations would wrongly inset a mid-window element).
- **Placement rule:** the overlay is a **sibling** of the scroll container inside a `relative` ancestor spanning the viewport — never a child of the scrolling element (a child scrolls away with the content).
- Not a `.probe(…)` target (a plain indicator, not an accessible affordance).
- **Wired:** Library (list edge), Record (per-section handles + `detail_scroll`), every Settings pane (one shared `body_scroll`), Participants roster, Updates body, onboarding page scroll; bounded: the model-picker dropdown (`picker_scroll`, reset on open). **Excluded:** the space page (the minimap *is* its indicator) and the composer's text scroll. Render-smoke: `*_renders_with_scroll_indicator`; the driver's `library`/`record`/`settings`/`participants` scenes exercise it.

## Edge-to-edge titlebar

`transparent_titlebar()` returns `TitlebarOptions { appears_transparent: true, title: None, traffic_light_position: Some(point(14, 11)) }` — macOS extends the content view under the traffic lights. Each view leaves room at the top; the reserves are platform-uniform:

- **`space_view::TITLE_BAR_RESERVE`** (36px): vertical reserve plus a `theme.background → transparent` gradient overlay (the title band, wired through `titlebar::make_draggable`) painted absolutely over the scroll area — posts fade into the chrome instead of clipping.
- **`settings::NAV_TOP_RESERVE`** (44px): the window controls sit over the sidebar nav band.
- **`record::STRIP_LEFT_PAD`** (80px macOS / 86px Linux): horizontal pad on the Record's strip; right padding adds `chrome::controls_reserve(window)`.

**The header captures the mouse** — an instance of the overlay-containment rule: a press on the transparent band used to land in the post beneath, so the window-move gesture dragged out a text selection (task 32). `titlebar::make_draggable` declares the strip `Overlay::Fade` and the band paints **after** the page it covers (which also restored the documented fade). Regression: `space_title_band_press_does_not_select_the_post_beneath`.

**The drag band is 36px in every window** (`titlebar::DRAG_BAND_HEIGHT`, aliased by every reserve). Settings' former 44px band sat over the Backends tab strip once the band began blocking the mouse, making the tabs unclickable — the band is a hit target the user can't see, so a uniform height is what makes "grab the top of any window" mean one thing; panes carry their own heading padding. Regression: `settings_backends_tabs_paint_clear_of_the_drag_band` (geometric).

## Overlay containment — surfaces that cover live content (`src/overlay.rs`)

**gpui does not occlude by painting.** A hit test reports every hitbox under the cursor; an element drawn on top does not take the mouse away from what's beneath. Containment is an explicit opt-in (`.occlude()` / `.block_mouse_except_scroll()`) and suppresses only hitboxes registered **before** the blocking one — so a contained surface must *also* paint after what it covers. Both halves were forgotten twice in the same shape (the drag band; the floating composer, where a drag-select fell through to the post underneath and drove the page's selection-autoscroll), which is why the rule is a shared seam.

Every overlaying surface declares an `Overlay` class via `overlay::Contain::contain_mouse`. The axis is **what should happen to the wheel** — clicks always belong to what you can see under the pointer:

| Class | Clicks | Wheel | Primitive |
| --- | --- | --- | --- |
| `Overlay::Fade` — translucent chrome you read live content through | captured | falls through to the page | `block_mouse_except_scroll`, no scroll handler |
| `Overlay::Scrolling` — an opaque surface that owns its own scrolling | captured | reaches the surface's own handler | `block_mouse_except_scroll` + a scroll handler |
| `Overlay::Popover` — an opaque surface with nothing to scroll | captured | captured | `occlude` |

The composer's handler deliberately *routes* rather than always consuming (a floating composer with nothing to scroll hands the wheel to the page, moving it toward its dock) — that policy living on the surface is why `Scrolling` isn't just `Popover`. `Popover` blocks the wheel because a menu whose page scrolled out from under it would anchor to moved content.

Current classes: title/drag bands `Fade` (painted last); floating/docked composer `Scrolling`; context menu, band menu, source-highlight picker `Popover`; failure/cascade notices `Popover` **on the card** (never the transparent full-width wrapper, which would swallow clicks nowhere near the notice); the inspector's scrim `Popover` and its overlaying panel `Scrolling` (both painted last); minimap `Fade` **only while visible** (a faded strip must contain nothing; the wheel always passes — the strip *is* the page's scroll indicator). **When you add a floating surface:** pick a class, call `contain_mouse`, paint it after what it covers. Tests: `space_composer_drag_is_contained_and_does_not_scroll_the_page`, `space_title_band_press_does_not_select_the_post_beneath`.

**Window dragging is wired explicitly** (`src/titlebar.rs`). With the transparent titlebar macOS hands us no draggable strip, gpui's `WindowControlArea::Drag` is a no-op there, and the Wayland backend never implements the control-area hit-test — so one explicit gesture serves both: arm on left mouse-down, `Window::start_window_move()` on the first move while armed (a plain click never starts a drag). Double-click → `titlebar_double_click()` (macOS; respects the zoom-vs-minimize preference) / `zoom_window()` (Linux); right-click → `show_window_menu(pos)` (the compositor's window menu; no-op on macOS). The armed flag is element-owned state (`use_keyed_state` holding a `Cell<bool>` mutated without an entity update, so arming never re-renders and survives a re-render landing between down and move). A mouse-down inside the CSD resize band yields to the resize (`chrome::in_resize_band`). `titlebar::drag_band(id, height, window, cx)` builds the full-width transparent band (About / Library / Settings / Onboarding, painted last); `titlebar::make_draggable(el, key, window, cx)` attaches the gesture to an existing strip (Updates' spacer, Record's strip — whose tabs keep their clicks — and the space view's gradient band).

## Linux window chrome — CSD, primary menu, keyboard

Everything lives in `src/chrome.rs` (module docs carry the full rationale); this is the map.

**Decoration model.** Wayland has no server titlebar unless the compositor implements `zxdg_toplevel_decoration_v1` (KWin does; Mutter never). Every window *requests* `WindowDecorations::Client` (`lib.rs::base_window_options`, which also sets `window_background: Transparent` and the Wayland `app_id`); `chrome::ChromeRoot` — a wrapper view between `gpui_component::Root` and the real view (identity on macOS) — renders by what was granted:

- **`Decorations::Client`** (GNOME always; KDE default): the zed-pattern CSD frame — shadow padding on untiled edges (`SHADOW_SIZE` 12px, folded into `set_client_inset`), a 1px `theme.border` frame, rounded corners on all four (`CORNER_RADIUS` 12px, the Adwaita radius), resize-edge handling (`start_window_resize` on the backdrop; the hit band spans the shadow margin plus 4px inside the frame edge; drag strips check `chrome::in_resize_band` and yield), and the **window-controls cluster** top-right — quiet ghost buttons in our voice; minimize/zoom render only if `window.window_controls()` reports the capability, close always. `Tiling::tiled()` collapses shadow/rounding/resize when maximized. Resize *cursors* are declarative zones — transparent listener-less divs with `.cursor(...)` — never `window.set_cursor_style` from paint (an imperative cursor is a per-frame request against last-painted hitboxes and outlives the pointer's stay in the band — the "stuck resize arrow" bug).
- **`Decorations::Server`** (KDE forced-SSD): no frame/controls/drag duty (this arm paints the window background, since `themed_root` strips Root's); the primary menu still renders (app chrome, not window management).

**Single CSD authority.** `gpui_component::Root` ships its own Linux CSD layer (`window_border()`), which stacked under ours painted the shadow padding as an opaque cliff with wrong-edge resize cursors. Every window is built through `chrome::themed_root` — Root with `bordered(false)` (upstream opt-out, gpui-component #2466: `Root::render` returns inner content directly, removing the competing layer entirely) + transparent background — and both palettes pin `window_border` transparent as belt-and-braces. Root must stay the outermost view (`Input` resolves it via the window root).

**Content-box discipline.** `window.viewport_size()` includes the CSD shadow padding. Any math anchoring to the window bottom/right or sizing a page (floating composer, minimap, scroll ranges, dock positions) must use `chrome::content_size(window)` — else bottom-anchored overlays hang into the shadow band. Equals the viewport on macOS/SSD/tests.

**Containment + corner duty.** The chrome frame clips descendants to its rect (`overflow_hidden`; deferred draws re-apply the captured content mask, so deferred overlays stay contained). The clip is rectangular (gpui masks carry no radii), so rounded corner *notches* are each corner-touching surface's duty: window roots apply `chrome::round_client_corners`; partial-edge bands use the single-corner variants (Settings nav rounds tl+bl; the title band rounds top; the composer bar — the bottom-most opaque surface — rounds bottom, and when the docked bar covers the window its visible quad is split from the virtual geometry so its top corners round at the window's top arcs); full-height edge strips inset by `chrome::corner_clearance`. All no-ops on macOS/SSD/tiled — apply unconditionally.

**Primary menu.** The Linux replacement for the macOS menus (`cx.set_menus` builds no UI on Linux): a quiet italic **"Eidola" wordmark** top-left (GNOME's primary-menu idiom in our voice) opening a popover of the app commands — New Space, one "New Space from “{title}”" row per live template (read from `TemplatesStore` at render time), Show/Hide Inspector (a no-op without a focused space window, matching the greyed macOS item), the selection-scoped Quote / Quote in Reply pair, the zoom trio, then Library, Record, Settings, Check for Updates, About, Quit — each with its Ctrl-chord beside it, so the popover doubles as the keyboard-reference card. One flat list whose grouping mirrors the macOS structure. Items dispatch the same actions. Toggled by click or **F10** (Linux-only, an `on_action` on ChromeRoot's wrapper div — an ancestor of every focused element). Dismissal: click-out, re-toggle, or selection. Probes `chrome/menu`, `chrome/menu/panel`, `chrome/menu/{slug}`; regression tests cover action-toggle, the real F10 keystroke, and a real simulated click on the wordmark's painted bounds.

**Chrome z-order.** The controls cluster and menu render `gpui::deferred` at priority 100/101 — painted after the whole normal-pass tree, above all view content. Both swallow their mouse-down (both-phase, the Library-pencil pattern) so clicks never arm the drag band beneath.

**Keyboard.** Three layers (`install_keybindings` + `gpui_markdown_editor::init`):

- **Chord commands** bind with gpui's **`secondary-` alias** (⌘ on macOS, Ctrl elsewhere): all globals and the editor's clipboard/select-all/submit chords.
- **Motion/deletion** differ structurally, so the editor keymap has per-platform tables: macOS ⌥=word / ⌘=line-or-document; Linux Ctrl+arrows=word, Ctrl+Home/End=document, Ctrl+⌫/Del=word-delete. Home/End are neutral.
- **Not bound on Linux**: ⌘H/⌥⌘H (AppKit hide) and ⌘M (the compositor's job).

User-visible chord copy goes through `actions::{primary_chord, primary_shift_chord, alt_name}` — never hardcode mac glyphs.

**Lifecycle & identity.** A windowed Linux launch quits with its last window (`QuitMode::LastWindowClosed`); a long-lived process is `--windowless` (what the systemd unit launches). Every window sets `app_id = "ai.eidola.app"`, matching the basename of `releases/linux/ai.eidola.app.desktop` (shipped in the Nix artifact) — that equality gives us a name in Alt-Tab and dock pinning. The freedesktop id follows the `ai.eidola.<product>` convention with **no OS suffix**: the `.macos`/`.ios` suffixes disambiguate sibling apps inside Apple's single namespace, while the freedesktop namespace holds exactly one Eidola app and its ids conventionally omit the OS. `APP_ID` is window metadata only — gpui feeds it to the Wayland `xdg_toplevel`/xdg-activation and to X11 `WM_CLASS` (same string for instance and class, so no separate `StartupWMClass` key is needed while the basename matches) — so nothing user-visible persists under it and a rename strands no state. The entry's `Icon=ai.eidola.app` resolves to the themed icons in `releases/linux/icons/hicolor/` (scalable SVG + 48/128/256 PNGs), installed to `share/icons/` by `eidolaGuiLinuxWrapped` and generated by `just update-brand`. Dev loop: symlink the .desktop into `~/.local/share/applications/` with `Exec` pointing at the dev binary — and after a rename, refresh the caches that key on the old name (`update-desktop-database ~/.local/share/applications`, `gtk-update-icon-cache ~/.local/share/icons/hicolor`) or the stale entry lingers as a duplicate launcher icon.

**Validated headlessly** (2026-07, sway headless + grim under Nix): frame/corners/shadow/border render, controls are capability-driven, the wordmark paints, text input and Ctrl+A work through a live Wayland virtual keyboard, and the `app_id` is on the wire. Pointer injection doesn't reach headless-sway surfaces, so click paths are guarded by the in-process probe-bounds tests.

## macOS UX — menus, keybindings, action dispatch

All wired in `src/lib.rs::install_menus`, `install_keybindings`, `install_action_handlers`. **Order matters** — see the ordering invariant.

### Menus (`cx.set_menus`)

- **Eidola**: About / Check for Updates… / Get Started / Settings… / Library… / Record… / Hide / Hide Others / Show All / Quit — Library and Record are app-level windows over your whole trail, so they live here.
- **Space**: New Space / New Space from Template ▸ / Show/Hide Inspector / Close Window — the space-centric replacement for "File". The inspector item is per-`SpaceView` like `CloseWindow`; its label states both directions because the menu bar is static.
- **Edit**: Undo / Redo / Cut / Copy / Paste / Select All / **Quote** / **Quote in Reply** — the standard verbs declared via `MenuItem::os_action(_, _, OsAction::*)` so they bind the macOS selectors and route through the responder chain; the quote pair acts on the selection and is registered per-`SpaceView` only while a quotable selection exists, so macOS greys them otherwise.
- **View**: Actual Size / Zoom In / Zoom Out — handlers write `font_scale` through `ConfigStore` (emits `Change::Config`; `theme::wire_config` re-applies on every window).
- **Window**: Minimize / Zoom.

`cx.set_dock_menu` adds "New Space" and "Library…". **The "Window" menu name is special**: gpui_macos detects a menu literally named `"Window"` and calls `setWindowsMenu_`, which is part of how AppKit recognizes a fully-wired app and reliably dispatches menu key-equivalents when no window is key; the Hide trio plays the same signaling role.

### Keybindings (`cx.bind_keys`)

Global chords use `secondary-`: `secondary-,` Settings, `secondary-n` NewSpace, `secondary-l` Library, `secondary-shift-l` Record, `secondary-w` CloseWindow, `secondary-q` Quit, `secondary-alt-i` ToggleInspector (the space inspector; gpui's element inspector moved to `secondary-alt-shift-i` as `ToggleElementInspector`), `secondary-0/=/+/-` the zoom trio (global — no context — so they fire with the composer focused; the editor keymap binds none of those keys under the primary modifier; regression: `zoom_keystrokes_resolve_to_actions`). macOS-only: ⌘H, ⌥⌘H, ⌘M. Linux-only: F10. The submit chords ⌘↩ (Post) / ⌘⇧↩ (Post quietly) are **not** view bindings — they live in the `MarkdownEditor` context and reach `Send`/`PostOnly` via the editor's `PressEnter` event, routed by each draft's / edit session's subscription; binding them on the view would shadow the editor. Esc routes through element key handlers rather than bindings so it composes with editor focus.

### Ordering invariant

`install_keybindings(cx)` **must** run before `install_menus(cx)`: `cx.set_menus` snapshots the keymap when building NSMenuItems (`keyEquivalent` from `bindings_for_action`). Menus-first leaves every item chord-less, and macOS can't intercept shortcuts at the menu level — breaking ⌘N/⌘Q when no window has key focus. **Diagnostic signal**: menu items missing their shortcut text.

### Action handlers (`cx.on_action`)

Mostly global. Two patterns:

- **Window-targeting handlers** (`Minimize`, `Zoom`) capture `cx.active_window()` and `cx.defer` the call — a direct `handle.update(cx, …)` on the window we were dispatched inside fails (its slot is taken) and `.ok()` swallows it.
- **`CloseWindow` is registered per-view**: each view root does `.on_action(…)` + `track_focus`es a handle `focus()`ed in the constructor (so dispatch reaches the listener before any click). Consequence: `is_action_available` is true only while such a window is alive, so macOS auto-disables "Close Window"/⌘W when none is open.

### Lifecycle

- `cx.activate(true)` at launch — menu bar fully connected from frame 0.
- `Application::on_reopen` registered on the builder *before* `run()` (it takes `&self` while `run()` consumes by value — bind the application to a local first). See [App lifecycle](#app-lifecycle--the-app-outlives-its-windows-and-q-retires-it).

## .app bundling — required, not cosmetic

A bare `cargo run -p eidola-gui` binary is a command-line tool to AppKit: `setActivationPolicy(Regular)` papers over the common path, but **menu key-equivalents fail to dispatch when no window is key**. Diagnostic signal: the menu bar shows `eidola-gui` instead of `Eidola`.

- `crates/eidola-gui/Support/Info.plist` — `CFBundleIdentifier = ai.eidola.app.macos`, `CFBundleExecutable = Eidola`, `NSPrincipalClass = NSApplication`, `NSHighResolutionCapable`, `CFBundleIconFile = AppIcon`, `LSMinimumSystemVersion = 13.0`. The floor is Ventura because `SMAppService` is (see `login_item.rs`); it is the **bundle's** floor, enforced by LaunchServices for bundle launches only — the binaries still declare `minos 11.0`, which is why `login_item.rs`'s class-availability guard stays.
- **Bundle identifier convention: `ai.eidola.<product>.<target>`** — lowercase forever, Apple's target-family names, `app` the flagship product slot; a child process or login item appends a role (`ai.eidola.app.macos.launcher`), none of which exist yet. This is the app's permanent identity to macOS — TCC grants, LaunchServices, the Developer ID App ID, and `SMAppService` registration all key off it, so changing it orphans every grant a user has made. Distinct from the Linux **`app_id`** (`ai.eidola.app`, `lib.rs::APP_ID`), which is a freedesktop identifier tied to the `.desktop` basename and icon-theme names rather than a reverse-DNS bundle id: it shares the `ai.eidola.<product>` stem but takes no target suffix, and it moves with the committed `.desktop`/icon filenames, never with the bundle id.
- **Bundle layout, one shape in dev and release:** `Contents/{Info.plist, MacOS/Eidola, MacOS/llama-server, Resources/AppIcon.icns}`. The inference sidecar sits in `Contents/MacOS/` beside the main binary — where Apple expects a bundle's executables, and the reason app-core's engine resolver is a single sibling-of-exe rule with no `.app` knowledge in it (`crates/eidola-app-core/AGENTS.md` → engine resolution). Moving it is a cross-cutting change: `flake.nix`, `scripts/package-gui-app.sh`, and the resolver must agree.
- `crates/eidola-gui/Support/AppIcon.icns` — the hexagon-grid app icon, committed and generated by `just update-brand` from the geometry in `brand/` (doctrine: `brand/AGENTS.md`). Both bundle paths copy it into `Contents/Resources/`, and the dev script **fails** if it is missing rather than shipping an icon-less bundle. Do not hand-edit it, and do not build a brand asset from an SF Symbol — the status-item glyph below is the one sanctioned SF Symbol use.
- `scripts/package-gui-app.sh` — copies the binary to `Contents/MacOS/Eidola` (renamed to match `CFBundleExecutable` — mismatch falls back to tool-mode), copies the plist and the icon, ad-hoc codesigns. Output `crates/eidola-gui/build/Eidola.app` (gitignored). The dev path.
- `just build gui` runs cargo + the package script on macOS; `just run gui` builds + `open`s. Non-macOS falls back to `cargo run`.
- **Release path:** `nix build .#eidola-gui-macos-universal` — universal binary, LC_UUID zeroed, same `Eidola.app` layout, recorded in `artifact-manifest.json`. Two reproducibility tricks: (1) gpui's Metal shaders compile at app startup (`runtime_shaders`) instead of via Apple's closed-source `metal` compiler at build time; (2) `flake.nix`'s `preBuild` stitches a missing `assets/assets/icons` sibling layout into the vendored gpui-component dep (upstream `icon_named!` reads a path that only resolves in the upstream workspace layout).

## Testing — two tiers

Both run via `cargo test -p eidola-gui` (the crate has both `[lib]` and `[[bin]]` so integration tests import view modules). A third, non-gating tool — the interactive UI driver — sits alongside.

### Behavior tests (`tests/behavior.rs`) — the regression gate

Built on `gpui::TestAppContext` (mocked rendering, deterministic dispatcher; runs on libtest worker threads without AppKit). Pattern: build stub stores (`Stores::stub_with`), open a window, drive interactions through the view's `focus_handle()` (the production keystroke path), assert against public view state or store entities with `read_with`. Stub stores have no backend (`Stores::app_core()` is `None`), so views early-return after local state mutation. Store *machinery* (supersede, bus dispatch, launch-order replay) is tested against a real tempdir `AppCore` in `tests/stores.rs` (`Stores::for_test`).

### Visual snapshots (`tests/visual.rs`) — local-only debug aid

**Not** a regression gate. `gpui::VisualTestAppContext` (real Metal renderer, offscreen window, deterministic dispatcher), `harness = false` so `fn main()` runs on the macOS main thread (libtest's worker thread would SIGABRT in AppKit). Cases in `tests/visual/cases.rs`; the harness renders each view **twice — Circadian Day and Night** — writing `tests/snapshots/<name>-{day,night}.png`. Build closures must be `Fn` (invoked once per mode). The PNGs are **gitignored** — pixels are platform- and machine-bound, so committing them would mean false-positive regressions; their value is local (an agent `Read`s a PNG to see a state; a dev eyeball-diffs runs). Missing PNG → written; mismatch → `<name>-<mode>.new.png` + fail; `UPDATE_SNAPSHOTS=1` overwrites. Recipes: `just render-snapshots[-update]`.

### The UI driver (`examples/driver.rs`) — interactive QA sessions

A long-running interactive session ("Playwright for eidola-gui") driven over a JSON-lines stdin/stdout protocol. `just driver` (a cargo *example*, so dev-dependency unification supplies gpui's `test-support` outside `cargo test`). Boots a `VisualTestAppContext`, installs the production keymap (`install_keybindings`, `pub` for this), then loops one JSON request/response per line.

- **Commands**: `scenes` / `open` / `windows` / `elements` (named click targets with painted bounds, from the probe registry) / `click` (by probe target or x/y, with modifiers and `button:"right"`) / `drag` (with `click_count` for double/triple-click and `hold` to pump frames so autoscroll-while-selecting runs) / `type` / `keys` / `modifiers` (drives the real `ModifiersChangedEvent` path) / `scroll` / `resize` / `screenshot` / `theme` (day|night + optional character) / `locale` (one of the shipped locale tags — see the Localization section) / `settle` / `close` / `quit`. Full protocol docs in the example's module comment.
- **Scenes** are stub-store fixtures mirroring the visual cases. No backend: store-backed flows stop at the stub guard; all window-local interaction is fully live.
- **Element staleness**: every `elements` call (and by-name `click`) clears the window's probe entries, forces a fresh frame, and re-reads — an unmounted element can never linger as a ghost target. Regression-tested in `tests/probe.rs`.
- **Limits (v1)**: app-global action handlers aren't installed (need the real `AppGlobal`/backend); window-scoped actions and keybindings work. macOS-only, like the visual tier.

## Accessibility & QA probes

gpui has AccessKit integration (zed #56065, in our pin): an element appears in the platform a11y tree only if it carries an `ElementId` **and** a role, with labels/state via the aria-style builders on `StatefulInteractiveElement`. On macOS this produces real `NSAccessibility` nodes.

Our annotation point is **`crate::probe::Probe`** — `el.id("…").probe(name, role, label)` — which does three things at once: sets the AccessKit role + label (always), derives the element's **focus attributes** from the role (wave B), and records painted bounds into a process-global registry (when probes are enabled — the driver's `elements`/`click` vocabulary). **The accessible name is the driver's selector**, so the AT surface and the QA surface are one annotation and cannot drift. The registry records via the public `canvas` idiom (gpui keeps its own bounds maps crate-private); probes are inert in production, and the trait bound makes ".id() before .probe()" a compile error to forget.

- **`probe_delegating(name, role, label)`**: the same annotation with no focus attributes — for a row of a roving-focus list (the list is the single tab stop). Not the answer for a wrapper around a `gpui-component` widget (see the focus section).
- **`probe_value(name, role, label, value)`**: adds `aria_value` — the content channel. It exists because `aria_value` is otherwise unobservable (the emitted `TreeUpdate` is crate-private); `ProbeEntry` carries the value, `assert_probe_value` asserts it, the driver reports it. Read the settled-value rule below before wiring one.
- **`probe_bounds(name, role, label)`**: the registry half only — driver selector + painted bounds, **no AccessKit attributes at all** (the element emits no node; the role/label describe the control in `elements` listings). The bounds-only slice of task 43's un-hoist design, pulled forward. **Exceptional by design**: only for a wrapper whose inner widget is itself the accessible node (today: the `Input` wrappers). `probe` stays the default; a bounds-only probe anywhere the wrapper is the control silently deletes the control from the a11y tree.

Conventions:

- **Names** are slash-scoped lowercase paths (`space/composer`, `library/row/{idx}/archive`); the name is the driver's selector, so it must be **unique per painted element** — index every repeated affordance, and a shared component takes a `name_prefix` from its host.
- **A shared component derives its element id from the probe name it was handed — never a constant.** Two elements sharing a `GlobalElementId` are one element to gpui: they share per-element state (`with_element_state` hands the second the box it just gave the first, so a `Stateful<Div>` pair shares one `pending_mouse_down`) and hash to the same AccessKit node id (`can_push` — a `debug_assert`, silently dropped from the tree in release). `load_error_panel` hard-coded `load-retry`, and the space inspector's two sections read different stores, fail independently, and stand in one panel with no intervening ids: mouse-up dispatches its capture phase in paint order, so the Space panel's handler found the press armed on the *Participants* button, saw its own hitbox unhovered and swallowed it — leaving that Retry inert in the one state where Retry is the only way forward (Codex review, PR #278). The probe name is already required to be unique per painted element, which is exactly what an element id must be, so deriving one from the other closes the class for every present and future caller. Regression: `each_failed_section_gets_a_retry_of_its_own`.
- **Labels** are what a screen reader should say — user-meaningful, dynamic where the content is.
- **Roles** come from `gpui::Role`: Button, Link, Tab, ListBox/ListBoxOption, ListItem, TextInput, Alert, Group, Article (a post), Label (a static readout), plus the landmark set. **`Alert`** marks status text that must be announced (the Unverifiable band, the error banners — the onboarding ones keyed per slide). Disclosures set `.aria_expanded`; single-select rows/tabs set `.aria_selected`.
- **`Role::Heading` is broken at this pin — do not add new ones.** `accesskit_macos` (re-verified at 0.26.2) maps it to the bare string `"Heading"` (not `"AXHeading"`) and exposes no `AXHeadingLevel`, so it can never match VoiceOver's heading rotor. Two pre-existing uses remain (`about/title`, `library/title`) — harmless. Use a named landmark instead. *Removal trigger: accesskit emitting `NSAccessibilityHeadingRole` + `AXHeadingLevel`.*
- **gpui-component widgets stay wrapped — under a two-regime rule keyed on who holds the focus.** Upstream's a11y work means `Button`, `Input`, and `Checkbox` emit their own role-bearing nodes, so one of the pair (wrapper, widget) must stand down or AT sees two controls. Which one depends on the regime:
  - **Hoisted controls** (`Button`, `Checkbox` — and `Switch` when it self-annotates): the probed wrapper is the control (role, label, focus, activation — the wrapper rule below), so the widget is made presentational with **`.role(None)` immediately after its constructor** (the fork extends the widgets' `role` builders to `impl Into<Option<Role>>`; `None` = no AccessKit node, the HTML `role="none"` analog).
  - **Focus-bearing editors** (`Input`): the widget owns the tracked focus handle, and a focused element with no node reports focus on the *window root* — so the **widget is the node**: it carries **`.aria_label(..)` immediately after its constructor** (the fork's `Input::aria_label`; the node also reports the text as its value), and the wrapper is a **bounds-only probe** (`probe_bounds` — driver selector unchanged, no AccessKit attributes).

  The emitted `TreeUpdate` is crate-private, so **the gate is source review plus the source-scan test** `self_annotating_widgets_opt_out_of_their_own_a11y_nodes` (`tests/probe.rs`), which enforces each regime's annotation and its constructor-first placement. `Switch` sets no role at our rev and needs nothing yet (tripwire comments at its two call sites); `Tab` annotates the **same element** our probe annotates — one node, no duplicate, but `Tab::render` re-applies its own label *after* ours (`tab.rs`), so a Tab probe label that differs from the visible tab text would be silently overwritten (today they match).
- **New interactive UI must ship with probes** — annotate in the same change; coverage is asserted in `tests/probe.rs` (extend it for new views).

**Landmarks and containment.** Role-less containers collapse in the a11y tree (children attach to the nearest role-bearing ancestor), so named containers exist and are probed: `space/conversation` (`Main`), `space/minimap` (`Navigation`), `settings/nav` (`TabList`, vertical), `settings/content` (`Main`, named for the selected pane), `settings/backends/tabs` (`TabList`), `record/sections` (`TabList`), `record/body` (`List`/`Region`), `library/list` (`List`).

Two workarounds worth knowing before touching them:

- **`uniform_list` cannot carry a role** (it implements `InteractiveElement` but not `StatefulInteractiveElement`) — the `List` parent goes on the container already spanning the viewport. Do not add a *new* wrapper div to get one; the existing wrapper is the scroll-container invariant, and a second would break it.
- **Set position is mandatory on a virtualized row — counting *data* rows.** `uniform_list` renders only the visible window, so AT sees six of six hundred unless rows set `.aria_position_in_set`/`.aria_size_of_set` — indexed among the section's **loaded data rows**, never the display index (the Record's display model interleaves headers and a load-more row). `record::RecordView::row_set_metadata` is the one rule. `size` is the loaded count (the server-side total is unknown and gpui offers no way to say so). gpui does not handle `accesskit::Action::ScrollIntoView`, so this metadata plus the explicit "Load more" affordance is the whole story.

**Space-window reading order: the minimap is deliberately last.** gpui builds a11y nodes in prepaint order = child order = paint order, and the minimap must paint above the floating composer (`deferred` defers prepaint too, so it can't decouple them). The `Main` landmark resolves the audit finding instead: the conversation region precedes the composer, and `Navigation` maps to `AXLandmarkNavigation`, so the strip is reachable from the landmark rotor.

**Every window is named.** Each `open_*_window` calls `Window::set_window_title` (labels the a11y root; previously all windows presented an unnamed `AXWindow`). Static for singletons; the space window's title is live (`SpaceView::sync_window_title`, guarded on change). **Write the title from an observer, never from `render`**: `draw_roots` builds the frame's AccessKit root *before* prepainting, and `set_window_title` marks nothing dirty — a title set during `render` updates the platform title at once while the accessible root keeps the stale name until an unrelated redraw. So `SpaceView` observes `stores.spaces` with `cx.observe_in` and writes there, plus once at construction. (Not testable at this pin: `flush_effects` draws inside the same update under test-support, and the AccessKit root label is crate-private; asserted via `window_title_for_test`.)

**Labels are spoken, not written.** A label is read aloud in full every focus, which makes these defects: (1) **raw markup** — minimap cells carry post text through `minimap::spoken_snippet`, which resolves embed markers, drops block markers, truncates on a word boundary; its inline pass (`strip_inline_markup`) is **positional, not a blanket delete** — a backslash escape yields the escaped character, a code span is spoken verbatim, and a `*`/`_` run is dropped only when it reads as a delimiter (flanking, ≥2 occurrences; an unpaired `2*3` stays literal). Residual misses are documented at the helper. (2) **Repeated context-free verbs** name their subject (`"Archive Tides and the moon"`, via `ghost_button_labeled`). (3) **Long hex** is announced character by character, so labels carry a short form (`record::spoken_hash`, `hex_summary`) and the full value rides `.aria_value(…)`. Controls whose group label is a node-less div fold it into their own name (`"Day & night: Auto"`).

**Content is in the tree — and only when it has settled (wave C).** *The rule* (the single most dangerous trap here): **an `aria_value` may only be bound to text that has stopped changing.** AT re-reads a focused control's whole value on every change, so a value wired to a streaming reply or live editor buffer re-speaks the entire text per token — annotation that makes the app less usable than silence. So:

- **A settled post is an `Article`** (`space/post/{i}`), named by `post::article_label` (the byline folded onto one line) with the whole post as its value via `minimap::spoken_text`. **A streaming reply gets no node at all** — the row becomes one when the stream finalizes. Live progress belongs in an announcement, which needs `aria_live` (upstream, below); until then streaming is honestly unannounceable.
- **The composer's value is frozen while focused** (`composer_aria_value`, snapshot `(draft id, text)`), refreshing at settled moments. **The seed lives in `activate_draft`** — every reopen path funnels through it, and seeding at retirement would miss the quote paths (which set the buffer and *then* activate); Escape clears `active_draft` before any frame renders the composer unfocused, and reopening focuses the same draft, so the render-time conditions alone could never re-seed after a type → Escape → reopen round trip. Regression: `space_composer_reopened_draft_reads_the_text_it_holds`.
- **The failure and cascade notices are `Alert`s** (`space/error`, `space/cascade`) whose **message is the value**, not the label — `node_updated` re-announces only on value changes, so that shape starts speaking the day `aria_live` lands, and is perceivable today.
- **Static values ride their own `Label` node**: `settings/account/balance`, `settings/account/pool/{i}`, `about/version`, `updates/version`, the plan rows' credits/expiry subline.
- **Deliberately excluded by the same rule:** the Local pane's model rows (a download counter ticking ~2.5 Hz needs the announcement channel, not a value). The Wallet rows are simply not yet swept.

**The regression gate, and how far it reaches.** `tests/probe.rs`'s `assert_probe`/`assert_probe_value` assert the role, label, and value at each call site. It is the whole seam: the emitted `TreeUpdate` is crate-private, so nothing can observe tree shape, parentage, reading order, focus reporting, or the aria attributes that don't pass through probes (`aria_position_in_set`, `aria_selected`, …) — those are compile-checked and eyeballed. Where such an attribute is load-bearing, expose the computation and assert *that* (`row_set_metadata_for_test`, `composer_aria_value_for_test`). Window titles are likewise unobservable (`TestWindow` has no `get_title`); asserted via `window_title_for_test`. *Removal trigger:* upstream `Window::debug_a11y_tree_json` (zed#60397) returns `None` under `TestAppContext` and always will (a11y activates via a platform callback `TestWindow` no-ops) — closing this needs upstream to expose the retained `TreeUpdate` to test windows.

**Coverage today.** Every interactive affordance across the window set carries a probe, and the content-bearing nodes carry their content (posts, composer, notices, balances, versions, the model pickers' selections, the Templates referenced rows, the full-hash values behind shortened labels).

**Still missing** (waves D and E):

- **Prose has no *text* semantics** — everything renders through `MarkdownEditor`, which carries no annotations: no caret tracking, no typed-character echo, no line-level review, no selection round-trip. That is wave D in `gpui-markdown-editor` — which must first make its constant `.id("markdown-editor")` per-instance (duplicate-node-id assert the moment it gains a role).
- **Text fields are still not Tab-reachable** (wave B's one hole; see the `Role::TextInput` note below).
- **Nothing can be announced.** gpui has no `aria_live` builder and never calls `set_live`, and the macOS adapter announces only for a node with a live setting **and a value** — every `Role::Alert` is perceivable but silent. Our half is done (the notices carry the message as the value); the ~10 lines are upstream. When it lands, `.aria_live(Live::Polite)` on those two nodes is the whole client change.

**Focus and keyboard (wave B).** The focus model lives in `src/focus.rs`; the space window's key map in `src/space_view/keyboard.rs`. Both carry full rationale — this is the contract:

- **Focusability is derived from the role**: `probe_inner` applies `.focusable()` to every `focus::is_focusable` role, `.tab_index(0)` + the `:focus-visible` ring to every `focus::is_tab_stop` role. Tab stops are the **interactive** set (Button / Link / Tab / CheckBox / Switch / ListBoxOption / MenuItem / Slider / …). `Role::Article` is focusable but not a tab stop (posts are the arrow-key surface) and draws its own ring.
- **A structural role never becomes a tab stop, however clickable an instance is** — the classification can't see the instance, and a focusable element with no click listener is a stop gpui's Enter/Space can never activate. `Role::ListItem` is structure; a row that really is a link says `Link` (`traces.rs` and `references::footnote_row` both switch role by `navigable`). Regression: `a_listing_contributes_one_tab_stop_regardless_of_row_count`.
- **`Role::TextInput` is deliberately excluded — the model's one hole.** The editors own their focus handles, and a tab stop on a wrapper would land focus on a div that cannot type. The `Input` wrappers are now bounds-only (`probe_bounds` — the labeled `Input` node is the AT surface); the one remaining role-bearing `TextInput` probe is the composer, whose `MarkdownEditor` carries no annotations until wave D. **Tab-reachability of text fields is unchanged and remains the wave E gap**: reaching a field by Tab needs *its* handle marked `tab_stop(true)` — per-site plumbing plus an upstream `Input` fix (it calls `.tab_index(…)` on the element, but gpui reads tab-stop state off the tracked handle). The composer is covered by design instead: a space opens with it focused, and any printable routes to it (task 38).
- **The ring is `:focus-visible`, and gpui owns the condition** (`Window::last_input_was_keyboard()`): shown only while focused *and* the last input was a key. gpui also suppresses hover entirely under keyboard modality — why every hover-gated affordance needs a focus reveal.
- **The ring is a box shadow, not a border** — 1.5px in `theme.ring` (0.55 alpha day / 0.70 night — night raises alpha, never thickness), inset 1px outside the element's bounds. A shadow isn't layout (nothing shifts), and gpui paints it with the element's own corner radii. Two stacked shadows: the accent ring + a paper-colored spacer punching the 1px gap. The colors are snapshotted into `focus::set_ring_colors` by `theme::apply`/`apply_fixed` (`probe_inner` has no `App` to ask).
- **A post rings its reading column, not its row** (`focus::POST_RING_OFFSET` = 6px): the row is full-bleed, so a ring on its bounds reads as two window-wide separators. No `:focus-visible` guard needed — `tree_focus` is only ever set by the keyboard model.
- **Tree focus is observed, not merely bookkept** (`keyboard::sync_tree_focus`, head of `render`): the window's focus is the truth, and Tab or a click moves it without telling `tree_focus` — a stale value painted a second apparent focus target. Each level is observed through the handle that can answer for it: the post level asks `post_focus.is_focused` (exact); the affordance level asks the **slot pool** (`affordance_slots` — one handle per verb), so a Tab within the row resyncs the level's index and a Tab out clears it. **A transient overlay borrows the keyboard rather than ending the level:** the observation parks while one is open (the same set `handle_conversation_key` yields to) and the falling edge restores focus to the level's handle — but **only to a lender who still has nothing**: `overlay_borrowed_focus` records who held the keyboard, and restores only if that handle is still focused (a menu item can hand focus somewhere on purpose — Reply focuses the new draft's editor). Regressions: `space_an_overlay_that_hands_off_focus_does_not_get_it_back`, `space_tree_focus_releases_when_the_conversation_loses_focus`, `space_tree_focus_releases_from_the_affordance_level_too`.
- **Tab order is grouped by region, not paint order.** Each landmark declares `focus::TabRegion::tab_region(index)` (`tab_index(N).tab_group().tab_stop(false)`). **The region indices are negative on purpose**: gpui sorts a shorter tab path before a longer one sharing its prefix, so an ungrouped affordance (path `[0]`) precedes every member of a group at index ≥ 0; `NAV = -20`, `MAIN = -10`, `AUX = +10` yields nav → main → ungrouped floating chrome → aux. Pinned by `the_region_order_puts_ungrouped_chrome_between_main_and_aux`.
- **A probed wrapper around a `gpui-component` widget IS the control**: role, label, handle, ring, *and* activation, with the widget taken out of the tab order (`.tab_stop(false)`). Two gpui facts force it: (1) Enter/Space runs only the focused element's **own** click listeners, so a focusable wrapper with no handler is a dead stop; (2) a focused element with no a11y node reports no focus at all (`set_focus` no-ops without a pushed node and falls back to the window root). Hoisting satisfies both; the mouse path stays single-fire because the widget no longer stops propagation and the click bubbles to the wrapper's one handler (`Button::clickable()` gates only a `stop_propagation` guard, never styling). **The hazard is `disabled`** — the widget's disabled state no longer guards the keyboard, so a wrapper around a dynamically-disabled control adds `.tab_stop(false)` while disabled. `Switch` tracks no handle at all, so the hoist is the whole fix there. **The hoisted widget also suppresses its own AccessKit node** via `.role(None)` (see the probes section — the wrapper must be the *only* node for the control). **The hoist does not extend to `Input`** — no hoist exists for typing (the field's own handle receives focus), so there the widget is the node and the wrapper goes bounds-only (the two-regime rule in the probes section). Regressions: `tab_reaches_a_control_that_enter_actually_activates`, `a_disabled_control_is_not_a_tab_stop`, `self_annotating_widgets_opt_out_of_their_own_a11y_nodes`.
- **One predicate decides both tab-stopness and activation** wherever a control disables itself (a single `.map(|d| if enabled { d.on_click(..) } else { d.tab_stop(false) })`) — `tab_stop(false)` alone removes only the Tab entry, so a wrapper already focused when its control disables keeps its `on_click` and a second Enter re-invokes the running operation. One expression makes it unrepresentable.
- **A checkbox's state is `toggled`, not `selected`**: `accesskit_macos` reads `accessibilityValue` from `toggled()` (consulting `is_selected` only for `Role::Tab`), so a CheckBox carrying only `aria_selected` reports no value. The three checkbox wrappers use `.aria_toggled(..)`. (Not assertable through the registry.)
- **A pointer click on a hoisted wrapper moves focus nowhere, by design** — verified: `Button`/`Checkbox` call `window.prevent_default()` in their own `on_mouse_down`, and gpui registers the focus-transfer listener before mouse-down listeners, so in the bubble pass the widget's `prevent_default` suppresses every ancestor's transfer. The macOS convention.
- **A faded overlay contributes no tab stops.** Minimap cells take their press handler only while the strip is up, so at rest they'd be N dead stops — tab-stopness shares the predicate that decides activation. The cells stay annotated at rest (the map stays readable to AT); VoiceOver activation is unaffected (`Action::Click` synthesizes a press). Real keyboard activation for cells is the recorded follow-up (task 12). Regression: `a_faded_minimap_contributes_no_tab_stops`.
- **Hover-gated affordances reveal on focus too**: a post's action gutter via `post_affordances_revealed`; the Library's verbs via the roving cursor. Regressions: `keyboard_focus_reveals_a_posts_hover_gated_verbs`, `keyboard_focus_reveals_a_library_rows_verbs`.
- **A virtualized list is one tab stop with a roving cursor** (Library; per-section Record). **The handle rides the element that carries the role** (`library-list-wrap`, `record-body`), never the `uniform_list` (no role → a handle there focuses a node the tree doesn't contain, and `TreeUpdate.focus` falls back to the window root). **The same rule governs the cursor pointer**: `.aria_active_descendant()` goes on the row's own role-bearing element — a role-less wrapper is invisible in the node tree and the pointer is silently dropped (and a wrapper changes the row's `GlobalElementId`, hence its node id, on cursor frames). The Record's spending group header carries `Role::Label` for exactly this. A tab stop per row cannot work — `uniform_list` materializes only the visible window, so Tab walks off the end of the slice. The list tracks the handle and owns the keys: ↑/↓/Home/End move the cursor (`scroll_to_item` materializes off-screen rows), Enter activates. The cursor's row draws the ring directly **under keyboard modality only** (focus can arrive programmatically; a pointer user shouldn't see a cursor) — but the a11y state is *not* modality-gated (AT wants focus however it arrived). The Library's cursor row is `aria_selected` and reveals its verbs — ordinary tab stops painted inside the list, so Tab reads list → Rename → Archive → out.
- **Two questions, two predicates** (`LibraryView::cursor_and_reveal`, read by both the row render and its test seam): the **cursor** (ring + focus identity) is `is_focused` — Tab moving onto the row's verb makes the verb the focused element with its own ring, and keeping the row's would show two indications for one focus; the **reveal** stays `contains_focused` — the verbs must not vanish under the Tab that just reached them. The Record takes the same `is_focused` rule. Regression: `library_cursor_yields_to_a_verb_it_tabs_into`.
- **Focus comes back from a detail** (`RecordView::close_detail`): opening one unmounts the element tracking `list_focus` while the window's focus still names it — a dead handle (roving keys reach nothing; `focus_next` restarts from the window top). Backing out hands focus to the listing. Regression: `record_closing_a_detail_returns_focus_to_the_listing`. **Any surface that unmounts a focus-bearing element owes the same handoff** — the space inspector's close does it for its title field, and only when the dying panel actually holds the keyboard (see its section). The key handler is gated on the list being focused *exactly*, not containing focus — on a verb, gpui's own activation fires on key up, and a containing-focus handler would also act on the key down of the same press.
- **The cursor is clamped on read, never chased on write** (`cursor()` returning `Option<usize>` as `min(stored, len-1)`, `None` when empty): rows come and go under it (archive, re-list, shrink), and a stored index that outlives its row points one past the end. Regressions: `library_cursor_clamps_when_its_row_disappears` and the roving tests.

**The space window's keyboard map.** Two levels over the post tree; Tab is the between-region device, the arrows the within-region one:

| Level | Key | Effect |
| --- | --- | --- |
| tree | ↑ / ↓ | previous / next row of the selected path |
| tree | ← / → | branch moves (below) |
| tree | Home / End | first / last **post** of the path (the path's real end is the trailing draft — the composer, not a place focus rests) |
| tree | Enter | enter the post → its affordance row |
| tree | Escape | release the conversation (focus the view root) |
| tree | any printable | jump to the trailing draft and start composing (task 38) |
| affordance | ← / → | cycle the post's verbs (Tab does too — each verb is a real tab stop) |
| affordance | Enter | activate |
| affordance | Escape | back to the post |

**Branch moves are deliberately dumb** (predictability over cleverness): `→` takes the next sibling in the focused post's strip (on a fork anchor, descends into the branch after the one the fork rests on); `←` the previous (at the first sibling, returns to the anchor); with no siblings both no-op — `←` never hunts for the nearest fork. **Where the selected child is synthetic the navigable path simply ends** — remapping onto the nearest persisted sibling made the next arrow move the reader's branch selection for them; navigation observes the tree, it does not steer it. A synthetic child is always a leaf, which keeps `path` and `levels` index-aligned. Regression: `space_navigating_beside_an_escaped_fork_draft_keeps_the_branch`. The pure decision is `keyboard::tree_target` (unit-tested incl. every no-op edge); `keyboard::scroll_into_view` scrolls minimally (never moves an already-visible row; aligns the top of a row taller than the viewport).

**The Escape chain** (gpui dispatches bindings before listeners and bubbles inner→outer; each rung consumes the press):

0. **any transient overlay** — `transient_overlay_open` (the two menus, the highlight picker, the inspector's router dropdown, and its participant model dropdowns — those asked through `open_inspector_participant_picker`, so one whose form has been unmounted owns nothing), the *one* definition of "an overlay owns the keyboard", read by both `handle_conversation_key` and `sync_tree_focus` (the two had drifted: the handler yielded for the menus but not the highlight picker, so keystrokes fell through behind an open picker — and a printable starts a draft. Regression: `space_an_open_picker_keeps_printables_out_of_the_conversation`);
1. an open **context menu** (the view root closes it; inner handlers yield via `context_menu_absorbs_escape`), then the **inspector's router dropdown** (the root's second rung, same shape);
2. an inline **edit session** cancels;
3. the **composer** deactivates its draft;
4. the **affordance level** steps back to the post;
5. the **post level** releases tree focus.

**Escape never closes the window.** Pinned by `space_escape_yields_to_the_context_menu_before_the_focus_levels` and `space_enter_descends_into_the_posts_affordances_and_escape_climbs_out`.

**Every press the model handles is consumed** (`cx.stop_propagation()` on the root's key listener): `gpui_macos::handle_key_event` reports handled to AppKit only when `propagate == false`; otherwise the same native event reaches `[[self inputContext] handleEvent:]` — for type-to-compose, the editor the press just focused, typing the character twice. Assertable: `space_typing_consumes_the_press_so_the_platform_cannot_retype_it`.

**Type to compose (task 38).** A printable, non-whitespace character with nothing composing **and no inspector field focused** (`inspector_field_focused` — a character typed into a setting is text, and the jump consumes the press) activates the trailing draft at the end of the current branch, places the caret after existing text, and applies the character (`MarkdownEditorState::append_at_end`). Whitespace is excluded (space is gpui's activation key on a focused affordance). **The page does not move** — the jump runs none of a click's settling, and an off-screen composer floats, so the caret reveal moves the composer's internal scroll, not the page. The accessible value is re-seeded after the append (the freeze rule means nothing else would refresh it). Regressions: `space_typing_jumps_to_the_trailing_draft_without_moving_the_page`, `space_typing_into_an_open_composer_is_not_intercepted`, `space_typing_reseeds_the_composers_accessible_value`.

**The composer's resize handle is keyboard-operable** (`Role::Slider`): ↑/↓ step `composer_fraction` by `COMPOSER_FRACTION_STEP` between the drag's bounds, switching to Exact as a drag does; reports orientation/min/max/value/step. Its listener is inner to the root's, so it takes the arrows before tree navigation. Regression: `space_composer_resize_handle_adjusts_with_the_arrows`.

**Known gap — Tab does not reveal an off-screen control in an ordinary scroll pane.** gpui never scrolls a focused element into view, so in Settings/Participants/Updates Tab can move focus below the fold. The virtualized listings are exempt (the roving cursor scrolls) and the space tree has `scroll_into_view`. A seam-level fix is blocked: the focused element's bounds are crate-private (`a11y.node_bounds`), and a probe-derived tab stop rides gpui's **implicit** focus handle our code never receives. The achievable shape today is per-section (view-owned handles + `ScrollAnchor` + `contains_focused`) — a design decision deliberately not half-built; it becomes a one-liner when gpui exposes bounds for the focused handle.

**What is still unobservable:** the emitted `TreeUpdate` — nothing asserts focus actually reaches the AccessKit tree, only that the element carries a tracked handle and a role (gpui's documented precondition). The tests assert our side: the role classification and ring composition (unit, `focus.rs`), the region order, tree-nav transitions, the Escape chain, focus-driven reveals through the probe registry, and the modality condition (`focus_visible_tracks_the_input_modality`).

**AT-initiated activation works**: `Window::handle_a11y_action` has a built-in `Action::Click` fallback synthesizing a mouse down/up at the node's centre, so VoiceOver activation of probed divs works without `on_a11y_action` (that hook is for non-click actions).

Zed ships with AccessKit force-disabled after early teething (zed #57954) — about Zed's rollout, not the gpui API; our annotated surface is smaller and fixture-tested. If instability appears, `Application::new_inaccessible()` is the kill-switch.

## gpui / gpui-component pinning

`gpui-component` and `gpui-component-assets` track **the `eidola` branch of our fork** (`eidola-ai/gpui-component`, `branch = "eidola"` in both this crate and `gpui-markdown-editor` — same spec so cargo unifies). The branch is upstream longbridge main plus a short rebased patch stack; each carried commit names its removal trigger.

**Fork-branch rewrite practice (all `eidola-ai` fork deps — gpui-component, pulldown-cmark, turso):** these branches are *rebased* onto upstream when they advance, which orphans the previously locked SHA. **Before any force-push of a tracked fork branch, tag the currently-locked rev on the fork** (`pin-<shortsha>`, e.g. `pin-cda36771`, `pin-397a8a65`) — cargo's precise-rev fetch resolves tag-reachable objects, so historical lockfiles (releases, rollbacks, bisects) stay buildable. Branch tracking over `rev` pins is deliberate (the carry-and-rebase model); the tags are what make it safe.

The carried commits:

- **`layout_selections` viewport bound** (the Record detail-body perf fix — skip lines outside the selection/content mask). *Removal trigger: upstream landing.*
- **Two `TestWindow` guards**: `HasWindowHandle::window_handle` is `unimplemented!()` (a panic, not an `Err`) on gpui's `TestWindow`, and upstream calls it unguarded from `Root::new → install_window_hit_test_forwarder` (`macos_accessibility.rs`) and from `Input::render → sync_native_content_type` (`input/native.rs`, plus the latent `native_menu/macos.rs` site) — either kills every test that opens a `Root` window / renders an `Input`. The guards wrap the call in `catch_unwind` so a test window opts out. *Removal trigger: gpui's `TestWindow::window_handle` returning `Err(HandleError::Unavailable)`.* (`native_menu/windows.rs` still has a bare site — Windows-only, deliberately left.)
- **`role(None)` presentational opt-out** — `Button` and `Checkbox` gain Input's `role` override, and all three accept `impl Into<Option<Role>>`, where `None` emits no AccessKit node (gpui builds a node only for elements with a role), so our probed wrappers stay the single accessible control instead of AT seeing two nodes per control (see Accessibility & QA probes). Submitted upstream. *Removal trigger: the upstream PR landing (the commit then drops from the fork's stack), or the un-hoist wave making the widgets the control.*
- **`Input::aria_label`** — a label builder on `Input`, applied to the widget's own node. Needed because for focus-bearing editors the widget must *be* the accessible node (its tracked handle is what reports focus), and without a label API that node was nameless (see the two-regime rule in Accessibility & QA probes). Submitted upstream. *Removal trigger: the upstream PR landing.*

`gpui-component` pulls `gpui`/`gpui_platform` from `zed-industries/zed` without a rev; we mirror that exact spec so cargo unifies on a single `gpui`. `Cargo.lock` is the canonical pin for **both** resolved revs — check the lock, not this prose. Practice when moving either: `cargo update -p gpui-component -p gpui-component-assets` follows the fork branch head but also drags the rev-less zed crates to zed main — re-pin with `cargo update -p gpui -p gpui_platform --precise <rev>` and verify the lock resolves **one** zed source line.

The zed pin is at `1a246efd` (2026-07-28) — the rev gpui-component's own lockfile builds against, so the pair is upstream-proven. This pin includes the Render/View unification (zed `74b5207744`) and gpui's AccessKit integration (zed #56065). The pin was once held back because zed #57835's action profiler panicked under parallel libtest; upstream fixed the race and made it opt-in (`gpui/profiler`, off), so the hold is obsolete — but the practice stands: **when advancing the pin, re-run the full editor behavior suite under default libtest parallelism before committing the lock.**

`pulldown-cmark` (an editor dep) likewise tracks the `eidola` branch of `eidola-ai/pulldown-cmark` — upstream main + the `ENABLE_EMPTY_NESTED_LISTS` opt-in and block display math (`$$` blocks). *Removal trigger: the upstream PRs landing.* The flag's bit position is upstream's to assign (it has moved as upstream claimed bits); our code references it by name only — keep it that way.

## Non-Rust dependencies

gpui pulls them all — no GTK/Qt/node/python. **macOS:** system frameworks (Cocoa, AppKit, CoreFoundation, CoreGraphics, CoreText, CoreVideo, Metal, Foundation, and ServiceManagement for the login item); build needs Xcode CLT. The `objc2*` crates (status item, activation policy, `SMAppService`) are macOS-target dependencies — pure Rust bindings, no extra system requirement. **Linux (Wayland-only):** fontconfig, freetype, libxkbcommon, libwayland, libGL/EGL, Vulkan loader — see below.

## Linux build/dev target

macOS is primary; Linux is a supported build/run/release target (compiles, behavior tests pass, runs on live Wayland with full chrome + keyboard idiom, has a Nix release artifact). End-user packaging *format* (AppImage/tarball/deb) is a ship-time decision.

**Linux targets Wayland only — settled; do not reintroduce X11.** The genuinely X11-stuck demographic is not the target audience; people who want confidential AI without self-hosting are on default GNOME/KDE, Wayland-by-default.

- **Cargo features.** `gpui_platform` builds with `wayland` + `font-kit` (plus `runtime_shaders` for macOS); `wayland` is cfg-gated inside gpui so enabling it universally is a no-op on macOS. Mirrored in `[dev-dependencies]`. The `x11` feature is deliberately absent. One wart: upstream `gpui_linux` hardcodes `xkbcommon = { features = ["wayland", "x11"] }`, so `libxkbcommon-x11` must be present at **link time** — but no symbol is referenced, `--as-needed` drops it, and the final binary's `DT_NEEDED` is X11-free (verified). Keep `libxkbcommon-x11-dev` installed for builds.
- **The visual tier is macOS-only** (`VisualTestAppContext` instantiates `MacPlatform`; `tests/visual.rs` compiles to a skip-stub elsewhere). Behavior tests are the cross-platform gate. A Linux headless renderer (wgpu offscreen) is the natural follow-up.
- **Non-Linux hosts:** a Linux build from macOS is a plain `cargo build` inside a Debian/Ubuntu container with the C deps (the set `nix develop .#gui` supplies) and `mold` as linker (GNU ld OOM-kills linking gpui's debug binary under Docker Desktop's default memory ceiling). Point `CARGO_TARGET_DIR` at a Linux-only path if bind-mounting.
- **Native Linux dev:** `cargo build -p eidola-gui` works once the C build deps are present (distro packages or `nix develop .#gui`; wayland/vulkan/fontconfig are dlopened at runtime).
- **Release pipeline is Nix, not StageX (settled).** `nix build .#eidola-gui-linux`: an `x86_64-unknown-linux-gnu` release build against nixpkgs libs (RUNPATH-pinned), **wrapped with bundled Mesa Vulkan drivers** (`VK_ADD_DRIVER_FILES` as an overridable default — distro ICD manifests reference drivers by bare soname a Nix binary's linker can't resolve, and dlopening host Mesa into a Nix glibc invites symbol-version mismatches; bundling makes the host surface kernel + compositor socket + `/dev/dri`). Ships `share/applications/ai.eidola.app.desktop` plus the themed icons under `share/icons/hicolor/`. Recorded as `eidola-gui-linux-amd64` in `artifact-manifest.json`; built in CI by the `linux-gui` job. StageX was ruled out for this artifact class because a desktop app must be a **glibc dynamic** binary (the Vulkan loader dlopens Mesa ICDs built against glibc; musl can't) and StageX is musl-by-design with no graphics userland. Server/cli keep StageX.
- **Validated on real hardware** (2026-07-02, Ubuntu 26.04 + GNOME Wayland, amdgpu): builds natively, behavior tests pass, runs against a live session with hardware Vulkan. One upstream bug worked around: gpui delivers appearance changes from inside its xdg-desktop-portal callback while holding the Wayland client `RefCell` mutably, so a synchronous repaint panics ("already mutably borrowed" — deterministic at startup on GNOME); `theme::observe_window_appearance` spawns the theme application onto the next executor tick (an upstream fix — dropping the borrow before window callbacks — is the real cure). Still open: release binary size/packaging.
